# gate-simple-v0：凭据网关简化——一把钥匙、两处出口、一条规矩（草案）

2026-11-23，安全审查之后（审查报告：房间“完善安全网关”的共享目录 `secret-gate-review-*.md`）。本稿取代 `docs/gate-service-v0.md`（独立服务账户），并收窄 `docs/gate-next-v0.md` 的部分内容。未做。

## 0. 目标

用户定的目标，原话：

> 模型正常工作情况下看不到明文密码，并且根据完整上下文也不可能推出来完整密码，除非它刻意去偷。

拆开是两条：

1. **看不到**：模型上下文里出现的一切（任务原文、工具结果、网页快照、截图、日志、报错）都不含明文。
2. **推不出**：把这些内容全部拼起来，也还原不出完整的值。不能靠零碎片段、换了编码的回显、长度这类信息凑出来。

**明确不防**：与用户同一账户、刻意去偷的程序（包括被网页诱导后刻意去偷的 agent）。它可以读网关的私钥，也可以冒充浏览器组件取值。这一条写明，不再假装能防。

### 为什么这样定

审查表明，现在的独立服务账户（`gate-service-v0`）占网关约 3900 行，是今天高危问题的一半来源（替身网关、安装链路、`keys.retire`）。但它挡不住刻意攻击：浏览器取值接口 `browser.resolve` 对同账户进程开放，网站密码可以直接换出明文（`gate-service-v0` §1“剩下的缺口”）。它花了最多的代码，却没有换来相应的安全。真要防住刻意攻击，得把 agent 关进操作系统沙箱，这是另一件事（§9）。

## 1. 结构

- **一把钥匙**：网关以登录用户身份运行，家目录 `~/.secret-gate`（0700），一对密钥（0600）。没有服务账户、root 安装、LaunchDaemon、`gate.sock`、旧钥匙和迁移。
- **两处出口**：明文只在这两处出现，并且只发往密文里封好的网站：
  1. **网络代理**（mitmproxy addon）：请求发出前把密文换成真值。
  2. **浏览器填写**（`secret_fill`）：网关把真值写进允许网站页面上的一个输入框。
- **一条规矩**：凡是回到模型手里的东西，都先过同一个脱敏器（§3）。脱敏不了就扣下不给，绝不原样放行。
- **模型手里只有密文**：`enc:v1:`，或任务范围内的短引用 `enc:ref:`。没有任何接口会把明文交给调用它的模型：没有 decrypt，也没有“看一下值”。
- **一个例外**：`secret_otp` 返回 6 位验证码，它 30 秒后失效，推不出种子。

## 2. 明文从哪里进来（入口）

明文在进入任何模型之前就要封成密文，封装只在用户的设备上做：

- Mac：Keys 页的“新建密文”，以及任务输入框旁的“插入密文”按钮（新增）。
- iPhone / Android：现有的本机造密文（`SecretDraft`），加上任务输入框旁同样的按钮（新增）。
- 命令行：`secret-gate enc`。

**路由器 sealer（`router-v0` §9）与目标冲突**：用户把密码直接打在任务里时，路由模型会看到明文。处理方式（待用户定，§10 Q1）：

- **建议**：云端模型不再当 sealer。daemon 在任务入库前用本地规则做一道检查，只认明确的格式，比如 `password: xxx`、`密码是 xxx`、常见 API key 的前缀。命中就拒收，并提示用户改用“插入密文”。配了本地模型时由本地前台接替 sealer（`local-model-v0`），这一条照旧。
- 本地规则只是兜底：漏掉的明文照旧进了模型。所以界面上要让“插入密文”成为最顺手的写法。

## 3. 脱敏器：一条规矩的细则

所有出口共用一个 `redact()`，作用于每一处回到模型的文本：代理的响应头和响应体、浏览器快照、`browser_find` 的结果、控制台、网络日志、工具报错、审计摘要。截图另走遮罩（§3.5）。

### 3.1 匹配什么（针对“推不出”）

对每个本次用到过的值 v：

1. **整值的各种编码**：原样、URL 编码、表单编码、HTML 转义、JSON 转义、JS 字符串转义、base64（标准与 URL 安全、有无填充、任意偏移）、十六进制（大小写）。前三类已有，base64 是今天加的，十六进制是新增。
2. **大小写不敏感**：防止回显时被转成大写或小写。
3. **片段**：v 中任意一段连续 ≥ 4 个字符的子串，出现在输出里就遮掉。这样输出里能留下的片段最长只有 3 个字符；对 ≥ 12 个字符的值，拼不出完整内容。代价是会多遮一些无害文字（比如密码含 `pass`，页面上的 `pass` 也会被遮），这种误遮可以接受。
4. **按元素遮**：浏览器里网关填过的输入框，不论现在框里是什么，一律显示 `[REDACTED:label]`（今天已做，`6a91506`）。

### 3.2 失败即扣下

- 响应体超过上限时，整体替换成“内容过大，已扣下”，不再原样放行。当前是超过 4 MiB 原样返回，这一条要改。
- WebSocket 帧、HTTP trailer、不认识的压缩格式：只要这次请求用过值，就扣下或断开，不放行。
- 脱敏器自身出错：扣下。

### 3.3 封装时的下限

- 值短于 **8** 个字符时，拒绝封装成 `http`/`fill` 用途的密文，并提示原因：太短的值脱敏不住，片段规则会误遮整页，长度本身也太容易猜。验证码种子、API key 不受影响，它们都足够长。
- 当前下限是 4（`MIN_REDACT_LENGTH`、daemon `MIN_VALUE_LENGTH`），一并改成 8。

### 3.4 长度不外泄

当前的密文长度会随明文长度变化（`crypto.py` 不做填充），模型看密文长度就能推出密码长度。改为：封装前把明文补齐到 64 字节的整数倍，解密后去掉填充。只影响新密文；用户现在没有存密文，不需要兼容旧格式。

### 3.5 截图

保留现有遮罩：填过的元素和含值的元素先盖住再截，遮不住就拒绝截图（`browser_gate` 的遮罩截图）。不变。

## 4. 浏览器出口的细则（保留今天的修复）

保留今天修好的这些：按元素遮；在填过值的网站上只放行不改内容的按键；复制快捷键按规范化后的写法拦截；选择器里禁止转义和 `[value…]`；填过值后元素只能用快照里的 ref 指定；先查后填合成一次调用。

`browser.resolve` 不再是一个 socket 接口：浏览器组件与网关在同一账户、同一个进程组里，直接调用解密函数即可。它照旧只认 `fill` 用途和允许的网站，不过只是防误用，不是边界（§0）。

## 6. 保留什么

- 密文格式 `enc:v1:`（SealedBox，封入网站与用途），加上 §3.4 的长度填充。
- 短引用 `enc:ref:` 与任务范围：用于防误用、防串值，并让上下文更短。
- 代理替换与网站核对：Host 与 CONNECT 目标一致、重定向、IDN、IP 字面量，这些照旧。
- 浏览器 gate：全部保留，加上 §3、§4。
- `secret_otp`、`secret_describe`、`secret_http`（经代理发请求，结果经脱敏器）。
- 审计日志：不写值。

## 7. 各端改动

- **secret-gate**：删 §5 所列；脱敏器按 §3 补齐（片段、十六进制、大小写、超限扣下、WebSocket）；封装加下限和填充；`BOUNDARY.md` 重写成“出口 × 输出”的表，并在开头写明 §0 的“不防”。
- **daemon**：
  - `executors/gate.ts`：去掉服务模式分支，只剩本地网关。
  - `keeper/`：去掉服务看护。
  - `secrets/`：去掉 reissue 和 seed import。
  - sealer：按 §2 改。
  - `executors/protected.ts`：保留，用来防误改，不当作边界。
  - `/gate/pubkey`：直接读 `~/.secret-gate` 的公钥。
- **Mac**：删网关服务界面；Keys 页只显示一把钥匙，带“轮换”；任务输入框加“插入密文”。
- **iPhone / Android**：任务输入框加“插入密文”；`SecretDraft` 里去掉 `totp_seed_import`。
- **Linux 节点**：本来就没有服务账户，基本不变。

## 8. 落地顺序

1. 脱敏器补齐（§3.1、§3.2）和封装下限、填充（§3.3、§3.4）。先做这一步，因为它直接对应“推不出”，与删不删服务无关。
2. 入口：做“插入密文”按钮，按 Q1 的决定处理 sealer。
3. 删服务账户（secret-gate、daemon、Mac 一起改），已安装的机器由 Mac 应用卸载一次服务（保留 `system uninstall` 一个版本）。
4. 删 exec、repair、多钥匙。
5. 重写 `BOUNDARY.md`，`gate-service-v0.md` 标为“已取代”。

每一步都有测试。重点是“推不出”的测试：用一组回显方式模拟网站（整值、截断、分段、大小写、base64、十六进制、超大响应、WebSocket），断言模型能看到的输出里拼不出原值。

## 9. 以后如果要防刻意攻击

做法是把 agent 关进 macOS 的系统沙箱（Seatbelt），让它在内核层面读不到 `~/.secret-gate`。agent 用网关只能经 daemon 转交。这是独立的一件事，不影响本稿的结构：本稿的网关在那时可以原样保留，只是多一层沙箱。
