# assistant-v0：一个可靠的入口——助理、线程视图、声音、实时活动、自修复

2026-09-24，用户已拍板（§0）。补充 `app-v0.md` §5 与 `router-v0.md`；定稿后与之不一致处以本文为准。

## 设计哲学（用户原话整理）

后端稳健、有条理；前端只有一个输入口。用户要觉得这个输入口**可靠、稳、反馈及时**：说一句话，立刻知道被收到了、交给了谁、现在到哪、需不需要自己。出了 bug，能在手机上用对话让模型把服务端修好——这是及格线。

## 0. 决定

已定（用户提出）：
- 路由器升级为**助理**，直接和用户对话；它维护前台 / 后台任务，能回答“之前那个任务怎么样了”，能定时查进度或等任务自己回报再汇报。
- 派发、执行、需要你、完成、失败都要有**声音反馈**（语音派发时尤其重要）。
- 首页要体现**线程**：多个线程各自的任务，而不是看起来一整个大任务。
- **实时活动 / 灵动岛**要设计。
- **自修复**：手机上对话让模型修服务端 bug。

拍板（2026-09-24）：
- **助理就是路由器**：不是新组件。路由器本来就是每句话的第一个接收者，给它加上对话、任务登记簿、查进度、`watch` 与主动汇报这些能力。模型不变，仍是 **deepseek-flash（DeepSeek V4.1 Flash）**，照旧在 Mac 应用的“模型”设置里可换（`/settings/models` 的 router）；sealer 本来就用路由模型，也不变。
- **自修复不是特例**：它是可靠性的及格线示例，不做专门流水线。要的是通用能力：手机任务能在 Mac 上登记过的项目目录里干活（AgentSwitch 自己的仓库也是一个项目），多步任务稳，服务起不来时 Mac 应用自动退回上一版。
- 实时活动先做**本地更新版**，推送以后再说。
- 按 §6 顺序实施。

## 1. 助理（router 升级）

**现在**：输入框一句话 = 一个任务；路由器只在任务入口分诊一次，之后不和用户说话。
**改成**：输入框的话先到助理。助理是一个常驻的对话（`assistant` 会话，保存在 daemon），每轮能做：

| 动作 | 含义 |
|---|---|
| `reply` | 直接回答（闲聊、问进度、解释） |
| `create_task` | 新建任务（仍走 sealer → 分诊 → 线程归属，现有流程不变） |
| `task_status` | 查某个任务/线程：状态、当前步骤、最近事件、摘要；用户说“x.com 那个”“刚才那个登录”时按线程标题、站点、时间去**定位** |
| `cancel` / `answer` | 取消任务；替用户把话转成对某个待答问题的回答（仍需用户确认的审批不代批） |
| `watch` | 盯一个任务：每 N 分钟看一次，或等它结束/卡住/要人时再说话；到点由 daemon 调度器触发，不靠模型记时间 |

- **任务登记簿**：助理的上下文里始终有一张表——进行中（前台 = 用户正在等的，后台 = 已交代、不必盯的）、最近结束的、每个的线程标题、执行者、当前步骤、是否在等用户。数据来自现有 store，不另存一份。
- **主动汇报**：任务结束、失败、需要你、被 `watch` 的条件满足时，助理在对话里发一条消息（带口播稿），手机收到后播提示音/朗读（§3）。没有推送时只在应用打开时实时到达，其余在下次打开时补上。
- **模型**：就是路由模型（默认 deepseek-flash，设置里可换）；分诊、澄清问题、对话、`watch` 汇报都是它。
- **可靠性要求**：助理调用失败时，输入框里的话**不丢**：退回现有路径（直接建任务）并在对话里说明；每条用户消息都有回执（已收到 → 已理解/已建任务 → …），同一条消息不重复建任务（客户端消息 id 幂等）。

### 1.1 第一版（2026-09-24）

- **接口**：`POST /assistant {text, client_id, attachments?, pin?}`（手机可用）。同一个 `client_id` 24 小时内只处理一次，重发拿到第一次的结果。顺序：**先过 sealer**（对话里从不存明文）→ 存用户消息 → 路由模型做一次助理调用 → 执行动作 → 存助理消息 → 回 `{user, assistant, task?}`。`GET /assistant?after=<seq>&limit=` 取消息。
- **助理看到的**：最近 20 条对话；任务登记簿——进行中的（≤ 10）和最近结束的（≤ 10），每条：短 id、会话标题、状态、执行者、多久前、最近一步、在等的问题；用户这条消息（已密文化）。
- **动作**（JSON）：`reply {text}`；`create_task {task?, parent_id?}`——`task` 是助理整理成能独立执行的一句（“再试一次那个登录”→ 写清是哪个），但用户消息里的每个密文必须原样在里面，否则用用户原话；`parent_id` 表示接着某个任务做（沿用它的会话和目录）；`status {task_ids, text}`——回答进度，`text` 由助理按登记簿写；`cancel {task_ids, text}`——只能取消登记簿里的任务。
- **失败退回**：助理调用失败、超时或回复不合格，按原来的方式直接用用户原话建任务，助理消息写“助理暂时没回应，已直接建成任务”。sealer 失败时和建任务一样拒绝、什么也不存。
- 建任务仍走原来的接收流程（`POST /tasks` 的后半段：父任务 / 会话 / 目录 / 附件 / 提交），分诊仍由路由器在引擎里做。
- 手机首页变成对话：你的话、助理的回复；建了任务的回复下面挂那条任务的卡片（实时状态、结果、待处理）；不是从对话建的任务照旧单独显示。

## 2. 首页：线程视图

- 首页仍然只有一个输入框；上方是**和助理的对话**。
- 对话上方一条“进行中”横条：每个有活跃任务的线程一个小卡片（标题、执行者、当前步骤、是否等你），点开进**线程页**。
- 线程页 = 这个线程的任务按时间排开（现在的日志样式），加线程标题、摘要、浏览器会话槽位（若有）、删除线程。
- 任务结束后，助理在对话里给一句结论（口播稿），点开进线程页看全文与文件。

## 3. 声音与触感

| 时刻 | 声音（系统音效 / 短音） | 触感 | 语音模式下 |
|---|---|---|---|
| 消息发出 | 轻“嗒” | 轻触 | — |
| 助理已接收、任务已建 | 上扬短音 | 成功 | 念“好的，交给 Opus 去做了” |
| 开始执行 / 换执行者 | 无（避免吵） | — | 可选：念一句 |
| 需要你（审批、提问、验证码） | 醒目提示音 | 警告 | 念出问题 |
| 完成 | 完成音 | 成功 | 念口播稿 |
| 失败 / 被拦 | 低沉短音 | 错误 | 念原因一句 |

- 设置里：声音开关、触感开关、**语音模式**（自动朗读助理回复与结果；以后接语音输入）。
- 没打开应用时要响，需要推送（§4）。

## 4. 实时活动与灵动岛

用 ActivityKit，一个**汇总型**实时活动（不是每个任务一个）：

- **灵动岛紧凑态**：左 = 状态图标（执行中 / 等你 / 完成）；右 = 进行中任务数或当前任务已用时。
- **最小态**：状态图标；有任务等你时变色。
- **展开态**：当前最要紧的一个任务（等你的优先，其次最近开始的）：线程标题、当前步骤（“第 2 步：浏览器登录 x.com”）、执行者模型、已用时；等你时显示问题一句和“去处理”按钮（打开应用到那张卡片）。
- **锁屏**：最多 3 个进行中任务，每个一行（标题、步骤、用时），等你的置顶高亮。
- 开始：有任务进入执行；结束：全部任务结束后展示最后结论 1 分钟后消失。
- **样子**（2026-09-29 重做，用户：灵动岛太丑；演示页 `docs/design/visual-v1/island.html`）：换成应用自己的视觉语言。应用标记兼作身份和状态——进行中时上线有一段青色块（静止的一帧，灵动岛不跑动画），等你时末端琥珀，结束后末端绿（done）或红（incomplete）；紧凑态左边、最小态、锁屏标题行都是它。紧凑态右边：一个任务时是它的计时（等你时琥珀），几个时是计数 `■ 1 ⠋ 2`，结束后是结果颜色的方块。展开态：摄像头左边只放标记，状态词和计时在右边；下面一律靠左——标题，`└─` 接当前一步（等你时是琥珀色的问题），点线下是模型短名（小写；终端是 agent 像素图和名字）、“+N more”和等你时的 `[ open ]`（琥珀底、键帽式下沿）。锁屏：标记、`agentswitch · <Mac 名>`、计数或状态词；点线下每行是状态方块或转圈第一帧、标题、计时，下一行 `└─` 接当前一步。标记与 agent 像素图的数据放在无依赖的 `AgentSwitchLive`（`LiveArt`），应用的 `PixelArt` 引用同一份。
  - 2026-10-01（用户：灵动岛图标太大、被圆圈裁切，和 App 图标不一致）：标记按应用图标的画法（ui-v0 §7.2.10，`make-icons.swift`）——亮车道墨色 `#E9E6DF`、其余 `#5B5955`、斜线台阶补 42% 的半亮格、右下一格的硬阴影 `#2C2A28`（不加辉光，这个尺寸下是糊的一团）；状态照旧画在上面（青块、琥珀 / 绿 / 红的末端）。紧凑态左边和最小态每格 4 个物理像素（3x 屏上 4/3 pt，连阴影 20 × 16 pt），在 37 pt 的圆里四周留出约 5 pt；展开态和锁屏仍是 2 pt 一格。
- **终端的待处理项**（terminal-v0 §1）：等你批准的终端也占一行，和等你的任务一起置顶：终端名、请求的工具与对象、agent 名、已等待时长，点开进应用里的那个终端（`agentswitch://terminal/<id>`）。只有终端在等你时也会开始；处理完、又没有进行中的任务时立即消失（没有“最后结论”）。~~只算等你的终端，在跑的终端不进实时活动。~~ **在干活的终端也算**（2026-09-30，用户：实时活动应该包括终端里的活动，不只是路由器调度的）：和进行中的任务一样占一行、计入进行中——终端名，`└─` 接它正在做的事（agent 每次用工具前报给服务的那一个，说成人话，如“运行 npm test”；没报过就是“进行中”），计时从这一轮开始干活算起，agent 像素图。空闲、已结束的终端不算；一轮结束没有“结论”（终端里就是回答本身）。
- **Mac 上**（2026-09-30，用户：macOS 上缺少一个类似实时活动的权限提示和结果展示；用户定了照 macOS 26 把 iPhone 实时活动放进菜单栏的样子，“更官方、不占地方”；演示页 `docs/design/visual-v1/mac-live.html`）：Mac 应用自己没有 ActivityKit，做成同样的两层——
  - **胶囊**：状态栏里单独一项（在 AgentSwitch 自己的菜单栏图标左边，那个图标不动），黑底胶囊里是紧凑态：应用标记（状态同上）+ 一个时的计时（等你时琥珀）/ 几个时的计数 `■ 1 ⠋ 2` / 结束后的结果方块。只在有任务在跑、有东西等你或一分钟内有任务结束时出现。胶囊不动（菜单栏不跑动画，ui-v0 §7）：标记是静止的一帧、转圈是第一帧，计时每秒更新。
  - **卡片**：点胶囊落下手机锁屏那张卡（最多三行，等你的在前，“+N more”），卡片里的转圈和标记会动。卡上能直接答：终端的权限请求和任务的批准是 `[ deny ]` `[ allow ]`，一个问题、单选、不涉密的提问是各选项按钮，其余（要打字、多选、涉密）是 `[ open ]` 去任务页答；点标题打开那个终端（终端窗口）或任务（网页控制台）。
  - **自己落下**：出现新的请求时卡片自己落下并响手机同一段“等你”提示音（通用页可关），留到请求都答完；任务刚结束时落下 4 秒显示结论（有请求在等时不盖住请求），之后胶囊保留结果颜色到一分钟。应用启动时已经在等的、已经结束的不算新（和手机相同）。点胶囊开合、双击打开卡片上第一项、点别处收起。
  - **不抢焦点**：卡片是不激活应用的浮动面板，点 allow 不会把正在打字的窗口切走；在所有桌面和全屏应用上都显示（全屏时菜单栏藏起来，卡片落在屏幕右上角）。
  - **数据**：daemon 的 `GET /live`（只在本地监听，远程白名单不含）按手机实时活动的规则给出行（标题、当前一步、模型/agent、开始时间、要答的东西）和一分钟内结束的任务；Mac 每秒问一次。手机现在仍在 Kit 里自己算，以后可以改用它。
  - **结果要提示，报错不静默消失**（2026-09-30，用户：Mac 上的实时活动如果打开了，遇到报错、任务完成之类的也要提示；不然报错静默消失都不知道）：原先任务结束只落下 4 秒、胶囊保留结果一分钟就走，人不在电脑前就错过了；终端这一轮做完或出错完全没有提示。现在——
    - 结果包括任务结束（完成 / 部分完成 / 停下 / 失败）和**终端的一轮**：agent 报这一轮结束（Claude Code 与 Codex 的 `Stop`、Codex 的 `agent-turn-complete`、pi 的 `agent_end`、OpenCode 伴随进程看到会话从忙到空闲）算完成；Claude Code 的 `StopFailure`（这一轮因为 API 出错而结束：限流、过载、认证失败等，带错误名和说明）和进程非零退出算失败。靠输出安静下来猜的“空闲”不算一轮结束（太吵）；Codex、OpenCode 没有“这一轮出错”的钩子，只认非零退出。终端结果的一句：完成时是 agent 最后一段回答的开头，没有就“这一轮已完成”；失败时是错误说明或“进程退出（代码 N）”。
    - 新结果照旧落下 4 秒（有请求在等时不盖住请求），并响手机同样的提示音：完成一段上行三音，失败一段下行两音（“提示音”开关管三种：等你、完成、失败）。
    - **失败留到你看过**：失败的结果不随一分钟的窗口消失，胶囊一直是红色结果（请求在等时先显示请求），直到你点开卡片看过、或打开了那个任务 / 终端；卡片顶上列出没看过的失败（最新的在前，最多三条 + “+N more”）。完成的结果照旧一分钟后随窗口消失。
    - 正在看的不打扰：终端窗口在前台、正显示那个终端时，它这一轮的结果不落卡片、不响、失败也不留（你已经看到了）。
    - 应用启动时已经发生的结果照旧不算新。
  - 没做：菜单栏挤的时候只剩标记（演示页有）——状态栏项被刘海挡住时系统不告诉应用，按“是否被遮住”切换会来回跳，先不做。
- **更新方式**：应用在前台时本地更新；应用在后台/没打开时要靠 **APNs 推送更新**。推送需要付费 Apple Developer Program（个人免费团队不能用推送与推送型实时活动），daemon 需要持有 APNs 密钥（交给 secret-gate 管）。不上推送时，实时活动只在应用打开或刚切到后台的一小段时间里准确。

## 5. 可靠性及格线：能在手机上对话修好服务端

用户的例子：服务端出了 bug，在手机上说一声，模型把它修好。**不做成特例**，它由通用能力组成：
- **手机任务可选项目目录**：Mac 上登记“允许手机使用的项目根目录”（app-v0 §2 留的下一步），手机新建任务时助理按对话选（AgentSwitch 自己的仓库可以是其中之一）；目录规则（禁区、真实路径）不变。
  > 2026-09-25 用户决定更进一步：Mac 的文件夹对任务开放，像 Claude Code 一样——执行器可以读写任何非禁区的目录（Claude 改目录外的文件不再审批；只读步骤里的只读命令不限目录；OpenCode 的 `external_directory` 默认放行、只拒禁区），手机或助理也可以直接指定工作目录（`cwd`，过目录规则）。登记的项目目录变成按名字的快捷方式。禁区与“删除 / git push / 付款发消息要本人批”不变；Codex 仍在它自己的沙箱里（只能写工作目录，读全盘；放开它的沙箱会连 AgentSwitch 自己的配置也能改，所以不放）。同日本机端口改为要令牌（app-v0 §6）。
  > 2026-09-25 晚用户决定删掉项目目录（Mac「设置 › 项目」、手机「项目文件夹」、`GET|PUT /projects`、任务与助理的 `project` 参数、`projects.json` 都不再用）：文件夹直接用路径，助理的输入里多了“之前任务用过的文件夹”（最近 100 个任务里非临时目录，去重后最新 8 个，各带最后用它的任务；`register.ts` 的 `recentFolders`），用户说“还是那个仓库”“修一下 AgentSwitch 的 bug”时它从这里填 `cwd`。旧的 `projects.json` 留在数据目录里，不再读。
- **多步任务稳**：规划模型用优先模型，改动前后跑测试，结果与改动摘要在线程页可看。
- **上线与退回**：执行器不能重启服务（它在服务里面跑）。Mac 应用的看门狗在服务起不来时自动退回上一版应用包（`prev-AgentSwitch.app` 的做法固化下来）；换新版由用户在 Mac 或手机上确认。
- 服务整个挂掉、手机连不上时对话无从谈起，这一层只靠 Mac 应用的看门狗与退回。

## 6. 实施顺序（建议）

1. 声音与触感、线程视图（首页进行中横条 + 线程页）——纯前端，最快让输入口“有反馈”。**2026-09-24 已做**：五种提示各一段合成短音加系统触感（`Feedback.swift`，默认跟随静音开关，“静音时也响”与语音模式例外）；何时提示由 `CueTracker` 比对前后两次看到的任务与待处理项决定（首次只立基线，取消不响，看到时已结束的不算）；语音模式念“收到，正在安排”、需要你的问题、结束后到达的口播稿。日志每条上方有会话标签（每个会话一种颜色），顶部“进行中”横条每个活跃会话一张卡片（等你时高亮），会话页显示目标、进展和全部任务，可删除整个会话。
2. 助理：对话会话、任务登记簿、`reply/create_task/task_status/cancel`；消息回执与幂等；失败退回直接建任务。**2026-09-25 已做**：Mac 侧 `src/assistant/`（`POST /assistant`，`GET /assistant?after=` 增量、`?last=N` 首次取最新 N 条）；手机首页改成对话——你的话在右、助理的回复在左，建了任务的回复下面挂那条任务的实时卡片（不再重复你的话），问进度或取消的回复下面是指向相关任务的小链接，不是从对话建的任务照旧单独显示。发送后输入框立即清空，消息以淡色气泡等回复（“助理在想…”/“正在上传附件…”）；没收到回应就留在气泡里给“重发”和“改一改”，重发用同一个 `client_id`，Mac 只处理一次；轮询时若 Mac 已存下这条（按 `client_id` 找到），气泡自动消失。一次只发一条。助理回复有提示音，语音模式念回复原文；轮询到的新回复同样提示。Mac 没有助理接口（404）时退回直接建任务。
3. `watch` 与主动汇报；语音模式。**2026-09-25 已做**（`src/assistant/reports.ts`）：汇报由任务事件和 daemon 定时器驱动，文字从任务库拼出，**不调模型**（不会因模型失败漏报，也不会编进度）。任务结束（完成 / 部分完成 / 停下 / 失败）等摘要事件带来口播稿后发一条 `notice`：“「会话标题」完成了：口播稿”，最多等 45 秒，没等到就用已有的一句话或结果开头；取消的不报。审批或提问发出 5 秒后仍待处理才报“「标题」需要你回答/批准：…”，监督者当场替你决定的不打扰。助理新动作 `watch {task_ids, every_minutes}`（1–240，默认 10，0 = 不盯了），只对进行中的任务；存在 `assistant.db` 的 `watches` 表，重启后仍在；每 30 秒检查到期的，发 `progress`：“「标题」还在进行（N 分钟），刚才说：…/在等你：…”；任务结束即撤。登记簿里显示“watched every N min”，助理能改能停。标题里的密文换成 🔒，不截出半截密文。手机：汇报气泡前有铃铛（汇报）、时钟（进展）、眼睛（设了盯）图标，下面是任务的小链接；Mac 有助理时，语音模式只念对话里的消息（回复与汇报），不再另念任务口播稿和待答问题，免得念两遍；提示音：汇报不另响（任务本身的结束/需要你提示音已响），进展轻响一声。应用没打开时收不到，下次打开时从对话里补上（推送以后再说）。实测：真路由器与摘要器下，任务建好 24 秒后助理自己发来“「运行 echo hello-report 并回报输出」完成了：命令已执行，输出 hello-report。”
4. 手机任务的项目目录白名单；Mac 应用换版确认与起不来时自动退回上一版。**2026-09-25 已做**：项目目录在 Mac 上登记（`$AGENTSWITCH_HOME/projects.json`，Mac 应用「设置 › 项目」添加文件夹；`PUT /projects` 只收本机请求，手机 `GET /projects` 只读），保存时与每次使用时都按工作目录规则重新检查（禁区、禁区的上级、主目录、不存在的都拒绝）；任务带 `project`（按名字，不分大小写）就在那个目录里跑、不是临时目录，手机也能带；助理看得到项目清单，用户点名或明显指的是某个项目时在 `create_task` 里填，其余照旧临时目录。换版见 app-v0 §4“换新版”：新构建放在 `next/`，用户在菜单栏或手机「设置 › 新版本」确认后由 App 自己换，150 秒内新版不应答就自动退回，结果由助理在对话里说；缺 macOS 权限时什么都不停、说清要去哪里允许。实测：缺“App 管理”权限时发起安装，daemon 一秒没断，15 秒后助理报“新版本没有装上……允许之后再装一次”；允许权限后的完整换版待用户在 Mac 上授权后验证。另：打包改用开发证书签名，隐私授权不再每次换版作废。
5. 实时活动：本地更新版先做；推送版在有付费账号后做（同时解决后台提示音）。**2026-09-25 本地版已做**：手机工程加了小组件扩展 `AgentSwitchWidgets`（包名 = 应用包名 + `.widgets`；`project.yml` 用 `APP_BUNDLE_ID` 派生，`install-device.sh` 只覆盖它），状态放在无依赖的 `AgentSwitchLive` 模块里（扩展只链接它），由 Kit 的 `LiveSummary` 从任务、待答问题和首页的实时事件尾巴算出：最多 3 行，等你的排最前，其余按新到旧；每行会话标题、当前步骤（等你时是问题）、模型、开始时间；进行中与等你的计数。应用在前台/刚进后台时同步（状态没变不发，串行执行），没有进行中的任务时显示最后结论 1 分钟后结束，10 分钟没更新标“可能不是最新”。计时用系统自走的计时文本，应用被挂起后照样走。灵动岛：紧凑态左边状态图标（执行中蓝、等你橙、完成绿/失败红），右边多任务显示个数、单任务显示用时；最小态只有图标；展开态标题、用时、步骤与模型，等你时有“去处理”按钮；锁屏最多三行。点开活动或“去处理”走 `agentswitch://task/<id>` 打开那条任务。设置 › 提示与朗读 里可关；iOS 设置里关掉时提示去哪开。模拟器验证：示例状态（调试版 `-liveDemo YES`）下活动成功创建，SpringBoard 挂上、扩展正常启动无报错。真机第一版用户反馈“一点也不可读”（图标孤零零在角上、步骤是灰色的内部状态名、计时被圆角裁掉），重做：视图挪进 `AgentSwitchLiveUI` 包，Mac 上 `AGENTSWITCH_RENDER_DIR=<dir> swift test --filter LiveRenderTests` 把各状态渲染成图先自查；展开态左上角状态图标 + 一个词（执行中 / 等你处理 / 完成了 / 没做成），右上角计时（固定宽度、离开圆角），中间标题，底部步骤（大白字，等你时是问题）+ 模型标签 +“另有 N 个任务”，等你时有“去处理”；步骤改成人话（“正在安排执行者”“交给 claude-opus-5-5”“在运行命令：…”“在用工具 read”），不再显示内部状态名或工具原始输入；锁屏卡片深色底白字，任何壁纸都看得清。
