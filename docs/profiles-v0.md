## 0. 要点

- **一个配置（Profile）属于一个 agent，自带三样：登录、出口、浏览器。** 出口（直连或一个代理）和浏览器（一份指纹、它自己的登录态）合起来叫这个配置的**身份**；agent 的进程和那个浏览器用同一个出口，所以“指定了代理，浏览器也跟着走”。
- **身份不共用，更不跨 agent**（已定）：没有哪个身份把几个 agent 的配置包在一起。一个配置自己的身份只属于它自己。
- **没有自己身份的配置用“这台 Mac”的**：真实的指纹、现在那一个浏览器、这台 Mac 的出口。各 agent 的 `Default` 配置起初都是这样——也就是今天的样子。它不是谁建出来的身份，就是这台机器本身（要不要连这一处也分开，见 §10 的 5）。
- **切换不改你机器上原有的那一份**（已定）。配置是另开的家目录，由 AgentSwitch 在启动 agent 时用环境变量交给它（`CLAUDE_CONFIG_DIR`、`CODEX_HOME`……）。`~/.claude`、`~/.codex` 不动，所以官方 App 和你自己在别的终端里打的 `claude`、`codex` 不受影响。这和 cc switch 相反：它是把选中的那份配置拷进 `~/.claude`、`~/.codex`，全机一起换。
- **“设备指纹”对命令行 agent 来说就是家目录里的那几个随机标识**，换一个家目录就是一套新的，不需要伪造什么（§2）。本文只做隔离，不做伪装（§9）。
- **每个 agent 各管各的配置**（同 cc switch 的分栏），都有一份 `Default`——就是这台 Mac 上原有的那一份。每个 agent 有一个“当前配置”，新开的终端用它；开着的终端不变。什么都不建的人，一切照旧。
- **安全网关只留在调度里**（已定，§8）：终端就是终端，多出来的只有配置这一样。
- **先做 Claude Code**，再做自己的身份（出口与浏览器），再做其他 agent，最后才是调度任务。

## 1. 模型

```
Claude Code                              Codex
  Default ── 这台 Mac 的身份 ──┐           Default ── 这台 Mac 的身份 ──┐
  Work ───── 自己的身份        │           Team ───── 自己的身份        │
  Relay ──── 这台 Mac 的身份 ──┤                                        │
                               └──────── 这台 Mac ──────────────────────┘
                                         （真实指纹 · 现在那个浏览器 · 这台 Mac 的出口）

配置 Profile = 登录（一个家目录：账号或供应商、设备标识）
             + 身份：这台 Mac 的，或自己的（一个出口 + 一份指纹的浏览器）

终端 = agent + 配置 ──▶ 进程的家目录、进程的出口、它的浏览器工具连到哪个浏览器
```

- **自己的身份只属于一个配置**。没有“选用别的配置的身份”这回事，所以不同 agent 的配置之间、同一个 agent 的两个配置之间，都不会共用一个自建的浏览器或出口。
- **这台 Mac 的身份**就是现在那一个（browser-v0 §7.3 的 `identity.json` 与 `browser-profiles/main-camoufox`）：指纹默认是这台机器真实的那份，出口默认直连。用它的配置之间看上去就是同一台机器，这本来就是事实。
- **默认值**：
  - 各 agent 的 `Default` 配置：这台 Mac 的。可以改成自己的——比如只有一个 ChatGPT 账号，但想让它固定走某个代理、有自己的浏览器。
  - 新建**订阅登录**的配置：自己的（一份新指纹，出口另填）。Camoufox 没装时只能先用这台 Mac 的，装了再改。
  - 新建 **API 供应商**的配置：这台 Mac 的——它按密钥认人，不在浏览器里登录；要它走别的出口时改成自己的。
- **有自己的出口，就有自己的浏览器**：给一个配置填了代理，它就是“自己的身份”。浏览器要跟着出口走，而一个浏览器只有一个出口。（这台 Mac 的出口在 `Browser` 页它自己那一组里设，对所有用它的配置生效。）
- **自己的身份要先装 Camoufox**：没装时浏览器是本机的 Chrome（后备），没有指纹与代理可设，只有这台 Mac 的那一个。**只是多几个账号、不在乎指纹和出口的人，不需要它**：配置照建，登录照旧开在你自己的浏览器里。
- **指纹一律是 macOS 的**：命令行 agent 上报的系统是这台 Mac，浏览器若自称 Windows，两头对不上。这台 Mac 的指纹是真实的那份，配置自己的是生成的另一份。
- 一个终端**启动时**定下它的配置与身份，之后不变；改一个配置的身份，只影响之后新开的终端。
- **只给一个 agent 建了配置的人**（用户：有的人只改cc不改codex怎么处理）：不用处理。没建过的 agent 只有 `Default`，照旧用这台 Mac 的；换 Claude Code 的当前配置，Codex 的账号、出口、浏览器都不动。**出口跟着账号走，不跟着“现在切到了哪个”走**，没有“全机当前身份”这回事。只有 `Default` 的 agent，界面上不出现任何配置的东西。

## 2. 一个配置里有什么

每个 agent 的“一套”（2026-10-08 从各家程序里读到的）：

| agent | 家目录怎么给 | 里面认人的东西 | 登录 |
|---|---|---|---|
| Claude Code 2.1.292 | `CLAUDE_CONFIG_DIR` | `.claude.json` 里的 `userID`、`machineID`（都是首次运行时生成的 64 位随机十六进制，不取硬件）、账户信息；登录凭据在钥匙串里**按配置目录另存一条**（服务名带目录的哈希） | TUI 里 `/login`（开浏览器），或 API 密钥 / 地址 |
| Codex 0.162 | `CODEX_HOME` | `auth.json`、`installation_id`（随机 UUID，随请求发出） | `codex login`（开浏览器），或 API 密钥；供应商在 `config.toml` |
| OpenCode 2 | `XDG_DATA_HOME`（连同 CONFIG / STATE / CACHE） | 它的库 | `opencode auth login` |
| pi | `PI_CODING_AGENT_DIR` | `auth.json`、`models.json` | 它自己的登录或密钥 |

四家都能靠环境变量换家目录，都不需要改它们的默认目录。

**家目录里的东西分三类**（以 Claude Code 为例，其余同理）：

| 类 | 是什么 | 怎么放 |
|---|---|---|
| 账号与设备的 | `.claude.json` 里认人的字段、凭据（钥匙串）、遥测状态 | 每个配置各一份 |
| 你自己的 | `CLAUDE.md`、`skills/`、`commands/`、`agents/`、`plugins/`、`keybindings.json`、`output-styles/`、`settings.json` | 与 `Default` 共用（链接过去） |
| 会话的 | `projects/`，以及跟着会话走的 `file-history/`（回退用）、`todos/`、`plans/` 等 | 与 `Default` 共用（已定） |

这里的“共用”都在**同一个 agent 的几个配置之间**，不跨 agent。

- **会话共用**（已定）：同一个 agent 的任何配置都能续接它的任何会话，官方那边也都看得到；几个账号的会话在一个目录里。
- **`settings.json` 提议共用**：权限规则、hook、状态行是你的东西，不该每个配置各调一遍。配置自己的那几项——供应商的地址、模型名、取密钥的办法、出口——由 AgentSwitch 在启动时另叠一层（它本来就给每个终端带一份 `--settings`，优先级高于你的那份）。要注意的一种情况：你的 `settings.json` 里若已经写着别家的地址或代理（cc switch 就是写在这里的），共用之后会漏进每个配置，所以启动那一层必须把这几项逐个盖掉——能不能盖干净要实测（§11）。
- **`.claude.json` 里不认人的部分**（主题、已信任的文件夹、用户级的 MCP 服务器）没法共用——它和认人的字段在同一个文件里。新建时从 `Default` 带过来一次，认人的字段留空让它自己生成；之后在某个配置里新信任的文件夹只记在那个配置里。这是这个设计里一处不整齐的地方。

**没弄清的**：Claude Code 的程序里带着一段标准的 OpenTelemetry 主机探测（读硬件 UUID 与主机名），它是否随默认的遥测发给 Anthropic，没有查实（§11）。即使会，它也不在“换家目录”能管到的范围里（§9）。

## 3. 用起来是什么样

**在哪里管**：设置窗口的 `Agents` 页（agents-v0 §8）。每个 agent 一组，现在组里是“装了哪几个版本、用哪个”；下面加一段 `Profiles`，样子相同——每行一个配置，行首的单选标记就是“当前配置”。各 agent 的这一段互不相干。

```
Claude Code
  Profiles
  ◉ Default     Max · you@…          This Mac
  ○ Work        Max · work@…         Own · http · Tokyo      ▸
  ○ Relay       api.example.com      This Mac                ▸
    New Profile…

Codex
  Profiles
  ◉ Default     Pro · you@…          This Mac
    New Profile…
```

- **新建**：名字；登录的种类（`Subscription` / `API Provider`）；身份（`This Mac` / `Own`）。选 `Own` 时两栏：出口（`Direct`，或代理的地址、用户名、密码）与指纹（生成好的一份，可 `New Fingerprint`）。API 供应商多三栏：地址、密钥、模型名。
- **登录**（订阅类）：`Sign In` 在这个配置下开一个终端跑它自己的登录（已做的是 §3.1：没登录的配置开终端就从登录开始，没有单独的 `Sign In` 按钮）。配置有自己的身份时，登录页开在**它自己的浏览器**里（§5），于是登录发生在对的指纹和出口下；用这台 Mac 的身份时，照 agent 原来的做法开在你自己的浏览器里。登录后这一行写出账号与套餐。
- **一键切换**（2026-10-09 作废，见 §3.3：配置改在新建终端、恢复对话的地方选）：点行首的单选标记，或菜单栏面板里每个 agent 一行的 `Profile ▾`。换的是这个 agent 的“当前配置”：之后**新开的**终端用它，开着的不动，别的 agent 不动。
- **新建终端**：这个 agent 有不止一个配置时，面板里多一行 `Profile`，默认是当前的，这一次可以另选。
- **终端上看得到**：这个 agent 有不止一个配置时，列表里那一行和状态栏的 `claude · Opus 5.5` 之间多写配置名（`claude · Work · Opus 5.5`，在 `Default` 上的也写）。
- **`Continue As ›`**（换个配置接着做，只在同一个 agent 的配置之间）：关掉这个 agent 进程，用另一个配置的家目录续接同一段会话——“这个额度用完，换一个接着干”。两个配置是同一家的账号时直接续；一边是订阅、一边是别家转发的供应商时，记录里带签名的思考内容对方未必认，先压缩上下文再续（§11 要实测）。
- **续接一个结束了的终端**：默认用它原来的配置，不是当前配置。
- **不做自动轮换**：不替你在额度用尽时自己换号。
- **删除**：退出登录（删掉它在钥匙串里的那一条）、删掉它的家目录和它自己的身份（连同那个浏览器里的登录态）；共用的会话记录留着。
- **手机**：看得到每个终端的配置、新建时选、切换当前配置、`Continue As`。新建配置、登录、填代理密码先只在 Mac 上（同“跳过权限只能在 Mac 上选”的做法）。（2026-10-09：配置的代理手机上也能设了，见 §4.2；新建、删除、登录、颜色仍只在 Mac。）

### 3.1 没登录的配置，开终端就从登录开始（2026-10-09）

用户切到一个新建的配置开终端，Claude Code 直接进了对话界面，标题栏写 `API Usage Billing`（用户：我切换没登陆的配置之后进入cc直接说是api usage？）。查实：那不是在按 API 计费——Claude Code 自己说这个目录“未登录，认证方式：无”，环境、设置、钥匙串里都没有 key；`API Usage Billing` 只是它没有订阅登录时标题栏的默认字样，旁边那行 `Not logged in · Run /login` 被用户自己的状态栏挤掉了。它没有带人去登录，是因为新建配置时把“已完成初次设置”带了过去（§2，免得每个配置重走一遍主题之类的引导），引导里的登录那一步也就一起跳过了。

定下的做法（用户：没登陆的配置名下开终端 自动先进入登陆流程）：

- **问 agent 自己**：在一个配置名下开终端之前，服务在这个配置的目录里跑一次 `claude auth status`（`src/terminals/signIn.ts`），它答 `loggedIn: false` 才算没登录。登录放在哪里（钥匙串里按目录分的一条）只有它自己知道，服务不去猜。实测 0.1 秒。它没答（老版本没有这个命令、超时）就当不知道，照常开。
- **没登录就从 `/login` 起步**：启动命令的最后多一个参数 `/login`——Claude Code 把它当成第一句输入，开出来就停在登录方式的选择上（真的 Claude Code 2.1.294 上看过：`Select login method: 1. Claude account with subscription…`）。之后和手敲 `/login` 一样：有自己浏览器的配置，登录页开在它的浏览器里（§5.1）。续接一段会话时也一样，不然续上了也做不了事。
- **只问该问的**：`Default`（这台 Mac 自己的，没登录时 Claude Code 自己会走它的引导）不问；用 key 的配置（`API Provider`）没有人可登录，也不问。
- **先查出口再问登录**：有代理的配置，出口不通时终端根本不开（§4.1），也就不会走到这一步。
- Agents 页那一行本来就写 `Not Signed In`，不变。

脚本 `packages/daemon/scripts/profile_signin_probe.ts` 用真的 Claude Code 在临时目录里走一遍（不输入任何东西、不登录）。

### 3.2 配置的颜色；它名下运行的终端带同色的亮点（2026-10-09）

用户：给profile加上配色，活跃的某个profile的session加上同配色的亮点。

- **每个配置一个颜色**，`Default` 没有（它是这台 Mac 自己的，不标就是它）。新建时自动给一个同一个 agent 里还没人用的；六个用完了再从头轮。可以在 Agents 页点名字前的圆点换。早先建的配置在第一次读到时补上颜色并记下。
- **六个颜色按名字存**（`violet · sand · mint · orchid · olive · slate`，`src/profiles/store.ts` 的 `PROFILE_COLORS`），长什么样由各端自己定（深 / 浅两套，Mac 的 `ProfileColor`、iPhone Kit 的 `ProfileColor`）。**都不是状态色**——不用青（busy）、琥珀（waiting）、绿（ok）、红（failed），也不用信号粉和强调蓝；见 ui-v0 §7.2.11。
- **亮点**：在一个非 `Default` 配置名下、**还在运行**的终端，带一颗这个配置颜色的小亮点——Mac 的终端列表（行尾，agent 标记的左边）、底栏（agent 标记和 `claude · Work · …` 之间），iPhone 的终端列表（同样在行尾）。结束了的终端不带：亮点说的是“现在有东西在这个配置名下跑”。经典外观是圆点，像素外观是方点，都带一圈同色的光。
- **换颜色**：`PUT /profiles/:agent/:id/color`（只在 Mac 上）；开着的终端的亮点跟着变，不用重开。
- 配置自己的浏览器在 `GET /browsers` 里也带上了颜色，Browser 页还没有用它。
- 没做：网页终端页、手机上显示配置名。

### 3.3 配置在开终端的地方选，不再有“当前配置”这个开关（2026-10-09）

原来的做法（§3 的“一键切换”）：每个 agent 一个“当前配置”，在设置里点单选切换，之后新开的终端和恢复的对话都用它。用户问清楚这套逻辑之后提出：切换profile的逻辑换一下，新建窗口、恢复对话的时候指定profile怎么样；看过下面的方案：可以，就这样办。全局开关的毛病是它是个看不见的状态——容易忘了当前是谁，恢复一段旧对话时还会悄悄换了账号。

- **新建终端**：面板里多一行 `Profile`（Mac 与 iPhone 都有），只在这个 agent 有不止一个配置时出现；默认选中**上次新建时用的那个**，所以不想选时还是一步开出来。服务记着这个“上次用的”（就是原来的 `current` 字段，含义变了）；新建请求带 `profile`，不带时用它。
- **恢复对话**：点一下仍然直接恢复，**回到这段对话上次所在的配置**。想换账号接着干，用 `Resume As`——Mac 是对话行的右键菜单里的子菜单（标着它自己的那个），iPhone 是长按菜单里的 `Resume As <名字>`。换过之后，这段对话“上次所在的配置”就是新的那个；`Resume As Default` 把它带回这台 Mac 自己的登录。分叉、文件夹没了另选一个、对话在别处开着改分叉，这几步之间选定的配置都带着。
- **服务记下每段对话在哪个配置下跑**：终端一知道自己写的是哪段对话（续接时立刻知道，新开的由 agent 的钩子报上来，在里面 `/resume` 换了一段也算），就记一笔。放在 `profiles/sessions.json`——AgentSwitch 自己的目录，**不写进 agent 的对话文件**（对话仍然和它自己的 CLI 开出来的一样）。只记不是 `Default` 的；回到 `Default` 的把那一笔删掉。每个 agent 最多留 4000 笔，旧的先丢。
- **查不到就是 `Default`**：对话是在 AgentSwitch 之外开的、从没在别的配置下跑过、或者记下的那个配置已经删了——恢复时都用这台 Mac 自己的登录，不管上次新建选的是谁。
- **更新或重启之后**再恢复的终端，同样各回各的配置（它们就是照上面的规则恢复的）。
- **设置 › Agents 里的单选去掉**：那一页只留新建、删除、代理、颜色。`POST /profiles/current` 还在（没有界面用它了）。

## 4. 出口（代理）

- 出口属于身份：配置自己的身份有自己的出口；用这台 Mac 的配置，出口就是这台 Mac 的。
- 身份有上游代理时，服务为它开一个**本机转发口**（浏览器已经在用的那个转发层，browser-v0 §7.3，一个身份一个）；用这个身份的 agent 进程拿到的是 `HTTPS_PROXY` / `HTTP_PROXY = http://127.0.0.1:<口>`，`NO_PROXY=127.0.0.1,localhost`。没有上游代理的身份什么都不设，直连。
- 这样做而不是把上游代理直接写进环境变量，有三个原因：
  - **代理的密码不进 agent 的环境**（模型能读自己的环境变量）。进程只看得到本机的口。
  - **换上游不用重开终端**，浏览器和 agent 同时换。
  - **上游可以是 SOCKS**：四家里只有 Codex 认 SOCKS 而且不完整（agents-v0 §11），转发层替它们转。你要的 HTTP 代理自然也行。
- **上游断了就是断了，不改走直连**（转发层现在对浏览器就是这样：出本机的请求一律 502）。一个本该从别处出去的账号，不会因为代理掉线而用真实地址连出去。
- **改出口立即生效**，对这个身份的浏览器和所有开着的终端都是。所以改之前界面要写明：现在有几个终端在用它。
- **管得到的范围**：agent 自己的流量四家都认（agents-v0 §11）。它跑的命令（`git`、`curl`、`npm`）和它起的 MCP 服务器继承同一组变量，认环境变量的就走出口，**不认的会直连**——环境变量是约定，不是强制。要强制得按进程拦网络，macOS 上只能套一层沙箱，而那会和 Codex、Claude Code 自己的沙箱打架，不做。
- 出口除了进程的环境，还要写进启动时叠的那层设置（§2）：你的 `settings.json` 里若有 `HTTPS_PROXY`，会把环境里的盖掉。
- Codex 的进程本身现在不带代理变量（只给它跑的命令），有出口时要给它自己也设上。
- 转发层不拆 HTTPS（只转隧道），终端里不需要装任何证书。
- `Check Exit`：经这个出口查一次对外的地址与地点（浏览器的身份已经有这一项），配置那一行和浏览器那一组都显示。
- **一处行为会变**：这台 Mac 的身份现在可以设代理，但只管浏览器；按上面的规则，之后用这台 Mac 身份的终端也会走它（§10 的 6）。

## 5. 浏览器

**哪个终端用哪个浏览器**：只看它的配置。配置有自己的身份，就是它自己的那个浏览器；没有，就是这台 Mac 的那个。四个 agent 一样（pi 没有浏览器工具，它只跟出口）。

**三个维度**（用户：浏览器怎么管理呢 三个维度 不同agnet、不同账号、不同项目文件夹）：

| 维度 | 决定什么 |
|---|---|
| 账号（配置） | 哪个浏览器。有自己身份的配置各一个，互相隔离：各是一个进程、一份数据、一份指纹、一个出口 |
| agent | 配置是按 agent 分的，所以**自己的浏览器从不跨 agent**。只有这台 Mac 的那个浏览器里会同时有几个 agent 的标签（今天就是这样），每个终端的 agent 只看得到、只动得了自己开的 |
| 项目文件夹 | 不决定浏览器，只是标签的名字和排序（`claude · AgentSwitch`） |

- **浏览器的个数 = 这台 Mac 的一个 + 有自己身份且在用的配置数**，和开了几个终端、几个项目无关。
- **为什么不按文件夹分**：每个项目都要把你的网站重新登一遍，而这正是共用一个浏览器要省掉的事。不分的代价只有一处：两个项目的开发服务都起在 `localhost:3000` 时，在同一个浏览器里它们是同一个站点（Cookie、本地存储、Service Worker 共用），前一个项目留下的东西会影响后一个。提议用小办法对付：标签的操作里加一个 `Clear Site Data`（清掉这个标签所在站点的数据）。
- **文件夹决定用哪个账号**（“这个仓库永远用 `Work`”）是另一回事，那是文件夹选配置，浏览器只是跟着配置走。提议以后可以给文件夹钉一个配置（没钉的跟当前配置），先不做（§10 的 12）。

**什么时候开、什么时候关**：

- 一个身份一个 Camoufox 进程（指纹是启动时给的，一个进程只能有一份）。
- **启动**：这个身份第一次被用到——agent 第一次调浏览器工具、你点右下角的图标或在 `Browser` 页它那一组里开标签、这个配置要登录。约 8 秒。
- **停止**：没有标签且闲置一阵；或你点 `Stop`。同时运行的上限先定 3 个（每个占多少内存要实测，§11）：到了上限又要开新的，就停掉最久没用且没有标签的那个；都有标签时不停任何一个，新的不启动并说明原因。
- **标签跟着谁走**：agent 的标签属于它的终端——终端删除时关掉；`Continue As` 换到另一个配置时，这个终端在旧浏览器里的标签也关掉（那边的登录态不是新账号的）。你自己的标签属于那个浏览器，不属于哪个终端或文件夹。

**标签页按 Codex 客户端的办法管**（2026-10-08 用户：不指定指纹/代理的agent默认使用 默认指纹和无代理 浏览器，指定了指纹和代理的agent使用指定指纹和代理的浏览器；不同session（包括不同agent）的浏览器标签页管理按照codex的来。上面“哪个终端用哪个浏览器”即前半句，已定；这一段是后半句，细处是提议）：

  - **一轮结束就清**：agent 开的标签在它这一轮结束时关掉（Claude Code、Codex 的 hook 说得出一轮结束；OpenCode、pi 要看各自有没有这个信号），而不是像现在这样活到终端删除。

**做法**

- 它和共用的是同一种东西——自己的目录（`browser-profiles/<agent>.<id>`，cookie 与网站登录都在里面，与 `main` 无关）、自己的标签、自己的 agent 会话、自己的审计（`browser/of/<agent>.<id>/`）——只是**它发出去的一切都经这个配置的转发口**，也就是经这个配置的代理。agent 进程和它的浏览器从同一个地方出去。

- **它是哪种浏览器，和共用的那个是同一个选法**：引擎里装着 Camoufox 就是 Camoufox，没有才是 Chrome。这台 Mac 上装着（156.0.1-beta.36），所以这里是 Camoufox。用 Camoufox 时每个配置的浏览器有**自己的指纹**（存在它自己的状态目录里，与共用浏览器的、与别的配置的都不同），并且**按这个配置出口所在的时区启动**（共用浏览器对它自己的代理也是这样）。
- 在 Mac 上它**有窗口**：登录要人亲手做，而 Browser 页现在只会列共用的那一个浏览器。
- **这个配置名下的 agent，浏览器工具连的是它**：agent 桥的地址后面多一段 `/profile-browser/<agent>.<id>`，服务把这一段下面的全部浏览器路由都指到这个浏览器上（共用浏览器的路由一个没动）。
- **agent 要“用系统浏览器打开”的网址——Claude Code 的 `/login` 就是这样——在它里面打开**，不落到用户自己的浏览器里（那是另一个出口）。做法：这种终端的 `PATH` 最前面放一个叫 `open` 的小程序、`BROWSER` 也指向它；它拿到一个网址就交给服务（`POST /terminals/open`，凭这个终端自己的 hook 口令），别的照旧交给系统的 `open`。服务没接（这个浏览器在这台机器上没有窗口）就报错退出，**不退回用户的浏览器**；Claude Code 这时自己会把链接写在屏幕上。
- 登录回调是 `http://localhost:<端口>/callback`：浏览器把本机地址也交给转发口，转发口对本机地址一律直连，所以回得到 Claude Code。

**出口查询不再因为查询服务拒答而算成代理不通**（真跑时撞到的：`ipinfo.io` 对很多人共用的出口回 429）。现在依次问四处（原来那一处；`ipwho.is`，也给地点和时区；Cloudflare 的 trace，给地址和国家；ipify，只给地址）；对方自己拒答（4xx）或答非所问算“代理是通的”，换下一处问；四处都这样就是“通，但不知道从哪里出去”，终端照开、底栏只写配置名。转发口或代理说不行、连不上，才算不通。

**查实的（2026-10-09）**

- Claude Code 2.1.294 在一个空的配置目录下 `claude auth login`，`PATH` 前面放一个只记账的 `open`：它被叫到了，拿到的是 `https://claude.com/cai/oauth/authorize?...&redirect_uri=http://localhost:<端口>/callback…`。登录没有做完。
- `scripts/profile_browser_probe.ts`：临时目录、代理用正在运行的 Clash 的端口。出口查询先撞 429、改问下一处得到出口。**用这台 Mac 上装的 Camoufox**（服务会选的那个；只用它的程序，不写它的目录）：页面看到的地址**和出口是同一个**；页面被告知的时区是出口的时区（查到香港时是 `Asia/Hong_Kong`；另用一个编的时区试过，也照用），浏览器自报 `Firefox/156.0`；本机的一个页面照样打得开。无窗口和有窗口各跑了一遍，结果一样。先前还用 Chrome 跑过（`PROBE_ENGINE=chrome`，没装 Camoufox 时的那条路），同样成立。
- 一处说错过：第一次实测脚本没有带上引擎，跑的是 Chrome，当时就把这台 Mac 上的浏览器说成了 Chrome。用户：不是默认都让你用camoufox吗。。——是，这台 Mac 上一直会是 Camoufox。

**没做、没验证的**

- 当时 Mac 与 iPhone 的 Browser 页都看不到配置自己的浏览器；Mac 的随后做了（§5.2）。
- 整条链在装好的应用里没有走过：在带代理的配置名下开终端、`/login`、窗口弹出来、登录完回到终端。
- 登录页认不认这个浏览器没有试过（没有真的登录）。Camoufox 是为这个准备的，但 Google 账号登录、Cloudflare 的人机验证会不会拦，要真走一遍才知道。
- Codex、OpenCode 的终端在这样的配置下怎样打开网页没有看（现在只有 Claude Code 有配置）。

**窗口其实没到前面：一处修正（2026-10-09，同日）。** 登录页终于开进了配置的 Camoufox 之后，用户：登陆的时候应该让浏览器蹦到前台来，在浏览器页面点击show Windows的时候也应该让对应的窗口蹦到前台来。两处都没动。查实是上面“按目录认是哪个 Camoufox”引进的错：macOS 把 Camoufox 启动的辅助程序（内容、图形、网络等进程，这台 Mac 上一个浏览器带六个）也列为“运行中的应用”，它们的程序在 Camoufox.app 里面的小应用里，启动参数里带着和浏览器同一个目录；原来的写法把它们都当成浏览器，再按目录从七个里任取一个，多半取到辅助程序，而辅助程序不能被带到前面。共用浏览器的 `Show Window` 也因此一起坏了（改之前是“取第一个”，碰巧是浏览器本身）。

### 5.5 每个配置都有自己的浏览器，有没有代理都一样（2026-10-09）

用户在一个没设代理的配置下登录，登录页开在了系统默认浏览器里（用户：怎么登陆打开的不是配套的camoufox？）。查实：那个配置没有代理，而 §5.1 的第一版只给“有代理的配置”配了浏览器；那次开的终端没有拿到打开网页的小程序，配置的浏览器目录也从未建过。这条规则对多账号是错的：默认浏览器里登着哪个账号，授权页就把哪个账号给了这个配置。用户随后明确：**每个profile对应的指纹和session啥的都要隔离**。

改成：

- **`Default` 以外的每个配置都有自己的浏览器**——自己的目录（登录态、cookie、站点存储）、自己的指纹、自己的标签。有代理时经代理出去（§5.1 不变），没代理时和这台 Mac 一样直接出去。§5 开头“没指定指纹和代理的配置用 `This Mac` 的浏览器”那一条以此为准作废。
- **没代理的也走转发口**：同一个转发层，后面不接代理（`ExitPool.address(key, null)`）。这样它守的规矩和别的浏览器一样——AgentSwitch 自己的端口照样拒绝。agent 进程本身不变：没代理的配置，进程不带代理变量，照这台 Mac 的方式出去。
- **登录页开在它里面**：这个配置名下的终端拿到同一个打开网页的小程序（§5.1），`/login` 的页面开在这个配置的 Camoufox 里，窗口到前面（§5.3）。agent 的浏览器工具也用这个浏览器（一个配置一个浏览器，不分情况）。
- **只在浏览器有窗口时这样做**：没人看得见的浏览器里登不了录。服务以无窗口方式跑浏览器时（非 Mac，或关了窗口），没代理的配置不给这个小程序，照旧用系统浏览器；有代理的配置不变（宁可不开，也不从别的出口走）。
- **代理加上、换掉、拿掉**时，这个浏览器关掉重建（流量不能还走旧的路）；目录是同一个，登录态留着。
- **Browser 页**：`GET /browsers` 列出每个非 `Default` 的配置，不再只列有代理的。

**隔离到什么程度（在这台 Mac 上用真的 Camoufox 156.0.1-beta.36 量过，`packages/daemon/scripts/profile_isolation_probe.ts`，两个配置的浏览器、无窗口、临时目录）：**

- **登录态**：在 A 里登录一个站点（cookie 加站点存储），B 里同一个站点什么都没有；B 再登另一个账号，A 的还是自己的；A 关掉重开，登录还在。各在各的目录 `browser-profiles/<agent>.<id>-camoufox`，共用浏览器在 `main-camoufox`。
- **指纹**：每个配置一份，第一次用时生成、存在 `browser/of/<agent>.<id>/identity.json`、以后不变。生成的那几项里各不相同的是音频种子（每份必不同）和核心数、采样率、扬声器数（从几个值里随机取，可能碰巧一样）。
- **画面指纹（canvas）**：两个配置量出来不同——是这个版本的 Camoufox 自己加的扰动，而且同一个配置每次启动也不同（它不再接受固定的 `canvas:seed`，这个设置和 `fonts:spacing_seed` 在 beta.32 被拿掉了）。
- **没有分开的**：显卡名（`Apple M1, or similar`）、屏幕尺寸、字体与文字宽度——都是这台 Mac 真实的，每个配置一样。要让它们不同就得编造硬件，那是 §9 说的“不做”。没设代理的配置出口地址也都是这台 Mac 的。所以浏览器之间**互不相通**是做到的，**看起来像不同的机器**没有做到，也不打算做。

**登录页其实一直没被打开过：一处修正（2026-10-09，同日）。** 上面改完装上后，用户再试：登陆没成功打开camoufox。查实：终端拿到了打开网页的小程序，配置的浏览器也建了状态目录，但浏览器没启动。原因在更早的 §5.1——小程序用表单格式（`--data-urlencode`）把网址发给服务，而服务的本机监听只收 JSON 正文（`api/localGuard.ts`，防网页跨站提交表单），一律答 415；小程序于是报错退出，Claude Code 只显示“Browser didn't open?”。也就是说从 §5.1 起，`/login` 的页面在装好的服务里**从未**被打开过，有代理的配置也一样。之前没发现，是因为每一段都是对着替身验证的：单元测试把路由直接挂在没有防护的应用上，真 Claude Code 的探针对着一个什么都收的替身服务。

- 改法：小程序改发 JSON（网址里的引号、反斜杠先转义），加 `--noproxy '*'`（服务就在本机，不管终端带什么代理）；路由只读 JSON。没有去放宽监听的防护。
- 路由拒绝时在服务日志里写一行原因（不写网址）——小程序自己的报错进了 agent 的 stderr，谁也看不到，这次就是因此查了很久。
- 补了一条端到端测试：真的小程序脚本 → 和服务一样的本机监听（防护加本机口令）→ 路由 → 配置的浏览器；把小程序改回表单格式，这条测试会失败。
- **整条链用真的东西走通了**（`packages/daemon/scripts/profile_login_flow_probe.ts`，临时目录）：服务自己的开终端路由在没代理的新配置下启动真的 Claude Code → 停在登录方式选择 → 回车选第一项 → 约 2 秒后授权页开在这个配置自己的 Camoufox 里（有窗口），并记下“请把这个窗口带到前面” → 页面最后是 `claude.ai/login`，标题 `Sign in - Claude`，正常显示出邮箱、Google、Apple 几种登录方式。没有登录任何账号；Mac 应用把窗口带到前面这一步不在这个探针里。
- 探针里还看到一点：新配置的终端是带着“可以切到跳过权限”启动的，Claude Code 对没答过那条警告的目录会先停在警告上；配置的设置是链接到这台 Mac 自己那份的，所以这台 Mac 答过（`skipDangerousModePermissionPrompt`）就不会出现。

## 6. 四个 agent 各自怎么落

形状相同，各管各的，不同的只有下面这张表：

| agent | 订阅登录 | API 供应商 | 同一个 agent 的配置之间会话能共用吗 | 浏览器工具 |
|---|---|---|---|---|
| Claude Code | 另一个家目录，`/login` | 另一个家目录；地址与模型名在启动那层设置里，密钥经它自己的 `apiKeyHelper` 取 | 能（链接） | 有 |
| Codex | 另一个 `CODEX_HOME`，`codex login` | 另一个 `CODEX_HOME`；供应商用启动时的 `-c` 给 | 要实测（它除了文件还有自己的库） | 有 |

## 7. 官方 App 与调度

- **官方 App 不受影响**（已定）：它们用的就是 `Default` 的那一份。代价是反过来的：在别的配置下开的 Codex 会话，ChatGPT App 的会话列表里未必看得到（取决于 §6 那一项实测）；Claude Code 的会话是共用的，官方那边看得到，在那边续接用的是 `Default` 的账号。
- 给 `Default` 配置开了自己的身份（§1）之后要知道：官方 App 用同一个账号仍从这台 Mac 原来的地址出去，那个账号会从两个地址出现。
- 要让官方 App 跟着换，只能像 cc switch 那样改写默认目录——订阅登录的还要换钥匙串里的条目，App 开着时两边都会坏。不做；以后若做，只对 API 供应商类的配置提供一个明确的 `Apply to This Mac`。
- **调度任务**：先不变，仍用各 agent 的 `Default` 配置与这台 Mac 的身份，全程在网关后面（§8）。之后每个 agent 的任务用它的当前配置；那时凭据网关要接在身份的出口前面（任务 → 网关 → 身份的转发口 → 上游），待设计。

用户：安全网关功能可以只留在dispatch里，感觉正常session里用不到；dispatch里留着全套网关能力。

**终端里拿掉的**：

- 进程的网关环境（代理指向网关、网关的证书、`SECRET_GATE_HOME`）；Codex 给它跑的命令的那一份同样拿掉。空出来的代理位置就是 §4 的出口。
- Claude Code 终端里的网关工具（`secret_*`）。之后密文贴进终端里没有用处（没有东西替它解开）。
- 回复的加密：接口的 `seal`、Mac 的 `Encrypt & Send…`（`⌘⇧V`）与状态栏上的锁、手机回复框旁的锁与“像密码时先问”、网页控制台终端页的那一条。
- **浏览器工具前面的那一层**（已定：要浏览器工具，但不经网关）。终端里 agent 的浏览器工具直接连服务的 agent 桥：
  - 它看到的页面是原样的：快照不遮盖、截图不打码，没有 `secret_fill`。
  - 所以**登录由你来**：在那个浏览器里先登录好（登录态留在那个浏览器里），或在它的标签上接手、手打。
  - 服务自己的那几条照旧，谁来调都一样：只看得到自己的标签；只开 http(s)，AgentSwitch 自己的端口不给开；你接手时它的调用排队，接手期间的网络与控制台记录不给它；不在服务进程里执行代码。
  - 现在桥还拒绝三样：读写文件（上传、把截图存成文件）、页面脚本（`browser_evaluate`）、改窗口尺寸。前两样在没有网关之后留不留，见 §10 的 9。
  - 没有网关替模型整理工具表之后，桥要自己把它一律会拒绝的工具和参数从表里拿掉，免得模型白试。

**留着的**：

- **调度里是全套**：任务的环境、网关工具、密文替换、输入的加密、经网关的浏览器，一样不动。
- 你自己用的 `Fill Ciphertext`（`Browser` 页，往自己的标签里填密文）照旧，它不是 agent 的工具。
- 网关仍是 AgentSwitch 自己存密码的地方：代理的密码、API 供应商的密钥存成密文，明文只在服务的内存里。
- 禁区（凭据文件不给终端里的 agent 读）照旧，并且加上：一个终端读不到**别的配置**的家目录。它同终端里的其他禁区一样只挡随手的读取，不是边界（terminal-v0 §3）。
- 配置的家目录里，各家 agent 自己的凭据按它自己的方式存放（同现在的 `~/.codex/auth.json`）；AgentSwitch 自己的库与日志里只有密文或引用。

## 9. 边界：这是隔离，不是伪装

- **做的**：每个配置一套干净、自己生成的状态（标识、登录、浏览器），一个固定的出口。
- **不做**：改写 agent 上报的系统信息、冒充别的客户端或别的硬件；也不改进程的时区、主机名（那会连你自己的 `git` 提交时间一起改）。那已经不是隔离，而是对服务商造假，而且每次升级都会坏。
- **管不到的**：付款方式、邮箱与手机号、使用习惯（同样的仓库、同样的时间、提交记录里同一个名字）、同一份客户端程序的网络特征、不认环境变量的程序的直连（§4）、上面说的硬件探测若真的发出去。所以它**不保证几个账号不被关联**。
- 同时用几个账号、从别的地区使用，各家条款各有规定，由使用者自己判断。

## 10. 已定与待定

已定（2026-10-08，用户）：

1. 同一个 agent 的几个配置**共用会话记录**。
2. **身份不共用，各 agent 的配置分开**：这几个agent的profile需要分开，不能一个身份把他们全包起来。（先前选的是“可以共用，默认一对一”，讨论到“同一个人的 Claude 账号和 ChatGPT 账号共用一个身份”时改了。）
3. 官方 App **不跟着换**，不动 `~/.claude`、`~/.codex`。
4. 终端里的 agent **要浏览器工具，但不经网关**。
- 另：安全网关只留在调度里，调度里留全套。

待定（都带着提议）：

5. **各 agent 的 `Default` 起初共用这台 Mac 的那一个浏览器**（今天就是这样），提议保留：不建配置的人什么都不变，你常用的网站只登一次，不必一上来就是三四个浏览器；谁要分开，把那个 `Default` 改成自己的身份就行。另一种是连这一处也分开——每个 agent 的 `Default` 各一个浏览器。
6. 这台 Mac 的身份设了代理之后，用它的终端也跟着走（§4，提议走；现在只有浏览器走）。
7. 同时运行的浏览器上限（先 3 个，身份不共用之后更容易碰到）；几个 Camoufox 窗口怎么认（工具栏写名字，要实测）。
8. `settings.json` 在同一个 agent 的配置之间共用（提议，§2），还是拷一份各管各的。
9. 没有网关之后，终端里的浏览器工具放不放开**上传文件**和**页面脚本**。提议都先不放开，真用到再说：上传是服务替 agent 读文件，放开的话只给它自己本来读得到的（禁区之外）；页面脚本能读到你接手时手打的东西。
10. 右下角的图标放在哪：提议状态栏最右端、原来锁的位置（§5）；另一种是每个终端回复框自己的角上。
11. **你主要切的是哪一种**：几个订阅账号，还是几家 API 供应商（中转）。决定先做哪一种，以及要不要一个“从 cc switch 导入”。
12. 文件夹这一维（§5）：提议只用来整理标签；“文件夹钉一个配置”以后再加；按文件夹隔离浏览器数据不做。
15. 每个终端一张允许访问的网站名单（Codex 客户端每条会话有一张）：提议先不做，标签的清理先落地。
13. 手机上做到哪一步：提议看、选、切、`Continue As`；新建与登录先只在 Mac（§3）。
14. 一个终端里跑的命令也走出口：只能如此——子进程继承环境，除了 Codex 谁也没法单给 agent 自己设；要说清的是它不是强制的（§4）。

## 11. 动手前要查实的

都是“事实是什么”，查完才能把上面的提议变成定下来的：

1. Claude Code 在一个全新的家目录下向外发了哪些认设备的东西（尤其是硬件 UUID 有没有随默认遥测发出去）。
2. Claude Code：家目录里链接过去的目录和文件（`projects/`、`skills/`、`settings.json`）它是顺着链接写，还是把链接换成普通文件；启动那层设置能不能把你 `settings.json` 里的地址与代理盖干净。
3. Claude Code：换一个账号、换一家供应商续接同一段会话，带签名的思考内容认不认；`file-history/` 跟不跟得上。
4. Claude Code、Codex：登录页认不认 `BROWSER`；有没有不开浏览器的登录办法。
5. Codex：另一个 `CODEX_HOME` 下能不能续接别处的会话；凭据存在文件还是钥匙串、按什么区分。
6. OpenCode：登录文件能不能单独指到别处（能的话订阅类也能共用会话）；pi 的会话目录。
7. Camoufox：同一份引擎同时跑几个配置目录；每个占多少内存；工具栏上写名字的办法。
8. 各家 agent 有没有不认环境变量代理的连接（更新检查、远程 MCP、WebSocket）。

**已查实（2026-10-08，Claude Code 2.1.293，没有用到任何账号）**：`CLAUDE_CONFIG_DIR` 指到一个空目录时它说 `Not logged in · Please run /login`——不会沿用这台 Mac 的登录；它在那个目录里自己生成 `.claude.json`（新的 `userID`、`machineID`）、`projects/`、`sessions/`、`backups/`。
