## 0. 要点

- **两样东西，不是一样**。一个 **配置（Profile）** 是某个 agent 的一套登录与它自己的家目录；一个 **身份（Identity）** 是一个出口（代理）加一个浏览器（Camoufox 的指纹与它的登录态）。配置**指向**一个身份。这样“配置绑浏览器指纹、指定了代理浏览器也跟着走”是同一件事：出口和指纹都在身份里，agent 的进程和那个浏览器用的是同一个身份。
- **切换不改你机器上原有的那一份**。配置是另开的家目录，由 AgentSwitch 在启动 agent 时用环境变量交给它（`CLAUDE_CONFIG_DIR`、`CODEX_HOME`……）。`~/.claude`、`~/.codex` 不动，所以官方 App 和你自己在别的终端里打的 `claude`、`codex` 不受影响。这和 cc switch 相反：它是把选中的那份配置拷进 `~/.claude`、`~/.codex`，全机一起换。
- **“设备指纹”对命令行 agent 来说就是家目录里的那几个随机标识**，换一个家目录就是一套新的，不需要伪造什么（§2）。本文只做隔离，不做伪装（§7）。
- **每个 agent 各管各的配置**（同 cc switch 的分栏），都有一份 `Default`——就是这台 Mac 上原有的那一份。每个 agent 有一个“当前配置”，新开的终端用它；开着的终端不变。
- **先做 Claude Code**，再做出口与浏览器绑定，再做其他 agent，最后才是调度任务。

## 1. 模型

```
身份 Identity ──┬── 出口：直连，或一个上游代理（http / https / socks）
                └── 浏览器：一个 Camoufox（指纹、它自己的登录态、时区随出口）

配置 Profile（属于一个 agent）
   ├── 家目录：它的登录、它的设备标识、它的设置
   ├── 种类：订阅登录（浏览器里登录） | API 供应商（地址 + 密钥 + 模型名）
   └── 用哪个身份  ──▶  Identity

终端 / 任务 = agent + 配置  ──▶  进程的家目录、进程的代理、它的浏览器工具连到哪个浏览器
```

- 身份可以被几个配置共用：同一个人的 Claude 账号和 ChatGPT 账号，本来就该从同一个出口、在同一个浏览器里登录。也可以一个配置一个身份，完全分开。**新建配置时默认新建一个同名的身份**（一对一，最好懂）；要共用时在配置里改选已有的身份。
- `Default` 身份就是现在那一个（browser-v0 §7.3 的 `identity.json` 与 `browser-profiles/main-camoufox`），`Default` 配置默认指向它。什么都不建的人，一切照旧。

## 2. 每个 agent 的“一套”是什么（2026-10-08 从各家程序里读到的）

| agent | 家目录怎么给 | 里面认人的东西 | 登录 |
|---|---|---|---|
| Claude Code 2.1.292 | `CLAUDE_CONFIG_DIR` | `.claude.json` 里的 `userID`、`machineID`（都是首次运行时生成的 64 位随机十六进制，不取硬件）、账户信息；登录凭据在钥匙串里**按配置目录另存一条**（服务名带目录的哈希） | TUI 里 `/login`（开浏览器），或 API 密钥 / 地址 |
| Codex 0.162 | `CODEX_HOME` | `auth.json`、`installation_id`（随机 UUID，随请求发出） | `codex login`（开浏览器），或 API 密钥；供应商在 `config.toml` |
| OpenCode 2 | `XDG_DATA_HOME`（连同 CONFIG / STATE / CACHE） | 它的库 | `opencode auth login` |
| pi | `PI_CODING_AGENT_DIR` | `auth.json`、`models.json` | 它自己的登录或密钥 |

- 四家都能靠环境变量换家目录，都不需要改它们的默认目录。
- **没弄清的**：Claude Code 的程序里带着一段标准的 OpenTelemetry 主机探测（读硬件 UUID 与主机名），它是否随默认的遥测发给 Anthropic，没有查实。即使会，它也不在“换家目录”能管到的范围里（§7）。

**一个配置的家目录里放什么**（以 Claude Code 为例，其余同理）：

- **各自一份**：`.claude.json`（标识与账户）、凭据、遥测状态、输入历史。
- **与 Default 共用**（链接过去）：`CLAUDE.md`、`skills/`、`commands/`、`agents/`、`plugins/`、`keybindings.json`、`output-styles/`——这些是你的东西，不是账号的东西。
- **`settings.json`**：新建时从 Default 拷一份，之后各改各的（API 供应商的地址与模型名就写在这里，不能共用）。
- **`.claude.json` 里不认人的部分**（主题、已信任的文件夹、MCP 服务器）：新建时从 Default 带过来，认人的字段留空让它自己生成。否则新配置第一次打开要重新走一遍引导、重新信任每个文件夹。
- **会话记录 `projects/`**：待定 1。

## 3. 切换

- **当前配置**：每个 agent 一个。新建终端的面板里多一行 `Profile`，默认是当前的；状态栏 / 设置 › Agents / 菜单栏里点一下换当前配置（“一键切换”）。换了之后**新开的**终端用新的；开着的不动，各自标着自己的配置名。
- **`Continue As ›`**（换个配置接着做）：一个终端的会话在另一个配置下续接——关掉这个 agent 进程，用另一个配置的家目录 `--resume` 同一段会话。这是“额度用完换一个接着干”的做法，依赖待定 1。
- **不做自动轮换**：不替你在额度用尽时自己换号。

## 4. 出口（代理）

- 出口属于身份。身份有上游代理时，服务为它开一个**本机转发口**（浏览器已经在用的那个转发层，browser-v0 §7.3，一个身份一个）；用这个身份的 agent 进程拿到的是 `HTTPS_PROXY` / `HTTP_PROXY = http://127.0.0.1:<口>`，`NO_PROXY=127.0.0.1,localhost`。没有上游代理的身份什么都不设，直连。
- 这样做而不是把上游代理直接写进环境变量，有三个原因：
  - **代理的密码不进 agent 的环境**（模型能读自己的环境变量；项目规定凭据不以明文进模型上下文）。进程只看得到本机的口。
  - **换上游不用重开终端**，浏览器和 agent 同时换。
  - **上游可以是 SOCKS**：四家里只有 Codex 认 SOCKS 而且不完整（agents-v0 §11），转发层替它们转。你要的 HTTP 代理自然也行。
- 一个终端里 agent 自己的流量和它跑的命令（`git`、`curl`、`npm`）都走这个出口。Codex 的进程本身现在不带代理变量（只给它跑的命令），有出口的配置下要给它自己也设上。
- 转发层不拆 HTTPS（只转隧道），终端里不需要装任何证书。

## 5. 浏览器

**agent 与浏览器的关系**：经身份。终端里 agent 的浏览器工具连到“它的配置所指身份”的那个浏览器，于是它上网的出口、指纹、登录态都是那个身份的。两个配置指向同一个身份，就共用一个浏览器；指向不同身份，就各用各的。

**同时开几个**：一个身份一个 Camoufox 进程（指纹是启动时给的，一个进程只能有一份）。用到时才启动（约 8 秒），没有标签页且闲置一阵后自己停。同时运行的上限先定 3 个，超出时停掉最久没用、没有标签的那个。

**`Browser` 页显示什么**：

- 左栏先按**身份**分组，每组一行头：身份名 · `macOS · Firefox 156 · http Tokyo` 或 `direct` · 运行中 / 未启动；组内照旧按“谁的标签”分（你的、各终端的 agent、任务）。
- 状态栏右端的身份浮框（`Fingerprint` / `Proxy` / `Engine`）跟着所选的那一组；`Engine` 是全机一份。
- `⌘T` 开在所选身份的浏览器里。没有建过第二个身份时，这一页和现在一样（只有一组，不显示组头）。
- 真窗口谁是谁：几个 Camoufox 在程序坞里长得一样，窗口上要能看出身份（标题前缀或工具栏颜色，能不能做到要实测，待定）。

**回复框右下角的浏览器图标**：点一下，启动（如未启动）并把这个终端所属身份的浏览器窗口叫到最前；它没有标签时开一个空白标签。这个浏览器里有标签在等你时，图标上一个点。手机上点它是跳到 `Browser` 页的那一组。

**登录走对应的浏览器**：新建订阅登录的配置时，agent 要开的登录页开在这个配置的身份的浏览器里（给 agent 的 `BROWSER` 变量指向一个只会“在某身份里开标签”的小程序；Claude Code 的程序里读这个变量、并为远程会话改写它，看起来是认的，四家都要实测；不认的就由你把它打印出来的登录地址贴进那个浏览器），这样登录发生在对的指纹和出口下。

## 6. 其他 agent、官方 App、调度

- **其他 agent**：同一个形状，只有 §2 表里那两列不同（家目录怎么给、怎么登录）。各自的注意点：
  - Codex：服务对自己 hook 的信任是记在 `CODEX_HOME` 的 `config.toml` 里的，每个配置的家目录要各做一次；Daybreak 的默认值也是每个家目录各一份；会话能不能跨家目录续接要实测（它有自己的库，不只是文件）。
  - OpenCode：会话在它的库里，不能跨配置共用。
- **官方 App**：不受影响（§0）。代价是反过来的：在别的配置下开的 Codex 会话，ChatGPT App 的会话列表里看不到。要让官方 App 跟着换，只能像 cc switch 那样改写默认目录——订阅登录的还要换钥匙串里的条目，App 开着时两边都会坏。先不做；以后若做，只对 API 供应商类的配置提供一个明确的 `Apply to This Mac`。
- **调度任务**：第一步不变，仍用 `Default`。之后每个 agent 的任务用它的当前配置，用量那几行按配置分开显示；凭据网关要接在身份的出口后面（待设计）。

## 7. 边界：这是隔离，不是伪装

- **做的**：每个配置一套干净、自己生成的状态（标识、登录、浏览器），一个固定的出口。
- **不做**：改写 agent 上报的系统信息、冒充别的客户端或别的硬件。那已经不是隔离，而是对服务商造假，而且每次升级都会坏。
- **管不到的**：付款方式、邮箱与手机号、使用习惯（同样的仓库、同样的时间）、同一份客户端程序的网络特征、上面说的硬件探测若真的发出去。所以它**不保证几个账号不被关联**。
- 同时用几个账号、从别的地区使用，各家条款各有规定，由使用者自己判断。

## 8. 安全网关只留在调度里

用户已定。终端里拿掉的：

- 进程的网关环境（代理指向网关、网关的证书、`SECRET_GATE_HOME`）；Codex 给它跑的命令的那一份同样拿掉。
- Claude Code 终端里的网关工具（`secret_*`）。
- 回复的加密：接口的 `seal`、Mac 的 `Encrypt & Send…`（`⌘⇧V`）与回复框、状态栏上的锁、手机回复框旁的锁与“像密码时先问”。

留着的：

- 调度的一切照旧。
- **浏览器前面的那一层**（待定 4）：agent 用浏览器时页面内容的遮盖、密文填入、`Browser` 页的 `Fill Ciphertext`。`BOUNDARY.md` 写着“agent 不得有不经网关的浏览器”，这是浏览器的保护，不是会话的功能。
- 禁区（凭据文件不给终端里的 agent 读）照旧，并且要加上：一个终端读不到**别的配置**的家目录。
- 代理密码、API 密钥的存放仍用密文（同浏览器身份里的代理密码），明文只在服务的内存里。API 供应商类的 Claude Code 配置用它自己的 `apiKeyHelper` 取密钥，密钥不进环境变量。

## 9. 分步

1. 网关从终端里拿掉（§8）。
2. Claude Code 的配置：家目录、启动、登录、列表与当前配置、新建终端里选、终端上标名字、`Continue As`。只在终端里。
3. 身份有多个：每个身份一个转发口与一个浏览器；配置指向身份；agent 进程的代理；回复框的浏览器图标；`Browser` 页分组。
4. Codex 的配置。
5. OpenCode、pi。
6. 调度任务用配置。
7. （可选）`Apply to This Mac`。

每一步先补演示页（`docs/design/concepts/profiles.html`）。

## 10. 待定

4. **终端里的 agent 还要不要浏览器工具，以及它前面留不留网关那一层**（§8）。提议：要，留。
