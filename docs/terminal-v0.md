# terminal-v0：手动入口——AgentSwitch 自己的终端会话

2026-09-28 用户要求：在 Mac 和手机上统一管理 agent 的终端会话——看有哪些、回话、删除，权限请求直接点。决定做**两个入口**：

- **调度**（Dispatch；原称“托管”，2026-10-02 定名，dispatch-v0）：现在的对话框。说一句话，调度模型选执行器和模型、派活、验收（assistant-v0、loop-v0）。
- **手动**：你自己选 agent 和目录开终端会话，自己盯、自己回、自己批。模型还做不到完全托管，需要人直接上手的时候用这个。

两个入口并列，互不代替；本文只讲手动入口。本文是草案。

> 2026-09-28 演示已实现：服务端（§2–§4，`packages/daemon/src/terminals/`、`src/api/terminals.ts`）和网页演示页（控制台 › 终端，`ui/terminal.html`）。用真 Claude Code（Haiku）验证过：新建、信任对话框用按键条作答、网页上点“允许”后终端显示 “Allowed by PermissionRequest hook”、在终端里直接作答后卡片自动撤掉、`--resume` 续接后记得上一轮；Codex 能在终端里启动。Mac 窗口和 iPhone 页面未做。

## 0. 原则

- **终端进程归服务所有**：daemon 启动并持有每个会话的伪终端（像 tmux 的服务端），Mac 和手机都只是显示端。关掉窗口、手机断线，会话照跑；任一端连上都看到当前屏幕。
- **不做终端模拟器内核**：显示用 SwiftTerm（macOS 与 iOS 同一套），服务端用 `node-pty` 起进程、`@xterm/headless` 维护屏幕与回滚。
- **只能开 agent，不能开 shell**：可启动的程序限定为 `claude`、`codex`、`opencode`、`pi`（及它们的参数），手机上没有“开一个终端”这种能力。
- **会话同样在凭据网关后面**：环境与托管执行器相同（代理、CA、secret-gate MCP、禁区），所以密文在手动会话里也能用；加密发送的回话先过 sealer（或本地前台，local-model-v0），直接发送的同在 Mac 上敲键盘。
- **权限请求直接给你**：手动入口里不经调度模型代批；按钮来自 agent 的 hook，不靠识别屏幕。

## 1. 界面

用词：界面上叫“终端”（“会话”已经是 thread 的叫法，ui-v0 §4）。

**iPhone**：底部两个标签页 **调度** · **终端**（`Dispatch` · `Terminals`）。

- 调度：现在的首页，不变。
- 终端：列表 = AgentSwitch 持有的终端（等你处理的在最前，状态点：进行中 / 等你 / 空闲 / 已结束）+ 一组“Mac 上的其他会话”（现在「设置 › 编码会话」的只读列表搬到这里）。右上角“新建”：选执行器（Claude Code / Codex / OpenCode / pi）、目录（最近用过的目录 + 默认工作目录 + 手动输入）、模型（可选，默认用该执行器自己的默认）。
- 终端页：SwiftTerm 实时显示（可滚动回看、可缩放）；底部回话框（多行，发送 = 粘贴进去再回车）；常用按键条（Esc、Tab、↑↓、Ctrl-C、回车）；有权限请求时上方出现卡片：请求原文 + 允许 / 拒绝（Claude Code 另有“本会话都允许”）。agent 出选择题（Claude Code 的 `AskUserQuestion`）时，卡片是问题卡：每题的问题和选项，选好后提交，没有允许 / 拒绝（2026-10-01，§3 “选择题”）。
- **一轮的结果**（2026-09-30，assistant-v0 §4 “结果要提示”）：服务记下每个终端最近一轮怎么结束——`Stop` / `agent-turn-complete` / pi 的 `agent_end` / OpenCode 伴随进程从忙到空闲算完成（从进行中或等你转过来才算，重复的 `Stop` 不算两次）；Claude Code 的 `StopFailure`（会话配置里多注册这一个钩子）和进程非零退出算失败。只放在本机的 `GET /live` 里给 Mac 的实时活动（完成时带 agent 最后一段回答的开头，只在内存里，不入库、不进日志、不经远程，也不进终端列表）。
- 提醒复用托管那一套：等你处理时提示音、实时活动一并显示终端的待处理项；在干活的终端也进实时活动（2026-09-30，assistant-v0 §4），显示它正在用的工具——服务从 `PreToolUse`（pi 是 `tool_call`）记下最近一次的工具和对象，回到空闲时清掉。Mac 菜单栏的实时活动（assistant-v0 §4，2026-09-30）同样列出等你的终端，权限请求在卡片上直接 allow / deny，没有请求 id 的“等你”（如 Codex 的表单）点 `[ open ]` 进终端窗口的那个终端。选择题（§3）在卡片上只写第一题的问题、按 `[ open ]` 进终端作答（`GET /live` 给它 `kind: "question"`、`answerable: false`），不出 allow / deny。
- 「设置 › 编码会话」移除（内容在终端标签页里）。

## 2. 会话宿主（daemon）

```
SessionHost
  spawn(harness, cwd, model?, resume?) → TerminalSession
  TerminalSession {id, harness, cwd, argv, pid, cols, rows, status, title,
                   agentSessionId?, createdAt, lastOutputAt, origin: "new"|"resumed"}
  write(id, bytes) · resize(id, cols, rows) · kill(id) · snapshot(id) · subscribe(id, afterSeq)
```

- `node-pty` 启动，工作目录只要是存在的文件夹（2026-09-30 起，用户：终端的使用体验不能不如普通终端；此前按 control-v0 §2 的任务规则，不能是主目录、`~/Library`、`~/.config` 等）。环境 = 托管执行器的 gate 环境 + `AGENTSWITCH_TERMINAL_ID=<id>`（hook 靠它把事件对上会话）。
- `@xterm/headless` 维护屏幕，`@xterm/addon-serialize` 出快照；输出按序号切块保存在内存环形缓冲（默认 2 MB/会话），供断线续传。
- 输出只在转义序列之间切块：程序的一块输出可能停在一个序列中间，从快照接着画的屏幕会把序列后半截当文字显示（实测出现过 `27;2H`）。没写完的尾巴留到下一块一起发，50 毫秒内没有下一块就照发。
- 状态：
  - 进行中 / 等你 / 空闲来自 hook 或伴随进程（§3）；两者都没有时按“最近 N 秒有输出”估计进行中，其余为空闲。估计时不把“对刚发过去的东西的回应”算作工作（2026-09-29，用户：闲置状态经常判定为工作中）：全屏的 agent 在等待时也会重画——回显你敲的字、鼠标在屏幕上移动、焦点变化、改尺寸、服务请求的重画——所以写入、改尺寸、重画之后 600 毫秒内的输出不会把空闲的终端变成进行中（已在进行中的照旧保持）。
  - 伴随进程（`Companion`，2026-09-29）：和程序一起启动、替它报状态和权限请求，先于程序启动，可以改程序的启动参数；启动失败就按原计划启动程序，状态靠估计。终端从创建那一刻就在列表里（`pid` 为空），伴随进程启动期间第二次续接同一会话会找到它；期间被删除则不再启动程序。目前只有 OpenCode 用（§3）。
  - 已结束：进程退出，保留最后屏幕与退出码，直到你删除。
- 服务重启（含 Mac 应用换新版）时伪终端随之结束。v0 不保存终端列表，重启后列表为空；agent 自己的会话记录仍在，出现在会话列表里，可“继续”（§5）。（原计划标“已中断”，未实现。）Mac 的终端窗口在页面收到 401 或网页进程退出时自动重新登录。
- 打包：`node-pty` 是原生模块，Mac 应用的运行时要带 darwin-arm64 的预编译产物，`build-app.sh` 加检查。

## 3. hook：状态与权限

AgentSwitch 启动的会话，hook 通过**会话自己的配置**注入（命令行参数或会话专用的配置目录），**不改用户的全局配置**；用户在 iTerm 里自己开的 agent 不受影响。唯一的例外是 Codex 的 hook 信任记录（见下，2026-09-29 用户同意）。

| 执行器 | 状态 | 权限请求 | 注入方式 |
|---|---|---|---|
| Claude Code | `SessionStart`→空闲（并报会话 id），`PreToolUse`→进行中（并过禁区），`UserPromptSubmit`→进行中，`Notification`/`Stop`→等你/空闲，`PostToolUse`（撤掉在终端里答过的请求） | `PermissionRequest` hook 返回 `{"behavior":"allow"}` 或 `{"behavior":"deny","message":…}`（结构化，不按键）；选择题返回 `allow` 带 `updatedInput.answers`（见下“选择题”） | `--settings <会话专用 settings.json>`，有 gate 时另加 `--mcp-config` |
| Codex | hook（与 Claude Code 同名同格式）：`SessionStart`、`UserPromptSubmit`、`PreToolUse`（过禁区）、`PostToolUse`、`Stop`；等你：Codex 自己的“需要你”通知（OSC 9，见下）；信任之前退回 `notify` + 按输出估计 | `PermissionRequest` hook，同 Claude Code | `-c hooks.<事件>=[…]`、`-c notify=…`、`-c default_permissions=…` 等命令行覆盖；hook 的信任记录写进用户的 `~/.codex/config.toml`（见下） |
| OpenCode | 伴随进程看它的服务：有会话在跑→进行中，有待答的问题或（逐项确认时）待批的权限请求→等你，否则空闲 | 服务上的权限请求出卡片，在服务上作答；在 TUI 里先答了就撤卡片；`--auto` 下 TUI 自己批，不出卡片 | 服务自己起 `opencode serve --stdio`（带终端的环境与 `OPENCODE_CONFIG=<会话专用配置>`），TUI 用 `--server <url>` 连上，密码经 `OPENCODE_PASSWORD`；起不来时退回 `--standalone`，状态靠估计 |
| pi | 扩展：`agent_start`→进行中，`agent_settled`→空闲（没有它的旧版用 `agent_end`），`ui_prompt_start`/`ui_prompt_end`→等你/进行中；`tool_call` 过禁区 | 无权限层 | `--extension <AgentSwitch 自带的扩展>` |

- hook 命令（`src/terminals/hookClient.ts`，用服务自己的 node 运行）只做一件事：把事件 POST 到本机 `/terminals/hook`，带 `AGENTSWITCH_TERMINAL_ID` 和**这个终端自己的 hook 令牌**（`AGENTSWITCH_TERMINAL_HOOK_TOKEN`）。**不用本机令牌**：终端里的 agent 读得到自己的环境变量，拿到本机令牌就能调任何本机接口（2026-09-30 起终端里的 agent 本来就能读本机令牌文件，§3；hook 仍只带自己的令牌，环境里不放本机令牌）。hook 令牌只能给自己这个终端报事件、提权限请求，不能替自己作答；本机令牌检查对这一条路由放行，由路由自己核对 hook 令牌。权限请求的 hook 等服务回答（最长 30 分钟），没人回答就不给结论，agent 照常在终端里问。hook 命令出任何问题都静默退出，不影响 agent。
- **Codex 的 hook**（2026-09-29，codex 0.158）：事件名和输入输出与 Claude Code 相同（`hook_event_name`、`session_id`、`tool_name`、`tool_input`；`hookSpecificOutput.permissionDecision`、`decision.behavior`），用 `-c hooks.<事件>=[{matcher="*",hooks=[{type="command",command=…,timeout=N}]}]` 按终端传入。Codex 只运行**已信任**的 hook，信任不能从命令行给：它是用户 `~/.codex/config.toml` 里 `hooks.state."<键>".trusted_hash` 记的哈希，哈希覆盖整条定义，命令一变就要重新信任。经用户同意（“直接加入 ~/.codex/config.toml 哈希不行吗”→“可以”）由服务写入，这是 AgentSwitch 对这个文件唯一的改动：服务起一个一次性的 `codex app-server`（同样的 `-c` 参数，不调模型），用 `hooks/list` 看哪几条没信任，再让 Codex 自己用 `config/batchWrite` 写入哈希（文件其余内容原样保留），写完再查一遍。每次新开 Codex 终端前都重查一遍（不到 1 秒）：开发者的另一份 AgentSwitch 会在同样的键下写自己的哈希，而带着 Codex 不信任的 hook 启动，终端会停在 Codex 的“Hooks need review”上。重查期间视为未知，等不及的终端不带 hook 启动。测试不碰用户的 Codex 配置（2026-09-29 查出 `tests/build.test.ts` 启动的 daemon 找到了本机的 Codex、把测试用的哈希写进了用户配置，冲掉了应用写的那份）：测试进程的 `CODEX_HOME` 指向临时目录，用默认配置建 daemon 的测试关掉终端。信任确认之前 Codex 终端不带 hook（没有权限卡片），状态靠 `notify` 与估计；列出的 hook 不满 6 条（Codex 太旧）时同样如此。`SessionStart` 在第一次提交时才触发。hook 管不到的确认：应用工具（如 Computer Use）的批准是一张表单（`request_user_input`），不经 `PermissionRequest`（2026-09-29，用户：这个怎么没 hook 到）。“等你”用 Codex 自己的通知：终端带 `-c tui.notifications=["approval-requested","async-question","plan-mode-prompt"]`、`tui.notification_method="osc9"`、`tui.notification_condition="always"`，Codex 每次有东西等你（命令批准、应用的表单、问题、计划确认）都往终端写一条 OSC 9（实测：`ESC ]9;Approval requested: …`，窗口不在前台也发），服务读到就显示“等你”；之后任何 hook 事件（工具跑完、这一轮结束、你又发了话）或在屏幕上答了（卡片），回到进行中；没有 hook 时你一打字就算答了。事件名是 Codex 配置的一部分，不读屏幕文字。先前一版读的是标题前缀 `[ ! ] Action Required`，用户指出标题文字随时会改、不够正式，已换掉；名字里仍去掉这段前缀（否则名字会跟着闪）。
- **OpenCode 的伴随进程**（2026-09-29，OpenCode 2.0.18，`src/terminals/opencodeTerminal.ts`）：2.x 的插件是装在目录里的 Effect 模块（配置里的 `plugins` 只认目录，1.x 的单文件插件不加载），没有能按终端传入的 hook；但它的 TUI 本身是服务的客户端，服务知道什么在跑、什么在等。所以服务替每个 OpenCode 终端起一个私有服务（和 `--standalone` 起的一样，只是地址和密码在服务手里），TUI 用 `--server` 连上；服务每 0.5 秒看一次 `GET /api/session/active`、`/api/permission/request`、`/api/form`。权限卡片按 Claude 的工具名显示（`shell`→Bash、`edit`→Edit、`read`→Read、`webfetch`→WebFetch，其余用 OpenCode 的动作名）；允许回 `once`（不回 `always`，那会在 OpenCode 共用的数据库里存一条以后都生效的规则），拒绝回 `reject`。TUI 进程的环境里有这个私有服务的密码（TUI 从 `OPENCODE_PASSWORD` 读），只能访问这个终端自己的回环服务；私有服务自己的环境里没有密码（`--stdio` 启动后删掉）。终端结束时私有服务一起结束；AgentSwitch 服务退出时它的标准输入关闭，也会自己退出。实测：TUI 连上后显示正常；用接口造一个待批请求，出卡片、状态变“等你”，在卡片上拒绝后请求在 OpenCode 里消失，状态回到空闲；终端退出后私有服务也退出。
- 实测（Claude Code 2.1.283）：`PermissionRequest` hook 运行期间，终端里**同时**显示 Claude 自己的确认框，两边谁先答算谁的。在终端里答了，Claude 不会结束那个 hook，所以服务端靠随后的事件撤卡片：工具执行了（`PostToolUse`，按工具名和输入对上那一条）、这一轮结束（`Stop`）、用户又发了话（`UserPromptSubmit`）。
- **选择题**（2026-10-01，用户：如果 agent 给一个选择题也会出这个 allow deny，这样不太对吧？能不能 hook 的更精细，直接用这个框来选 agent 给的选项）：Claude Code 的 `AskUserQuestion`（输入 `{questions:[{question, header, multiSelect, options:[{label, description}]}]}`，1–4 题，每题 2–4 个选项，“Other” 由界面自己加）同样经 `PermissionRequest` hook，原先每个画面都给它出通用的权限卡片（`AskUserQuestion` + 原始 JSON + allow / deny），而且点 allow 什么也没答上（见下）。现在：
  - **服务**认出这一种请求：工具名是 `AskUserQuestion`、`questions` 每题都有问题文字和选项（或没有选项、只收文字的题）时，请求多一个 `questions: [{question, header, multiSelect, options:[{label, description}]}]`（原有字段不变，旧画面照旧显示，但它们的 allow 会被拒，见 §4），`summary` 是问题本身（多题用 “ · ” 连起来），手机朗读、实时活动、Mac 菜单栏都按它写。
  - **卡片**（网页终端页 = Mac 终端窗口、iPhone 终端页；演示页 `terminal.html#ask`、`phone.html?ask`）：琥珀标题条（网页 `[?] Question`，手机是方块加 `Question`，同各自的权限卡片）；每题一段：`header`（agent 写的短标签，淡色 `// header`）、问题、选项（`label`，`description` 淡色在下）；单选 `< >` / `<x>`、多选 `[ ] [x]`（ui-v0 §7.2.6），最后一行 `Other` 带输入框，在里面打字就选上它（单选时替换已选的项，多选时并列）；每题都有答案后 `[ Submit ]` 才可点。没有 allow / deny：不想答就在终端里按 esc（Claude Code 自己的“拒绝”），或者直接在终端里答。
  - **提交**：`POST /terminals/:id/permissions/:pid {decision: "allow", answers: {"<问题原文>": {labels?: [...], other?: "…"}}}`（§4）。服务核对：问题原文必须是这个请求里的；`labels` 必须是该题的选项；单选恰好一个（一个选项或 Other 的文字），多选至少一个；只收文字的题只收 `other`。Other 的文字默认先过 sealer（同 `/input`，发现凭据换成密文；`seal: false` 跳过），审计仍只记 decision 与工具名，不记答案。
  - **回给 Claude Code**：hook 返回 `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow","updatedInput":{…原来的输入, "answers":{"<问题原文>":"<答案>"}}}}}`。答案的写法照 Claude Code 自己的对话框：单选是选项的 `label`；多选是各 `label` 用 “, ” 连起来（`label` 里本身有 “, ” 或 `"` 的，用 JSON 字符串的写法加引号）；选 Other 时是打的字（多选时作为最后一项）。
  - **依据**（Claude Code 2.1.286 的内嵌 JS，2026-10-01 读二进制里的源码；没有对真模型跑过）：
    - `AskUserQuestion` 的 `requiresUserInteraction()` 为真，`checkPermissions` 总是 `ask`（“Answer questions?”）；输入的 schema 里有 `answers: record<问题原文, string | string[]>`（数组按 “, ” 连成一条）和 `annotations: {<问题原文>: {notes?, preview?}}`；`call()` 读 `answers`，交给模型的结果是 `"<问题>"="<答案>"`——全是选项原文时说 “Your questions have been answered…”，有自己写的字时说 “The user answered… Read the answers carefully…”，一题没答则 “The user did not answer the questions.”。
    - 交互界面的权限处理（`runHooks`）里有 `if(!F.updatedInput&&e.requiresUserInteraction?.())return null;`：**不带 `updatedInput` 的 allow 对问题无效**，Claude Code 当作 hook 没有结论，对话框照旧等着——这就是原先点 allow 没答上的原因。带了 `updatedInput` 时，重新检查权限（`Cx(…, {hookUpdatedInput})`）对 `AskUserQuestion` 与 `ExitPlanMode` 跳过“必须问人”（`N1n`：`new Set([ExitPlanMode, AskUserQuestion])`），随后 `handleHookAllow(updatedInput)` 用 hook 给的输入执行工具；这份输入要过工具的 schema（不合就报 “The permission handler returned updatedInput for … that failed schema validation”），所以要带上原来的 `questions`。
    - 对话框自己的答法（`ze(question, value, otherText)`）：多选 `Brt(labels)`（“, ” 连接，含 “, ” 或 `"` 的 JSON 加引号），Other 用输入的文字，`label` 原样。
    - hook 和对话框同时进行（`jo`：`L=await r.runHooks(…)` 后 `k(L)`），hook 先答时走 `onWin` → `q()` → `te?.abort()`（`Ze()` 给这次对话框建的 `AbortController`）：**终端里的对话框随之关掉**。终端里先答了，hook 照旧没人结束，卡片仍按 `PostToolUse` 撤掉（同上）。
    - SDK 宿主的 “strict” 模式另有 `admitCardAnswer`，只许多出 `answers` `annotations` `response` `followUp` 这几个字段；终端里的是交互界面（“launcher”），不经它，但我们给的形状也满足它。
  - `annotations.notes`（给某题附一句话）Claude Code 收，卡片暂不提供。iPhone 的调试演示：`-uiDemo YES -uiDemoScreen terminalquestion`。
  - **Codex**（0.158）：没有对应的路子——它的提问（`request_user_input`）不经 `PermissionRequest`，而 `PermissionRequest` 的 `updatedInput` 它明确不收（“PermissionRequest hook returned unsupported updatedInput”，schema 注明 “Reserved for a future input-rewrite capability … fail closed if this field is present”）。Codex 终端维持原样：它的问题在终端里答，“等你”照旧来自 OSC 9。
- 环境：去掉“当前是某个 Claude Code 会话”的标记（`CLAUDECODE`、`CLAUDE_CODE_CHILD_SESSION`、`CLAUDE_CODE_SESSION_*`、`CLAUDE_CODE_MESSAGING_*` 等）。服务从 Claude Code 里启动时（开发者这样跑过）会被新终端继承，Claude 会以为自己是子会话、不存会话记录，还会拿到上层会话的消息通道令牌。用户自己的设置（`ANTHROPIC_*`、`CLAUDE_CONFIG_DIR`）保留。
- **权限模式**（2026-09-28，用户：iTerm 里用 `claude --dangerously-skip-permissions`，AgentSwitch 的终端却回到了自动或逐项确认）：新建和“继续”时选“逐项确认 / 自动 / 跳过权限”，页面记住上次的选择，第一次跟随 Mac 的审批模式（control-v0 §1：manual→逐项确认，scoped/auto→自动，skip→跳过权限）。对应参数：Claude Code `--permission-mode manual|auto` 或 `--dangerously-skip-permissions`；Codex 逐项确认为 `-a on-request -s read-only`（2026-09-28 审计：原先不带参数，实际权限取决于用户的 `config.toml`，可能是从不询问），自动为 `-a on-request -s workspace-write`，跳过为 `--dangerously-bypass-approvals-and-sandbox`；OpenCode 自动和跳过都是 `--auto`；pi 没有这一层。跳过权限在 Mac 和手机上都能选（2026-09-29 用户要求；原先手机请求 403），手机上选它先确认；标题带上显示“跳过权限”。
- **继续沿用原会话的模式**（用户：点“继续”没地方选跳过权限，进去就是 auto）：会话列表从记录里读出每个会话最后用的模式（Claude Code 取最后一条 `permissionMode`；Codex 取最后一次的 `approval_policy` 与沙箱，`never` + `danger-full-access` 即跳过权限），“继续”就用它，读不出时才用记住的选择。归入三个词时只能收紧、不能放宽（2026-09-28 审计）：Claude Code 的 `acceptEdits`、`dontAsk`、`plan` 都比 auto 窄，一律按逐项确认继续；Codex 只读沙箱或记录里没有沙箱的，按逐项确认继续，可写沙箱才算自动。侧栏里跳过权限的会话和终端标“跳过权限”。Claude Code 终端另带 `--allow-dangerously-skip-permissions`，以别的模式启动后也能在终端里按 ⇧Tab 切到跳过权限（和 iTerm 一样；2026-09-29 起手机开的也带）。
- **不重复继续**：对已经在终端里打开（或已分叉出终端）的会话再点“继续”，直接切到那个终端（服务端同样：`/terminals/resume` 返回已开着的那个）。现在“继续”接着写原会话，不再每次多出一份记录；分叉只在用户选了“分叉一份”时发生（§5）。
- **终端的禁区只剩凭据**（2026-09-30，用户：“在终端里去掉所有模型不可以读取本地令牌的限制吧，要不使用体验还不如终端，只在路由器调度的入口加上这个限制”；另选了放开 AgentSwitch 自己的文件和终端目录）：终端里的 agent 和在普通终端里一样，能读本机令牌（因而能调本机接口，包括替自己批准、改审批策略）、读写 AgentSwitch 的数据目录与配置、读远程 TLS 私钥和浏览器会话目录（各网站的登录态；用户随后也放开：“浏览器会话目录也别禁止了”）。仍然拒绝的只有网关的私钥与 socket（读到就能解开所有密文；网关以独立账户运行时私钥本来就读不到）。路由器调度的任务（托管执行器）照旧用完整的禁区表。下面各 agent 的做法不变，只是给终端的是这张小表（`terminalProtected`）。
- **禁区**（2026-09-28 审计后补齐；用户决定不另加系统沙箱，各用 agent 自己的机制）：
  - Claude Code：`PreToolUse` hook 把每次工具调用交给服务，按托管执行器同一套规则（`decideTool` + 禁区表）判断，碰到本机令牌、gate 密钥、浏览器会话目录等就拒绝，其余不给结论、交回 agent 自己的模式决定；任何模式下都在（实测跳过权限模式下让它读本机令牌，被这一层拒绝）。会话配置另带 `permissions.deny` 的 `Read`/`Edit` 规则，服务无响应（hook 放行）时仍挡直接读取。
  - Codex（2026-09-29 改，用户：Codex 桌面版里批准了 `ps` 就能跑，终端里批准了也跑不了；“不用管沙箱了，直接改就行了”）：Codex 从不放开 `deny` 条目（它给模型的权限说明里标着 `escalatable="false"`），带着它们，批准“到沙箱外运行”的命令仍在沙箱里执行，而沙箱里起不了 setuid 程序（`ps`、`top`、`sudo`、`ping`；`codex sandbox` 复现同样的 `operation not permitted`）。桌面版的配置里只有 `read`/`write`，所以能跑。现在 hook 生效时禁读目录不再写成 `deny`，改由 `PreToolUse` 过禁区（实测：Codex 报 `tool_name: "Bash"`、`tool_input.command`，与 Claude Code 同一套检查），批准后的命令真正在沙箱外运行（实测 `ps` 正常）；禁区根目录仍是 `read`，沙箱里不可写。代价：沙箱内的命令对这几个路径的保护从系统强制降为按命令文字比对，同 Claude Code；网关私钥在独立账户里，不受影响。hook 未生效时仍用下面的旧做法。旧做法：用它自己的权限配置（`default_permissions` + `[permissions.agentswitch]`，逐项确认继承 `:read-only`、自动继承 `:workspace`），禁读目录设 `deny`、其余禁区设 `read`。由 Codex 的系统沙箱执行，换写法（`cd` 后用通配符、脚本）也读不到（实测，codex 0.158）；但只管沙箱里跑的命令：跳过权限模式没有沙箱，用户批准到沙箱外运行的命令也不受限。gate 代理与 CA 只经 `shell_environment_policy.set` 给它执行的命令，不放进 Codex 进程自己的环境（同托管执行器）。
  - OpenCode：会话专用配置里的 `permission` 拒绝规则（读按路径、bash 按命令文本、写与外部目录按路径），与托管执行器同一份禁区表；只加拒绝，不改用户其余的权限设置；`--auto` 下同样生效。终端里的 OpenCode 用私有服务（AgentSwitch 起的；退回时是 `--standalone` 起的）：2.x 默认把会话放进用户共用的后台服务（`opencode serve --service`）里跑，终端进程的环境（这份配置、gate 代理）到不了那里（2026-09-28 实测：私有服务的 agent 权限里有这些拒绝规则，后台服务里没有）。
  - pi：没有权限层；AgentSwitch 自带扩展在 `tool_call` 时把工具与参数交给服务，按 `decideTool` 判断，拒绝即 `block`。扩展出错或服务无响应时拦截（pi 的约定：处理出错即拦截）。
  - 除 Codex 外都是按字符串比对工具参数，挡直接的读取，挡不住有意绕过（BOUNDARY.md）；同一系统账户下真正的隔离只有网关的独立账户。
- **浏览器工具**（2026-10-02，browser-v0 §6）：Codex、Claude Code、OpenCode 的终端会话多一个 MCP 服务器 `browser` = `secret-gate browser -- <agent 桥>`，在 AgentSwitch 服务持有的共享浏览器里开标签，你在 App 的 Browser 页看得到、可接手（标签归在 `codex · <文件夹>` 名下，Claude Code 写作 `claude`）。注入方式同上表，不改用户的全局配置：Codex 是 `-c mcp_servers.browser.{command,args,env,tool_timeout_sec}`（工具超时 300 秒：你接手时它的调用最多等 2 分钟），Claude Code 是 `--mcp-config` 里 secret-gate 旁边的一项，OpenCode 是 `OPENCODE_CONFIG` 里的 `mcp.browser`。终端启动时服务为它发一个浏览器会话，令牌在 `$AGENTSWITCH_HOME/browser/sessions/` 下的 0600 文件里，桥从文件读（不进命令行、环境和模型上下文）；程序退出即作废，删除终端时它的标签一并关闭。只在网关可用时加（不给 agent 未经网关的浏览器）；pi 没有 MCP，不加；`AGENTSWITCH_BROWSER_HOST=0` 时不加。与你共用 `main` 配置的登录态（browser-v0 决定 3）；同一 uid 的 agent 读得到令牌文件，这只挡随手直连，不是边界（同 hook 令牌）。
- 各家 hook 名称与返回格式随版本变化：实现前逐家核实并在测试里固定样例；探测不到 hook 能力的版本退回“按键作答 + 屏幕原文”。
- 权限按钮的底线同托管：删除、推送、付款、禁区相关的请求在手机上二次确认；禁区照拒（执行器层直接拒，不出按钮）。

## 4. 接口

本机与远程同一组路由（远程只给配对设备，走现有 TLS + 钉指纹）：

- `GET /terminals` → `{terminals, agents, models}`：AgentSwitch 持有的终端（含 `name`、`customName`、`title`）、本机装了的 agent、每个 agent 可选的模型（`[{id, name}]`，新建时的模型菜单）；其他会话仍从 `GET /sessions` 取。
- `GET /terminals/style` → 屏幕的字体与配色（§1）。`PATCH /terminals/:id {name}` → 改名，`null` 或空串恢复自动命名。
- `POST /terminals {harness, cwd, model?}` → 新建；`POST /terminals/resume {harness, agentSessionId, cwd, fork?}` → 续接（§5）：接着写同一个会话；它已开在 AgentSwitch 的终端里时返回那个终端（200，`existing: true`）；开在别的程序里时 409 `{error, elsewhere: {app, pid}}`；`fork: true` 分叉一份。会话 id 与模型 id 一样不得以 `-` 开头（它跟在 `--resume` 后面，否则可被当成参数，例如借此绕过“跳过权限只能在 Mac 上选”）；agent 不支持的续接或分叉返回 400（pi 不能续接，OpenCode 不能分叉）。会话所在的文件夹已不存在时返回 422 `{error, folderGone, alike, near}`（§5 “文件夹不在了”）。服务在启动进程前再查一次“已开在这里”，两个画面同时续接同一会话只得到一个终端。`cwd` 规范化后保存（`~/p/` 与 `~/p` 是同一个文件夹）。
- `GET /terminals/:id/stream?after=<seq>`（SSE）：先发快照 `{seq, cols, rows, data}`，再发输出块 `{seq, data}`（UTF-8 文本）、状态变化、权限请求；断线按 `after` 续传，缓冲外的旧序号直接给新快照。每次连上，补发之后都给当前的尺寸 `resize {cols, rows, by}` 和 `permissions {requests}`——此刻所有待处理的请求，整份。显示端拿它替换手上的列表（2026-09-30，用户：电脑上允许/拒绝之后手机上还留着这个请求，再点显示 no such request）：手机进后台后流就断了，断线期间在别处答掉的请求收不到 `permission_resolved`，重连原先只补发还在等的，不说哪些没了。点一个已在别处答掉的请求得到 404，显示端直接去掉卡片，不当错误。某个画面积压超过 5000 条未发出的事件时服务断开它，重连后从新快照开始。
- `POST /terminals/:id/input {text, submit?, seal?, attachments?}`：回话。`attachments: [{token, upload}]`（2026-09-30，用户：手机上图片附件只能插到消息开头、选了就直接发给终端，删不掉也没法在文字中途插图——要和 Claude Code 一样，给图片占位符，发送时再按输入的样子送过去）：手机选的图片和文件先 `POST /uploads` 暂存，正文里在光标处留占位符（`[Image #1]`、`[File #2]`）；服务先把整段正文过 sealer（sealer 只替换凭据，占位符原样留下），再按占位符把正文切开，依次粘贴文字和文件（文件搬到该终端的附件目录，同 `/attach`，每个文件的路径单独粘贴一次——Claude Code 把图片路径变成它自己的 `[Image #n]`，其他 agent 同在终端里拖进文件），之后回车；每段之间稍等一下，让 agent 接住每次粘贴。正文里没有的占位符对应的文件不发；没有对应文件的占位符按文字发。返回多一个 `attached`（发出的文件数），旧版服务不认 `attachments` 时就没有它，手机据此提示更新。`seal` 缺省为真：先过 sealer（发现凭据就换成密文再写入；本地前台可用时由它处理）；`seal:false` 直接写入（同在 Mac 上敲键盘，2026-09-29）。程序开了 bracketed paste 时整段粘贴再回车，多行回复不会被拆成几次发送。`POST /terminals/:id/keys {keys:["esc","ctrl-c",…]}`：控制键，不过 sealer；方向键跟随程序的光标键模式；`pgup` `pgdn`；`wheel-up` `wheel-down` 是滚轮：程序开了鼠标时按它的编码（SGR 1006 或默认）发在屏幕中间，全屏但没开鼠标时发方向键，普通屏幕不发（显示端自己回滚）。`click:<列>:<行>`（从 0 数，2026-09-30，用户：手机上的终端只能滚动，点击操作没透传）是在那一格点一下左键：程序开了鼠标时按它的编码发按下和松开（x10 模式只发按下），没开时什么都不发；格子超出屏幕的整个请求 400。`GET /terminals/:id/commands`：这个 agent 在这个文件夹里可用的斜杠命令（内置、自己写的命令和技能）。`POST /terminals/:id/attach {uploads:[id]}`（2026-09-30，用户：手机上不能直接发图）：先 `POST /uploads` 暂存，再把文件搬到系统临时目录下的 `agentswitch-attach/<终端 id>/`（路径不含空格，不放进项目文件夹；终端删除时一并删掉），把它们的完整路径以粘贴的方式输进 agent 的输入框、不回车——同在 Mac 上把文件拖进终端。Claude Code 收到图片路径会变成 `[Image #n]`；接着写要说的话再发送。返回 `{files:[{name, path, size, type}]}`；审计只记个数与大小。
- `GET /sessions`（control-v0 §3）不带 `limit` 时给出 Mac 列出的全部会话（每个 agent 最近 90 天里最新的 400 个记录，去掉临时目录、AgentSwitch 自己执行器的、没有标题的和探针），目录树用它（2026-10-03，用户：有的目录下面的session显示不完全，经常是有的时候我删除一个session之后又蹦出来几个）。原先网页和手机都只要最近 80 个、按更新时间截断，于是旧一些的会话不在它的文件夹里，删掉一个，下一个就补进来。手机发一个大数 `limit`，老版本的 Mac 按它自己的上限（500）给；手机在终端标签页上每 20 秒取一次（同网页，原来每 4 秒；下拉刷新、删除后立即取）。打开记录、删除、搜索也都在全部会话里找，不再只看最近的 200 或 240 个；搜索只留列表里还有的会话读过的话，删掉或过期的放掉；第一次搜索要读每个记录的末尾，会话多时会慢一些。git 状态只看终端的目录和最近用过的 60 个会话文件夹。
- `GET /sessions/search?q=` → `{hits: [{harness, id, excerpt}]}`（§1 搜索）：在目录树列出的会话（全部，同 `GET /sessions`）里找说过的话——用户打的字和 agent 的回复，不含工具调用、工具输出（常是整个文件）和子代理的记录；不分大小写，新的在前，最多 30 个，`excerpt` 是第一处命中前后的原话（一行）。每个会话读过的话留在内存里，记录只会在末尾追加，之后只读新加的部分（第一次只读每个记录最后 48 MB，每个会话最多留 100 万字）；读的时候每个会话之间让出事件循环，终端照常输出。`q` 1–200 字，否则 400。
- `GET /folders/git` → `{folders: {<文件夹>: {branch, changed, ahead, behind}}}`（§1 文件夹行的 git 状态）：只对目录树列出的文件夹跑 `git status`（终端的目录和最近用过的 60 个会话文件夹），不接受调用方给的路径；不在仓库里的文件夹不出现。`git status` 不用 fsmonitor、不拿可选锁（`--no-optional-locks`，不和 agent 自己的 git 抢 `index.lock`），同时最多 4 个，1.5 秒没出结果就放弃（大仓库宁可不显示也不拖慢）；结果 15 秒内算新，过期的先回旧值、后台再看；某个终端的 agent 用完一次工具或结束一轮，它的文件夹记为过期。macOS 没装开发者工具时 `/usr/bin/git` 只是个会弹安装框的壳，这时不跑。
- `POST /terminals/:id/write {data}`：原始按键，给本机的完整键盘（网页、Mac 窗口），**不在手机可用的路由里**（手机只走 `/input` 和 `/keys`）。
- `POST /terminals/:id/resize {cols, rows, screen?}`：多个显示端同时连着时以最后一次交互的那一端为准；`screen` 是显示端的 id，服务记为尺寸的主人（§1 “尺寸有主”），尺寸没变、主人换了也发 `resize` 事件。
- `POST /terminals/:id/permissions/:pid {decision: "allow"|"deny"}`。（`allow_session` 未实现。）选择题（§3，2026-10-01）：`{decision: "allow", answers: {"<问题原文>": {labels?: ["<选项>"…], other?: "<文字>"}}, seal?}`——答案不合（问题不是这个请求的、选项不在其中、单选不止一个、空答案）400；对选择题只给 `allow` 不给答案 400（旧画面的 allow 不再静悄悄地什么也没答）；对普通请求给答案 400；`deny` 照旧可用（同在终端里按 esc）。Other 的文字默认过 sealer（`seal` 缺省为真，同 `/input`；sealer 不可用时 400/503），返回 `{ok, sealed}`。
- `POST /terminals/:id/kill`：结束进程（SIGHUP，3 秒后 SIGKILL；发给整个进程组，agent 启动的子进程一并结束），终端留在列表里、保留最后的屏幕。
- `DELETE /terminals/:id`：结束进程并从列表移除；`DELETE /terminals/:id?transcript=1`：同时删除 agent 自己的会话记录文件（不可恢复，界面二次确认）。只删这个终端自己开出的会话：新终端或分叉的 agent 第一次报告的会话 id；之后在终端里 `/resume` 切过去的会话只跟随、不归它，关闭时不删（2026-09-28 审计：原先删的是最后报告的 id，会删掉别的会话）。等进程退出后再删，免得 agent 最后几次写入又把文件建出来。
- 审计：每次新建、续接、回话（只记长度和换成密文的个数，不记内容）、控制键、权限决定、结束、删除，一行一条记在 `$AGENTSWITCH_HOME/terminals/audit.jsonl`，带来源（`local` 或配对设备的 id）。本机原始按键不逐键记录。

## 5. Mac 上的其他会话

用户在 iTerm 等终端里自己开的 Claude Code / Codex / OpenCode 会话（control-v0 §3 已能读到）：

- 在终端标签页的“Mac 上的其他会话”里只读显示（最近消息、目录、时间），不能回话、不能批权限——进程不在 AgentSwitch 手里。
- “继续”：**接着写同一个会话**——Claude Code `claude --resume <id>`，Codex `codex resume <id>`，OpenCode `--session <id>`。记录只有一份，在这里聊过的，之后在 iTerm 里 `claude --resume`、在 Codex 桌面版里打开都看得到，反过来也一样（2026-09-28 第五轮改回，用户：要像 Codex 的 CLI 和桌面版那样保证会话唯一；上一版为了不碰 iTerm 里开着的原会话一律分叉，结果每点一次“继续”就多一份记录）。
- **同一时刻只让一个程序写**（2026-09-28 实测，Claude Code 2.1.283、codex 0.158）：
  - Codex 自己有写入锁：写一个对话的进程持有 `~/.codex/thread-writer-locks/<id>.lock`，第二个进程打开同一对话时显示“This conversation is open in another app”，可重试或分叉。桌面版也持有它载入的对话的锁。
  - Claude Code 没有锁：两个 `claude --resume <同一 id>` 同时开都不提示，两边各写各的，记录会岔开（记录是按 `parentUuid` 连的树，下次续接只沿其中一枝）。但每个运行中的 Claude 在 `~/.claude/sessions/<pid>.json` 登记 `sessionId`，退出时删掉。
  - 所以服务在续接前查这两处（登记的进程已不在、或 pid 已被别的程序占用的不算）：开着的是 AgentSwitch 自己的终端就直接给那个终端；开在别处则返回 409，带上是哪个程序（沿父进程往上找到的第一个 `.app` 的名字，如 iTerm2、ChatGPT），页面说明“先在那边退出再继续”，也可以选“分叉一份”（`fork: true`，即 `--fork-session` / `codex fork`：新会话带上完整历史，原会话不动）。OpenCode 查不到别处的进程，原会话还在活动时仍先确认。
  - 不是实时互见：两个在跑的进程各有自己的上下文，另一边写进记录的内容，要重新打开才看得到（所以才只让一个写）。真正实时共用只能是一个进程、多个画面——AgentSwitch 的 Mac 窗口和手机看的就是同一个终端；要让 iTerm 也接进同一个终端，需要 `agentswitch attach`（以后，同 tmux attach）。
- 已经在 AgentSwitch 里打开的会话不在列表里重复出现（`TerminalInfo.agentSessionId` / `resumedFrom`）。分叉出来的终端 `forked: true`。
- **文件夹不在了**（2026-10-03，用户问目录位置变了 Claude Code 的会话是不是就打不开了，确认后：如果会话没了选择新目录继续）：agent 按会话开始时的文件夹记它（Claude Code 的记录放在 `~/.claude/projects/<文件夹路径换成的键>/` 下，`--continue`、`/resume` 的默认列表、自动记忆和 `~/.claude.json` 里按路径的设置都跟着这个路径；Codex 记在会话开头的 `session_meta` 里）。文件夹被移动、改名或删除后，原来的“继续”在服务端被拒（`cwd … is not an existing directory`），没有出路。现在：
  - 续接时文件夹不存在，服务返回 422，带上它可能去了哪：Mac 知道的同名文件夹（其他会话和终端用过的、现在还在的，最多 5 个）和原路径上方最近一个还在的文件夹。新建终端时文件夹不存在仍是原来的 400。
  - 网页（含 Mac 窗口）弹出同一个确认框，多一行文件夹（同新建面板的写法，Mac 窗口旁边有 Choose…），候选一行一个列在下面，点一下填入；手机弹出 `Folder Gone` 页：同新建页的文件夹一行、候选、最近用过的文件夹，`[ Resume ]`。只有同名文件夹会预先填入；上方仍在的文件夹只列出不预填（2026-10-03 审查：预填时一个回车就会把会话挪进那个更大的文件夹，Claude Code 还会把记录也搬过去）；什么都没填时不能确认。路径整段发回服务（`~` 只用于显示），中文输入法里按回车选字不会提交。选好后用同一个请求换 `cwd` 再续接一次；选的文件夹也不存在时，框里仍说原来的文件夹，加一句“所选的 … 也不存在”，并把它留在框里改。之后若会话开在别的程序里，照常问要不要分叉，分叉也在新文件夹里。会话已经开在本机某个终端里时，服务先给那个终端，不再问文件夹；agent 不支持的续接或分叉先回 400。
  - Claude Code 在别的文件夹里续接一个会话时自己找得到（先找当前文件夹的记录，再在所有项目里按 id 找），并在记录里写一行 `{type: "relocated", relocatedCwd}`、把记录挪到新文件夹对应的项目下（2.1.288 的行为）。Codex 在别的文件夹里续接时会先问“用会话的目录还是当前目录”；服务续接或分叉 Codex 时总是带上 `-C <终端的文件夹>`，不再问（原来只在第一次换文件夹时带，之后会话的 `session_meta` 仍写着旧文件夹，可能每次都问）。OpenCode 按 id 续接，不保证它换了文件夹后的行为。
  - 列表里会话挂在哪个文件夹：agent 自己搬过的，挂在搬去的文件夹（还在时）——Claude Code 看最后一次 `relocated`，Codex 看最近一轮 `turn_context` 的 `cwd`，在命令行里换文件夹续接的也算；否则是它开始时的文件夹，只有那个文件夹已不存在、而后来的记录行在一个还在的文件夹里时，才挂到后来的文件夹。Claude Code 会话里 `cd` 进子目录不算搬家。
  - 尚未用真 agent 端到端试过换文件夹续接（服务、网页、手机的流程有测试，网页在隔离的临时服务上实测过弹框）。
  - 自动记忆和 `~/.claude.json` 里按路径的设置不会跟着搬，这是 Claude Code 自己的数据，服务不动。
- 删除会话记录（2026-09-28 改，用户：终端产生的副本删不掉）：侧栏里的会话行悬停出现 ×，确认后删掉 agent 自己保存的这段记录（Claude Code 的 `<project>/<id>.jsonl`、Codex 的 `rollout-…-<id>.jsonl`、pi 的 `<时间>_<id>.jsonl`；OpenCode 存在自己的数据库里，交给它自己的命令 `opencode session delete --standalone <id>`——连子会话一起删，用私有服务、不碰在跑的后台服务，2.0.18 在临时数据目录里实测：0.13 秒删完，会话和消息都清空，不存在的 id 退出码 1——2026-10-01 加，用户：opencode、pi 都加上删除支持），`DELETE /sessions/:harness/:id`。OpenCode 和 pi 没有会话登记或写入锁可查，这两家仍以“90 秒内刚写过”当作可能正在别处使用，拒绝删除（刚关掉的本机终端除外）。开在还在运行的终端里，或被别的程序持有（Claude 的会话登记、Codex 的写入锁）的会话不能删；刚有活动不算（2026-10-01 改，用户：现在不能彻底删除某个会话了——关掉终端时 Claude Code 退出前还会往记录里写一行，之后 90 秒都算“刚有活动”，网页藏起删除、服务回 409；已结束但还列着的终端也挡着删除，而树里已经把它的会话重新列出来了）。有没有程序在写，看的是会话登记和写入锁，不靠最近的修改时间；只有拿不到这两项检查时（没开终端功能），才退回到“刚有活动不删”。删的是列表读到的那个文件；一个文件都没删到时返回 404，有文件删不掉时返回 500 并说明删了几个，不再笼统回成功。无论终端功能开没开，每次删除都记审计。已知未删：Codex 在对话里派生的子代理记录（带着对话历史的副本，列表里不显示）和 Claude 的 `<project>/<id>/` 子目录（子代理、工具结果）。原来只准删 AgentSwitch 建的记录，但分不清谁建的（旧版“继续”用普通 `--resume`，Claude 另存了一份副本，删除终端时没有算在内），而删除本来就是用户要的管理动作之一。
- “关闭”和“删除会话记录”是两件事：关闭结束进程、从终端列表移除，历史保留（同 iTerm 关标签页，`claude --resume` 里仍在）；删除会话记录是抹掉历史，无法恢复。关闭不默认删历史，需要时在关闭确认里勾选。只有记录是这个终端新建的（新建的会话、分叉）才给这个选项；接着写原会话的终端没有——关一个终端不该把原来的对话删掉，要删在会话列表里删（服务端同样拒绝）。

## 6. 与调度入口的关系

（下文的“托管”即调度入口 Dispatch，dispatch-v0。）

- 两个入口的数据分开：终端不进任务表、不经调度模型、不写战绩和 `MEMORY.md`。
- 托管里的调度模型仍能看到这些会话的目录元数据（control-v0 §3 那一节），作为项目背景。
- 托管的任务不能往终端里写字；手动入口也不会替你建任务。以后若要互通（把一个终端交给托管接手，或把托管任务开成终端），另行设计。

## 7. 安全边界

- 只能启动白名单里的 agent；参数由服务端拼，客户端只给执行器名、目录、模型、续接 id。
- 只有配对设备和本机能访问；手机的每一次回话、按键、权限决定都进审计。
- 加密发送的回话过 sealer；终端输出流不入库，只在内存缓冲里，经 TLS 给自己的设备（同 control-v0 §3 的规则）。
- 会话有 gate 环境与禁区保护（各 agent 的做法与强度见 §3）；手动会话里 agent 的权限模式默认是“逐项问你”。
