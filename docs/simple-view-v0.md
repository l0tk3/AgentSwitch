# simple-view-v0：简略视图——终端的另一种看法，以及调度页的同一套零件

2026-10-07 用户（手机上，看着终端列表里点开会话的那个只读记录页）：然后我发现手机上接管之前的那个预览页面挺好看的，简约，能不能补全该有的其他东西，然后保证功能完整性的前提下出一个简略视图，弄一个 html 给我 review。

同日看过概念稿之后，依次：classic 页面和 mac 上的都要做 · 你的 classic 很多元素还是像素的 · 学习一下 Claude 和 codex 桌面端怎么实现的 · 然后 mac 上切换到这个简略页面可以是白色的，要是变成白色的话目录也跟着变；然后手机和 mac 上都可以在两种风格中切换，电脑上默认是终端原版，手机上默认是简约风格，然后这个改进过的简约风格也应用到路由器页面 · 开做吧。

样子以演示页 `docs/design/concepts/simple-view.html` 为准（一部可点的手机和一个 Mac 窗口，两种外观，终端与调度页各自的状态；页面下方有“终端页有的，这里在哪”的对照表、Claude 与 Codex 桌面端做法的逐项对照）。本文是它背后的规则与分步。

## 0. 要点

- **一个终端，两种看法。** 终端视图是程序自己画的屏幕（terminal-v0）；简略视图是这段会话的**记录**——你的话、回答、一段段工作、它正在做什么——加上终端页已有的回复框、确认卡、提问卡。两个视图看的是同一个会话，随时互换；简略视图**不占终端的窗口大小**（它不要屏幕），所以终端正在另一端用着的时候照样能看、能回复，不需要“接手”。
- **接手前后是同一页。** 终端列表里点开一个以前的会话，是只读的记录加 `Resume`（control-v0 §3，已有）；`Resume` 之后留在这一页，补上回复与卡片；程序结束后回到只读加 `Resume`。
- **默认不同**：Mac 默认终端视图，手机默认简略视图。每个终端记住上次用的那个，两端各记各的。没有会话记录的程序只有终端视图，不显示切换。
- **内容来自各家结构化的记录，不从屏幕上读。** Claude 桌面端与 Codex 桌面端都不读终端画面（§3 末尾）；我们读各家边做边写的会话文件，状态、确认、提问、子代理仍来自 hook（terminal-v0 §3，已有）。
- **程序自己画的界面**（选模型的菜单、登录、没被认成卡片的提问）在简略视图里是一张 Prompt 卡：屏幕最后几行、按键、`Open Terminal`。这一点两家桌面端都没有（它们背后没有终端），是我们多出来的。
- **调度页用同一套零件**：路由器派出去的任务本来就是一个 agent 的一段会话；任务卡片与任务页换成同样的记录零件（§5.3），入口、动作、规则不变。
- **Mac 的简略视图跟随系统深浅**，变白时列表与各条栏一起变；终端视图与分屏里的终端块仍是深色（§5.2）。

## 1. 两种视图

- 切换：手机在导航栏右边一个图标（去终端 / 回简略），`⋯` 里也有一项；Mac 在顶栏右边两格开关，分屏时在那一块的标题栏上，每块各有各的。
- 记住：`terminalView.<终端 id>`（两端各自的本机设置）；没有记过的按默认。终端关闭后记的那一项随之清掉。
- 简略视图打开时**不发尺寸**（`/terminals/:id/resize` 只在终端视图里发），事件流带 `view=record`，服务不推屏幕内容（§4）。回复、按键、确认照旧经终端的接口。
- 终端视图里的一切不变。

## 2. 记录

一段会话的记录是一列**条目**，旧的在上：

| 条目 | 内容 |
|---|---|
| `user` | 你说的话；带的图片数；`queued`：发出时它正忙，还没读到 |
| `answer` | 它的回答，Markdown 全文（不再截到 2000 字；超过 20000 字才截，标 `clipped`）。带 `thinking: true` 的是**它路上想的**（见下） |
| `work` | 两段话之间的一段工作：用时，和一列**步骤** |
| `note` | 一行说明：`Interrupted`、`Compacted` 等 |

**步骤**：`read`（读文件）、`search`（搜索）、`list`（列目录）、`run`（跑命令）、`edit`（改文件，带增删行数）、`write`（新建文件）、`web`（联网）、`agent`（派子代理）、`todo`（更新任务清单）、`tool`（其他工具，写工具名）。每一步一行字（文件、命令、查询），`run` 带输出的末尾（至多 600 字），失败的标出。一步还可以带 `note`：**它自己说这一步是做什么的**（Claude Code 每条命令都带一句 `description`）。命令的全文和全部输出不在记录里，点开那一步时另取（§4）。

**它路上想的**（2026-10-07，用户拿官方桌面端对比：怎么少了思考细节呢）：Claude Code 的会话文件里，思考大多是封存的（只有签名、没有文字），但有一部分写了字——一两句“先看什么、再做什么”，官方桌面端把它当正文排出来。原来这里把它记成工作里的一步 `think`，只取第一行，而且只有 `Verbose` 才显示，所以平时看不到。改成：写了字的思考是一条 `answer`、标 `thinking`，全文；它把前后的工作分成两段（同官方的排法：`Ran 5 commands` / 一段话 / `Ran 3 commands`）。Codex 的推理摘要（`Reasoning` 的 `summary_text`）同样处理。没写字的思考不留痕。不认识 `thinking` 的旧版应用把它当普通回答显示（所以没有另起一种条目——旧版遇到不认识的条目种类会整份记录解不出来）。`think` 这种步骤不再产生。

界面上一段工作折成一行：`Worked 1m 12s · Read 1 · Searched 1 · Ran 2 · Edited 1`，右边是这一段的改动统计 `+14 −2`；点开是每一步。记录的详略有两档（`⋯` 里的 Transcript）：`Normal` 折着；`Verbose` 全部展开。

记录之外，同一个答复里还带：

- **任务清单**（`plan`）：它自己维护的清单的最新一版（Claude Code 的 TodoWrite，Codex 的计划），每项 `done` / `doing` / `todo`。
- **用量**（`usage`）：模型、上下文里现在有多少、窗口多大（知道的时候）。
- **模式**（`mode`）：会话文件里最近一次记下的权限模式，原样（`acceptEdits`、`plan`…）。
- **改动**另取（§4）：某一段工作或最近一轮按文件的 diff。

“正在做什么”的一行、子代理、等你的确认与提问**不在记录里**，来自终端自己的状态（`activity`、`subagents`、`permissions`，已有）。

## 3. 从哪来

| | 记录 | 改动 | 清单 | 用量 |
|---|---|---|---|---|
| Claude Code | `~/.claude/projects/<目录>/<会话>.jsonl`，边做边写：`assistant` 行的 `text` / `tool_use` / `thinking`，`user` 行的 `tool_result` | 结果行的 `toolUseResult.structuredPatch`（Edit、Write 都有） | 最近一次 TodoWrite 的输入 | `assistant` 行的 `message.usage` 与 `message.model` |
| Codex | `~/.codex/sessions/…/rollout-*.jsonl`：`event_msg` 里的 `item_completed`，就是它协议里的条目（UserMessage、AgentMessage 带 `phase`、Reasoning、CommandExecution 带 `parsed_cmd`、FileChange、Extension） | FileChange 的 `changes` | 计划更新 | `token_count` 的用量与 `model_context_window` |
| OpenCode、pi | 第一步沿用现有的粗记录（control-v0 §3：话与一行一个工具），`work` 的步骤只有工具名与一行字 | — | — | — |

- 读法：从文件末尾往回读一个窗口（2 MB，条目不够再放到 8 MB、32 MB——带截图的会话一行就有几百 KB），解析成条目；`before` 游标往前翻（`Earlier`）。本机 275 MB 的会话文件读最后 60 条用 60 毫秒。子代理的行（`isSidechain`）不进记录。忙时打的话：Claude Code 记成排队操作，读到后写成一条附件而不是用户行，两种都认。
- **没有逐字输出**：一条消息写完才出现在文件里。回答出现前，界面靠“正在做什么”的一行说明它在动。
- 两家桌面端的做法（2026-10-07 查，见演示页下方的逐项对照）：Claude 桌面端跑同一个引擎、收结构化的消息流，和终端之间是交接（`/desktop`、`/resume`），同一会话同一时间只在一处跑；Codex 桌面端是 `codex app-server` 的客户端。Codex 那条路（我们的服务也作为客户端连它的后台服务）内容更全、有逐字输出，但“终端开着的同时第二个客户端能看、能答确认”没有文档，更新日志还说别处打开的会话在终端里是锁住的——**先不走，等实测**（§8）。

## 4. 接口

都在已有的会话与终端接口旁边，手机与 Mac 共用，远程可用。

- `GET /sessions/:harness/:id/record?limit=&before=` → `{session, items, more, cursor, rev, plan, usage, mode}`。`limit` 是条目数（默认 60，至多 200）；`before` 取上一页的 `cursor`（往前翻的那一页只有记录，清单、用量、模式只跟最新的一页）。条目的 `id` 是它第一行在文件里的位置（文件只增不改），所以翻页不重不漏，一段工作也凭它再找到。带 `If-None-Match` 时没变回 304。
- `GET /sessions/:harness/:id/changes?work=<条目 id>` → `{files: [{path, added, removed, hunks: [{header, lines}]}]}`；不带 `work` 是最近一轮（最后一句你的话之后）的全部改动。每个文件至多 400 行，超过的标 `clipped`。
- `GET /terminals/:id/stream?view=record`：同一条事件流，不带屏幕（没有 `snapshot` / `output`），不带 `screen`（不画终端，所以不占尺寸），多两种事件：`activity`（`{activity, subagents}`：它正在用的工具和子代理变了；连上时先发一次当前的）和 `record`（`{rev}`：这个终端的会话文件变了，每 300 毫秒看一次；终端刚启动、agent 还没报会话号时每 2 秒找一次文件）。界面收到 `record` 就取一次记录。普通的终端流里没有这两种事件（旧版应用不认识）。OpenCode 的会话都在一个数据库里，看不出某一个变没变：没有 `record` 事件，界面自己隔几秒取一次。
- `GET /sessions/:harness/:id/steps/:item/:n` → `{kind, text, note?, out?, failed?, clipped?}`：某一段工作（`item` 是它的 `id`）的第 `n` 步，**完整的**——命令照原样（保留换行），输出全部。各至多 20000 字，超过时命令留开头、输出留末尾，标 `clipped`。只有 Claude Code 与 Codex；别的 agent、旧版服务 404，界面就停在记录里的那一行。实测本机 308 MB 的会话取一步不到 1 毫秒。
- `GET /sessions/:harness/:id/steps/:item/:n/images/:k` → 某一步带回来的第 `k` 张图片（2026-10-07，用户：这种readpng能不能展开后看到真的png内容呢）。记录里这一步多一项 `images`（几张），上面“完整的一步”也带它。Claude Code 把工具结果里的图片存在结果那一行（`tool_result` 的 `content` 里 `type: image`，base64），按这一步对应的结果行原样取出；Codex 的看图（`ImageView`）只记了文件路径，文件还在、扩展名是图片才读。图片存在哪一行只在服务里用，不进记录。类型白名单、12 MB 上限、`nosniff`、不变缓存都和下面“你发的图片”一样。在这次会话的真实文件上核对过形状与用时：105 步里 14 步带图（读图片文件、浏览器截图），取一张 4–9 毫秒。
- `GET /terminals/:id/files?q=` → `{files: [路径…]}`：回复里 `@` 的候选（§5.5）。文件夹是这个终端自己的（工作目录），调用方不能指定；是 git 仓库时用 `git ls-files`（已跟踪加未跟踪、不含被忽略的），否则有界地走一遍目录（跳过点开头的目录、`node_modules`、`build` 等，至多 8 层、4 万个文件）；每个文件夹 15 秒内只读一次。按名字匹配：文件名以它开头的在前，其次文件名包含，再次路径包含，各自短路径在前；至多 12 条。只回路径，不回内容。
- 终端的 `activity` 多一项 `note`：它自己说现在这一步是做什么的（PreToolUse 的 `tool_input.description`，一行，至多 200 字）。界面上“正在做什么”的一行有它就写它，没有才写命令。
- `GET /sessions/:harness/:id/images/:item/:n` → 你随一句话发的第 `n` 张图片（`item` 是那一条的 `id`，`n` 从 0 起，按它在那句话里的先后）。Claude Code 把图片存在会话文件的那一行里（base64），原样取出；Codex 只记了文件在哪（`local_image`），文件还在、扩展名是图片才读。只给 PNG、JPEG、GIF、WebP、HEIC（记录里写成 SVG 之类浏览器会执行的类型一律不给），单张至多 12 MB，带 `nosniff`；条目的位置不会变，所以回 `immutable`，界面各取一次。没有这张图、读得粗的 agent、旧版服务：404，界面在原位留一个写着 `Image` 的空框。实测本机 302 MB 的会话取一张图 6–23 毫秒。
- 回复 `POST /terminals/:id/input`、按键 `/keys`、附件 `/attach`、确认与提问 `/permissions/:pid`、命令 `/commands`：不变。回复的 `attachments` 多一种写法：`{token, path}`——文件已经在这台 Mac 上，不搬不拷，占位符处直接输入它的路径（terminal-v0 §4）；只有本机的画面能用，手机仍是先上传（`{token, upload}`）。
- 确认卡的两个新答法（§5.1）：`decision: "allow", always: true`（记成规则）与 `decision: "deny", message`（不同意，并告诉它换个做法）——**要先核实各家 hook 收不收**（§8）。

## 5. 界面

以演示页为准，这里只记规则。两种外观都做；Classic 按 ui-v0 §8：界面文字系统字体（等宽只留给代码、命令、路径和 Prompt 卡里的屏幕）、线性图标、圆点与系统转圈、圆角卡片与标准按钮。

### 5.1 一个终端的简略视图（两端）

- 自上而下：标题与一行说明（agent · 模型 · 分支 · 时间；目录）· `Earlier` · 记录 · “正在做什么”的一行（工具、对象、已用时间；子代理另起一行）· 等你的卡片。
- 底部：任务清单一行 `Tasks 2/4`（点开是清单）· 回复框（终端页的同一个：`+` 附件、`/` 命令、锁、像密码时先问）· 一行模式、模型、上下文用量。
- **它路上想的**排成一段话，比回答淡一些。
- **一步**：有 `note` 的命令，行上写的是那句话（`Run  Run the Agents tests and keep the last lines`），下面一行淡字是命令本身；没有 `note` 的照旧写命令和输出的末尾。命令这一步可以点开（2026-10-07，用户：官方的代码执行块里看没有省略而且有高亮显示）：一个代码块里是**完整的命令**——不截断、保留换行、过宽处折行——每条命令开头的词、引号里的内容（连同 here-document 的正文）、注释各用一种颜色（信号色、绿、淡），旁边 `Copy`；下面是全部输出。上色只认到这个程度（`ShellHighlight`，不做展开、不进引号里面），认不出的原样显示，不丢字。
- “正在做什么”的一行：有 `note` 时写 `Run  Build the release app  0:42`，不再是一长串命令。
- **小图标与流光**（2026-10-07，用户贴 Codex 桌面端的步骤列表：这种小图标和思考过程中的闪烁能不能加上）：
  - 经典外观里每一步的行首多一个小图标，一种步骤一个：读文件是一页纸、搜索是放大镜、列目录是文件夹、跑命令是终端、改文件是铅笔、新建文件是带加号的纸、联网是地球、子代理是分叉、任务清单是清单、其他工具是扳手（系统的符号，`RecordDisplay.symbol`，两端各一份，有测试保证不重样）。图标后面的词照旧。**像素外观不加**：它的词（`Read` `Run`…）本身就是标记。
  - **有流光就不要转圈**（同日，用户：加载图标实际上转圈圈可以去掉了，有流光特效的话）：“正在做什么”那一行和它下面每个子代理的一行，原来行首各有一个转圈；流光已经说明“还在进行”，转圈去掉。经典外观行首换成这一步的小图标（跑命令是终端、读文件是一页纸……没在用工具、在想的时候是“思考”那个；子代理是分叉），像素外观只剩字。子代理的行也带流光。
  - 还在进行的字上有一道流光：“正在做什么”的那一行，和还没结束的那段工作的一行（`Working 1m 12s · …`）。字本身是次一级的灰，一道正文色的光带从左扫到右，约 1.9 秒一遍；经典外观的光带是柔和的，像素外观是一小块、一格一格地走。结束了就停。系统开了“减弱动态效果”时不动。
- 你的话带了图片时，图片缩成小图排在那句话下面（高 84 点 / 手机 96 点，宽按比例、有上下限；多于几张只排前几张，后面写 `+n`）。点一张看整张：Mac 上一页（`←` `→` 换张、`⌘C` 拷贝），手机上用系统的预览（可放大、可分享）。只有你发的图片；工具读到或截到的图片不进记录。
- 忙且回复框为空时发送键是停止（发 `esc`）；打了字发出去，那条消息标 `Queued`，它读到后才算数。
- 确认卡 `Deny` / `Allow`，下面一行 `Always Allow <规则>`；卡片在的时候直接回复等于“不同意，并告诉它换个做法”。提问卡同终端页。答完收成记录里的一行。
- 手机的按键条平时收起（`+` 的最后一项取出），程序等按键而又没有卡片时自己出来，连同 Prompt 卡。Mac 没有按键条：`↩` 发送、`⇧↩` 换行、忙时 `esc` 打断；Prompt 卡在的时候键盘给程序；确认卡 `⌘↩` / `⌘⌫`。
- 链接点开与长按 / 右键菜单、代码块 `Copy`、过长消息 `Show More`、往回翻时 `↓ Latest`。

### 5.6 它猜你的下一句

2026-10-07 用户：有的时候cli会进行回复预测，这个也做出来，按tap补全。

- **它是什么、在哪**。Claude Code 一轮结束后有时会猜你下一句要说什么（prompt suggestion），用暗色字写在自己空着的输入行里；在终端里按 `tab` 填入、`↩` 直接发出。它**只在屏幕上**：会话文件里没有，hook 里也没有（程序里是内存中的一个状态 `promptSuggestion`）。所以只能从屏幕读。
- **先看了真的**。`packages/daemon/scripts/claude_suggestion_probe.ts`（打真模型的脚本，不进测试）在仓库里一个被 git 忽略的临时目录中起真的 `claude`（Haiku），问两句小话，等它歇下来，把屏幕最后几行连同“哪些字是暗色的”打出来。2026-10-07 在 2.1.292 上看到的：输入行是 `❯`、一个空格，后面整段暗色——`❯ ⟦add both⟧`。从程序里读到、并在实测中印证的几条：**第二次回答之前不给**（`early_conversation`；只问一句时三次都没有，问两句后每次都有）；这个账户上不用强制开关也有；先告诉它“终端失去焦点”再打字，照样给（往里打字就算有焦点），所以回复时不需要另外做什么。顺带看到每步都问的模式在它脚注里写的是 `manual mode on`（原来只认 `? for shortcuts`），已补进 §5.4 的读法。
- **怎么读**（`suggestionOnScreen`）：屏幕最后十行里最靠下的、以 `❯` 加空格开头的那一行是输入行；它后面有字、而且每个字都是暗色，就是它猜的话。你自己在终端里打的字不是暗色，不会被当成预测；开场时的示例（`Try "…"`）不算；超过 300 字不算。只在它**空闲**时读（屏幕静止 0.2 秒后），一开始工作立刻清掉。只读 Claude Code 的屏幕。
- **接口**：终端多一个字段 `suggestion`（没有就是 `null`），事件流多一种事件 `suggestion {text}`（两种流都有）。
- **Mac**：回复框空着、它空闲、有预测时，框里的占位字就是这句话，后面跟 `· tab`；按 `tab` 把它写进回复框（是你的字了，可以改，`↩` 才发）；一打字它就让开。发出一条回复后清掉（那是上一句的预测）。
- **手机**：回复框上方一行，右边 `Use`，点一下填入并调出键盘。
- **没做**：`↩` 直接发出预测（空框回车现在什么都不做，怕误发）；其他 agent（Codex 等）没有这个功能或没看过它们的屏幕。
- 验证：服务的测试（按真实屏幕的样子造的行：暗色的算、打了字的不算、示例不算、取最靠下的输入行；假 agent 画出同样的输入行——出现、被打字取代、再出现、开始工作时清掉、工作中不读、别的 agent 不读）；上面那个脚本的最后一行是服务自己的读法对着真屏幕读出的结果（`suggestion "add both" · mode default`）；Mac 连临时服务的实测（空框里写着 `run the tests again  ·  tab`，从窗口送一个 `tab` 后回复框里是这句话，它开始工作后占位字变回 `Reply · esc to Stop`）；手机模拟器里演示数据的那一行。**没验证**：装好的应用连着你真的会话时的样子——读法对真屏幕核对过，但“应用 → 服务 → 真的 Claude Code”这一整条没有连起来跑过。

## 6. 安全

- 记录是 agent 自己写下的会话，原来就经 `/sessions/:harness/:id` 给到已配对的手机；新接口是同一份内容的更细的读法，同一道门（远程只给已配对的设备，路由表里登记）。
- 多出来的是：回答全文、命令输出的末尾、改动的 diff。输出只取末尾 600 字；diff 每个文件至多 400 行。
- 记录里出现的密文（`enc:v1:…`、`enc:ref:…`）原样显示，它们本来就是给人看的形式；我们不往记录里写任何东西。
- 图片接口给出的是你自己发给 agent 的图片，同一道门。Codex 的记录里只有路径：只读扩展名是图片的文件，记录里写别的路径（比如私钥）读不出东西；类型只在白名单里选，SVG 不给（它在服务自己的网页同源下打开会执行脚本）。
- 回复里按路径带文件（`path`）只有本机的画面能用，远程调用一律 403：手机不能让 Mac 把它指的某个文件交给 agent。路径里不许有控制字符（混不进换行或粘贴结束符），必须是绝对路径且确实存在。本机画面本来就能往终端里输入任何字，这一条没有多给它什么。附件和在终端里拖文件一样**不过 sealer**：文件内容原样给 agent。
- 服务**只读**会话文件，不改、不删（删除仍是 terminal-v0 §5 的那一条路）。
- 测试用写在临时目录里的假会话文件，不读真实的 `~/.claude`、`~/.codex`。
