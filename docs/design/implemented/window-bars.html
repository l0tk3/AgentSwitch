已定：提议 B（2026-10-03，用户：排版按照提议B来；dispatch-v0 §1），应用照此实现。同一个窗口的三页（Dispatch · Terminals · Browser），“现在”是改之前的样子，提议 A 留作对照：两个提议都把各页自己的底部条换成横跨整个窗口的一条状态栏，Encrypt & Send 成为其中的一个图标，区别在三页怎么切换。“标出变化”用青色虚线框标出相对改之前挪动或新加的东西。依据在窗口下面。

// 查到的规范

  • Apple HIG · Windows：macOS 窗口的框架在内容上方，含窗口按钮和工具栏，“In rare cases, a window can also display a bottom bar”。底栏的建议：“Avoid putting critical information or actions in a bottom bar, because people often relocate a window in a way that hides its bottom edge. If you must include one, use it only to display a small amount of information directly related to a window's contents or to a selected item within it.” 例子是访达的状态栏（项目数、选中数、剩余空间）；信息多就用检查器。
  • Apple HIG · Toolbars：三段。前缘是返回、显示 / 隐藏侧栏和视图标题，“To ensure that these items are always available, items on the toolbar's leading edge aren't customizable.” 中间是常用控件，窗口变窄时收进溢出菜单；后缘是要一直可见的项目、检查器按钮、搜索和主操作。“Make every toolbar item available as a command in the menu bar.” macOS 26 的玻璃材质：少用工具栏背景和着色控件，默认单色。
  • Apple HIG · Segmented controls：“Consider using a segmented control to help people switch views in a toolbar or inspector pane.” 段数宽界面不超过五到七个；主窗口内容区里切换视图用标签视图。
  • Apple HIG · Sidebars / SwiftUI：侧栏用于去往应用的主要区域；“Avoid putting critical information or actions at the bottom of a sidebar.” SwiftUI 的 TabView 用 sidebarAdaptable 样式时 “On macOS … always shows a sidebar”：系统给的“顶层分区”在 Mac 上就是侧栏，没有 iPad 那种顶部标签栏。
  • Mario Guzmán（Michael Tsai 转述）：侧栏按钮 “Don't make the Sidebar toggle button a moving target … Keep it left-aligned, ‘pinned’ to the window control buttons.” 另一条：Big Sur 以后工具栏太挤，“Bottom Bars are needed now more than ever”。
  • VS Code UX Guidelines：左边的活动栏切换侧栏里的内容，标题栏和状态栏始终不变；状态栏横跨整个窗口，左边放和整个工作区有关的（状态、问题、同步），右边放和当前文件有关的（语言、缩进）；短文字，图标只用于明确的比喻，不加自定义颜色，项目越少越好，警告和错误底色只作最后手段。

// 对照现在

现在规范怎么说提议
侧栏按钮只在 Terminals 页出现，位置在三个页名之后侧栏按钮固定在前缘、紧挨窗口按钮，不要会动的目标A：固定在窗口按钮后，没有列表的页上变灰占位；B：同样固定，页名移到左侧图标栏
顶栏后端混着全局状态（各处的忙 / 等你、Gateway Down、应用标记）和本页操作（+），三页各不相同工具栏放当前视图的操作；全局的、给人看的信息少量放底栏（访达），或照 VS Code 放状态栏左边全局状态挪到状态栏左边，三页一样；顶栏后端只剩本页的操作，主操作（新建）固定在最右
三个页名写在顶栏里，像一组分段控件用分段控件在工具栏里切换视图是规范的（如活动监视器）；而“应用的几个大区域”在 Mac 上惯用侧栏A：保留，只规范其余部分；B：改成左侧图标栏（VS Code 的活动栏、Xcode 导航器顶部的图标），顶栏完全属于当前页
各页自己的底部条：终端下面的 Encrypt & Send，浏览器页下面的持有者与 Take Over底栏只放少量和窗口内容相关的信息，关键操作不要只放在底栏合成一条横跨窗口的状态栏；Encrypt & Send 是右边的一个锁图标，Take Over 是一个短词，二者同时留在菜单栏（并保留 ⌘⇧V 等快捷键）
