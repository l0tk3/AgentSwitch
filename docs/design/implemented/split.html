已定并实现（2026-10-03，用户：可以的，分屏很好，直接实现吧；terminal-v0 §1 分屏）。Mac 主窗口的 Terminals 页（按已定的提议 B 画），右边的终端区可以分成几块。都能直接操作：拖分屏之间的分隔线；把左侧的终端或会话拖到某一块的中间（在那里打开）或四边（在那边分出新的一块）；点左侧一行，在当前一块（顶上粉色细线）打开，⌘ 点一下在右边新分一块；⌘D 向右分、⌘⇧D 向下分，⌘⌥ 方向键换块，⌘⇧↩ 放大或还原当前一块。

// 怎么用

  • 在哪：Mac 窗口的 Terminals 页。网页控制台暂时仍一次一个终端（留到下一步）；手机屏幕小，仍一次一个终端。
  • 打开：把左侧的终端或会话拖到某一块上——拖到中间在那里打开，拖到四边就在那一边分出新的一块；也可以点选：点一行，在当前一块打开（和现在点一行换屏幕上的终端一样），⌘ 点一下在右边新分一块。会话（没在运行的）放进来即“继续”。顶栏多两个按钮：向右分屏 ⌘D、向下分屏 ⌘⇧D，新的一块是空的，等你放终端进去。
  • 调整：块与块之间的分隔线可以拖，拖动时每块中间显示新的列数 × 行数，松手 0.3 秒后终端按新尺寸重排（拖动途中不发，免得 agent 一直重画）；双击分隔线两边等分。每块最小约 40 列 × 8 行，最多 4 块。
  • 焦点：点进哪块，键盘就给哪块，那一块标题栏顶上一条粉色细线；⌘⌥←→↑↓ 在块之间移动；⌘⇧↩ 把当前一块放大到整个区域，再按一次还原。顶栏的标题、状态栏右边（agent、模式、尺寸、锁）都跟着当前一块；加密发送发给当前一块的终端。
  • 关闭：每块标题栏的 × 只关这一块，终端照常在左侧列表里运行；结束终端仍用原来的方式（右键菜单的 Close、⌘W）。
  • 一个终端只在一块里：点一个已在别处显示的终端，切到那一块；拖它则从原处挪过来（原处那块随之关掉）。左侧列表里正在显示的终端后面标着它在第几块（当前一块是粉色）。
  • 尺寸有主照旧：每块各自持有所显示终端的尺寸；手机打开其中一个终端时，那一块显示 On iPhone 的占位，点 [ Take Over ] 拿回来（演示里第 4 块）。
  • 记住：布局和每块里的会话记在本机；服务重启（换版）后终端都没了，各块留着原来的会话，点一下继续。

// 怎么实现（服务端不用改）

  • 网页（terminal.js）管布局：一棵二分树，每个节点左右或上下分、记一个比例；拖放、分隔线、焦点、快捷键都在这里，布局的增删改单独成一个纯逻辑模块并写测试。页面把每一块的位置报给 Mac 窗口（现在只报一块）。
  • Mac 窗口按块数建原生终端屏幕（SwiftTerm），每块一条画面流、一个自己的屏幕 id：服务端看来只是多了几块屏幕，“尺寸有主”不用改。浮在画面上的东西（权限卡、加密框、占位）照旧按位置报给窗口。
  • 网页控制台以后用同一套布局，每块一个 xterm（这一步没做）。手机不变。

// 当时待定的（已按建议做：最多 4 块、× 只关分屏、只记最后一次；“同时发给几块”没做）

  1. 最多几块：建议 4（1280 宽的窗口去掉列表后，4 块各约 80 列）。
  2. 关掉一块时是否顺便结束终端：建议不结束，× 只关分屏。
  3. 要不要“同时发给几块”：在加密发送框里勾选要发的几块，一次发给几个 agent。不做按键同步（tmux 的 synchronize-panes）：几个 Claude Code 同时弹出权限选择题时会被同一个按键误答。
  4. 布局只记最后一次，还是可以存几个命名布局：建议先只记最后一次。

// 依据

  • iTerm2：⌘D 左右分、⌘⇧D 上下分，⌘⌥ 方向键在分屏间移动，⌘⇧↩ 放大当前分屏；分隔线可拖。
  • Warp：⌘D 向右分、⌘⇧D 向下分。
  • VS Code：把编辑器拖到某一组的四边就在那边分出新组，拖到中间放进该组；⌘\ 分组。
  • tmux：分屏同样是二分树，可以把一块放大（zoom）再还原。
