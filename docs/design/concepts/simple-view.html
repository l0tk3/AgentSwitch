终端的简略视图，iPhone 与 Mac 两端，Pixel 与 Classic 两种外观；同一套画法也用到调度页（Dispatch）的任务上。接手前那个只读的记录页不变，按下 Resume 之后不换到终端的屏幕，而是留在同一页上，把回复、确认、提问、按键这些补进来。终端页能做的事这里都能做；程序自己画的界面随时切回终端。概念稿，2026-10-07。

// 比接手前的记录页多了什么

  • 回复：终端页的同一个输入框——+ 附件、/ 命令、锁（加密发送）、像密码时先问；下面一行是模式、模型和上下文用量。
  • 一段工作：折成一行摘要（用了多久、读了几个、跑了几条、改了几个），点开看每一步；改动的统计点开是按文件的 diff；输入框上面是任务清单。
  • 需要你时：确认卡和提问卡排在记录的末尾，答完收成一行，留在记录里。
  • 正在做什么：末尾一行写当前的工具与已用时间，子代理另起一行；忙的时候发送键变成 ■，按下打断。
  • 程序自己的界面（选模型的菜单、登录、任何没被认成卡片的提问）：一张 Prompt 卡，画出屏幕最后几行，按键条自己出来，旁边 Open Terminal。
  • 其余：Earlier 取更早的记录，过长的消息 Show More，往回翻时 ↓ Latest，代码块 Copy，链接点开与长按菜单，⋯ 里改名、关闭与换视图。

// 调度页（DISPATCH）也用这一套

调度页上路由器派出去的任务，本来就是一个 agent 的一段会话。任务卡片和任务页换成和简略视图同一套零件，原来的入口、动作和规则不变。

现在换成
卡片上的进度块 ▮▮▮▯▯ 3/5 和 └─ 当前一步Tasks 2/5（点开是清单）和“正在做什么”的一行：工具、命令、已用时间
任务页的 // Process：工具调用一次一行一段工作一行摘要 Worked 1m 14s · Read 1 · Ran 1 · Edited 1，点开看每一步；Transcript 切到 Verbose 全部展开

审批卡 [ Deny ] [ Allow ]同一张确认卡，多一行 Always Allow（记成规则）

动作 [ Cancel ] [ Hand to ▾ ] [ Retry ] [ Delete ]、评分不变，Classic 下是标准按钮
调度页的输入框（+：附件、密文、Pin Model）不变

这一页比终端那边好做：派出去的任务本来就是经结构化的接口跑的（Claude 的消息流、Codex 的 app-server、OpenCode 的服务接口），每一步、改动、计划现在就有，不需要 hook 和会话文件。

  • 在一块分屏里。记录排成中间一栏（最宽 700 点），输入框在这一块的底部、同样宽。分屏时每一块各有各的视图，块的标题栏右边切换；只有一块时切换在窗口顶栏的右边。

// 从 CLAUDE 与 CODEX 桌面端学到的

怎么驱动 agent

CLAUDE桌面端跑的是同一个引擎，不开终端界面，收的是结构化的消息流：开头一条说明模型与可用工具，之后是一条条完整的回答、工具结果和收尾的用量；子代理的消息带上级调用的编号。确认不靠终端里的对话框，由回调来答；权限模式可以中途换。

CODEX桌面端是 codex app-server 的一个客户端。对象分三层：会话、轮次、条目。条目有十九种，一个界面要画的主要是：你的话、回答、思考、计划、命令执行、文件改动、MCP 调用、搜索、子代理活动、上下文压缩。进行中有逐字的增量；确认和提问是服务端主动发来、等客户端答复的请求。

这一稿两家都不是从终端画面里读内容的。我们也不该只靠每 10 秒取一次记录：按 agent 接各自结构化的来源，见下面“怎么实现”。

终端和图形界面能不能同时看同一个会话

CLAUDE不能。/desktop 是把会话交给桌面端并退出终端；在桌面端 /resume 一个终端会话，第一步是先把终端里的关掉。同一时间只有一端在跑。能把正在跑的终端会话镜像出去的是 Remote Control，只到它自己的网页和手机端，不对第三方开放。

CODEX能看，能不能两处同时操作没有文档。它有一个本机的后台服务，桌面端是它的客户端；终端界面也可以连它（--remote，0.157 起符合条件的终端会话会自动启动并连上，加 --no-daemon 才不连）。第二个客户端接上一个正在跑的会话时，会拿到历史并从那一刻起收到更新。但更新日志里写明：在别的应用里打开着的会话，在终端里是锁住的，只能另开分支；确认请求发给哪一个客户端也没有写。这台 Mac 上这个服务现在没有在运行。

这一稿两个视图同时活着、随时互换，正是简略视图的前提，而两家自己都没有把这件事当成常规用法。所以不能指望照搬：Codex 那条路要先实测“终端开着的同时，另一个客户端能不能看、能不能答确认”；Claude Code 没有这样的通道，只能用 hook 加会话文件，细节少一档。

一段工作怎么显示

CLAUDE记录有三档：Normal 把工具调用折成摘要、回答给全文；Thinking 再加上思考；Verbose 把每一步都列出来。

CODEX文档里的样子是回答上面一行折起来的 Worked for 2m 30s ›，改动写成 Edited retry.ts +2 −2。服务端把命令解析成读文件、列目录、搜索这几类，界面可以说“读了哪个文件”而不是贴一条命令；回答分成过程中的话和最终回答。聊天里显示多少命令输出是一项设置。

这一稿原来只列工具名（Read ×2 · Bash）。现在一段工作是一行 Worked 1m 12s · Read 1 · Searched 1 · Ran 2 · Edited 1，点开是每一步做了什么；⋯ 里的 Transcript 在 Normal 与 Verbose 之间切，Verbose 全部展开并显示思考。

改了什么

CLAUDE改动之后出现一个 +12 -1 的统计，点开是左边文件列表、右边改动的 diff 视图，可以在行上留评论。

CODEX文件改动这一条带着每个文件的 diff，另有整轮改动的更新通知。桌面端有一块审阅面板（未暂存、已暂存、提交、分支、上一轮），可以在行上留评论，按文件或按块暂存、撤回。

这一稿新加：摘要行右边的 +14 −2，点开按文件看 diff。行上评论这一稿不做。

确认与提问

CLAUDEManual 模式下逐项确认，看得到 diff，逐个接受或拒绝。

CODEX对一条命令的答复有六种：这一次同意、这个会话里都同意、同意并记成规则（以后同类不再问）、放行一条网络规则、拒绝、取消整轮。提问的每个问题带标题、选项与说明、是否可自由填写、是否是保密内容。

CODEX（手机端的确认卡）四个选择：Approve、Always approve、Tell Codex what to do、Deny。Claude Code 在终端里的第三个选项也是“不同意，并告诉它换个做法”。

这一稿确认卡新加一行 Always Allow git push（记成规则）；卡片在的时候直接在下面回复，就是“不同意，并告诉它换个做法”（在 Permission 状态下发一句试试）。提问卡不变；标了保密的问题走加密发送。

它忙的时候再发话

CLAUDE停止键立刻打断；打字回车则不打断，等当前动作做完它才读到并调整。

CODEX协议里分开三件事：运行中插话、打断、排队。桌面端里接着发的话是插话还是排队由一项设置定；排着队的话停在输入框上面，可以改、调顺序、立刻发或删掉。

这一稿忙且输入框为空时发送键是停止；打了字发出去，那条消息先标 Queued，旁边可以 Cancel，它读到后才算数（在 Busy 状态下发一条试试）。排队的话不做改写和调顺序。

模式、模型、上下文、计划

CLAUDE权限模式的选择就在发送键旁边（Manual、Accept edits、Plan、Auto、Bypass permissions），按文件夹记住；计划、任务、子代理各有一块面板，后台任务面板列出子代理和后台命令。

CODEX权限的选择在输入框下面（Ask for approval、Approve for me、Full access），旁边是在哪里干活（这台电脑或云端）。计划是一组带状态的步骤（未开始、进行中、完成），随轮次更新；用量通知里带上下文窗口的大小。子代理各有自己的会话，从主会话里的活动点进去。

这一稿新加：输入框上面一行 Tasks 2/4，点开是清单；输入框下面一行是模式、模型和上下文用量，模式与模型点开可换。

只有终端里才有的界面

CLAUDE会在终端里打开面板的命令，在桌面端直接不可用（比如 /permissions 只回一句“这个环境里不可用”）。

这一稿我们背后一直有真的终端，所以能给一张 Prompt 卡并一键切回去。这一点比它完整，保留。

依据：Claude Code 桌面端文档（code.claude.com/docs/en/desktop）与无界面运行文档；Codex 的协议取自这台 Mac 上 codex 0.160.1 自己导出的定义（codex app-server generate-ts）和它的命令行帮助，界面与更新日志取自它的文档（learn.chatgpt.com/docs/app-server 及同站的 prompting、code-review、mobile、changelog 各页）。Codex 桌面端里确认按钮的文字、计划与思考的画法，文档没有写。

// 怎么实现

  • Codex：连它自己的后台服务。我们的服务作为又一个客户端连上去，订阅这个终端所在的会话：逐条的记录、逐字增量、确认、提问、计划、改动、用量都是现成的；回复、插话、打断各有对应的请求。终端界面照常开着，两边看到的是同一个会话。要先实测四件事：这个后台服务在这台 Mac 上现在没在运行，要弄清由谁启动、能不能由我们连；我们启动的 Codex 终端连的确实是它；终端开着的同时第二个客户端能看到更新、能答确认，而不是被锁在外面（文档没有写，更新日志说别处打开的会话在终端里是锁住的）；这套协议标着 experimental，版本升级可能变。实测不通的话，Codex 也退回 hook 加会话文件，和 Claude Code 一样。
  • Claude Code：hook 加会话文件。它没有对第三方开放的实时通道。终端继续跑；状态、当前工具、确认、提问、子代理我们已经从 hook 拿到；记录改成盯着它的会话文件（边做边写），不再每 10 秒取一次，也不再把每条消息截到 2000 字。代价是没有逐字输出，一条消息写完才出现；改动要从 Edit 的输入里还原。
  • Claude Code 的另一条路：像它的桌面端那样。不开终端，直接收它的消息流，逐字输出和改动都有；切到终端视图时做一次交接（一边停、另一边按会话编号接上）。细节全，但两个视图不能同时活着，切换有一两秒。建议先走上一条，这条留作以后。
  • OpenCode 与 pi。OpenCode 的终端已经是经它的服务接口接的，记录与确认可以直接取；pi 经它的扩展事件。
  • Prompt 卡要服务给出屏幕最后几行的文字。终端页已有整屏画面，这里只取尾部。
  • 模式与模型的切换。Codex 有对应的请求；Claude Code 在终端里是按键轮换模式，要靠 hook 报的当前模式来对齐，换模型是发 /model。这两项的可靠性要实测。
