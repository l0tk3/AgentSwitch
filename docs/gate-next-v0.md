# 凭据层下一步 v0：授权操作中的隐私保护

补充 `design-v0.md` §3.9、`router-v0.md` §9。创建于 2026-09-23，2026-09-24 根据隔离试验修订，同日接入生产 gate 与 daemon（验证见 §8）。本文记录设计要求和已实现的行为；每个入口的规则、失败行为和守护测试见 `packages/secret-gate/BOUNDARY.md`。

**用途与授权边界。** 在用户有权管理的账号、系统和数据范围内，为已授权的业务操作减少凭据及个人信息暴露。任务应明确业务目的、数据来源、必要字段、目标系统及允许的操作。授权依据来自用户任务和用户维护的可信上下文，并受目标系统权限及原凭据策略共同约束；仅出现站点名称、能够打开页面或声明“内部平台”，均不能单独构成数据传递授权。

**设计原则。**

- 最小权限：仅读取和处理完成任务必需的字段；来源读取与目标写入分别校验。缺少必要范围时，通过现有反馈流程补充信息，执行者不得自行扩大范围。
- 最小暴露：原值只在完成授权操作所必需的受控组件内处理；模型工具输出使用脱敏状态或受限引用。密文与引用仍按受控凭据管理，加密不改变原有业务权限。
- 可审计：保留必要的任务、授权依据、操作目标、允许或拒绝的结果及原因；对敏感字段值脱敏。明文临时产物按保留策略清理，操作审计记录仍须保留。
- 如实反馈：权限拒绝、字段不匹配、未知状态和失败原因保留在反馈链路中。隐私保护不改变模型或平台的安全判定，也不用于隐瞒实际操作目的。

以上是实施要求，不代表已完成合规认证或所有生产控制。

## 1. 任务范围内的短引用：`enc:ref:<id>`

**目的。** 减少长密文在工具调用中的复制错误，同时保留原密文封装的 host、用途和凭据类型限制。

**实现。**

- 形式 `enc:ref:` 加 16 个 base64url 字符（96 位随机），与显示用的 label 无关。同一范围内同一密文得到同一引用；不同任务里的同名 label 各有各的引用，互不解析。
- 执行范围：daemon 每次 `executor.run` 生成一个（`randomBytes(24)`），只经 stdin（`secret-gate refs register|release`）和进程环境、配置文件传递，不进 argv、日志、事件或提示词。Claude 执行器的 MCP 配置写进本次运行私有目录里的 0600 文件，只把路径交给 CLI（Agent SDK 原本会把带 env 的 MCP 配置整段放进 argv）；事件、结果、审批和提问文本里出现的范围（含 `Proxy-Authorization` 的 base64 形式）一律换成 `[scope]`。gate MCP 与浏览器 gate 拿 `SECRET_GATE_SCOPE`；三家 harness 的 shell 代理地址写成 `http://scope:<scope>@127.0.0.1:8080`，代理从 `Proxy-Authorization` 读出范围（HTTPS 记在 CONNECT 所在的连接上）后删掉该头再转发。用户注册表里的其他 MCP server 用不带范围的代理地址。
- 注册表 `$SECRET_GATE_HOME/refs.sqlite3`（0600）只存密文、label 和范围的 sha256。代理、MCP、CLI 是不同进程，每次调用各自打开，登记之后立即可用，代理不需要重载。
- 解析：代理、`secret_http`、`secret_exec`、`secret_otp`、`secret_describe`、`secret_fill`（及带引用的 `browser_type` / `browser_fill_form`）、`secret_repair` 都先按范围查出密文，再照原密文的 host、端口、用途校验；`enc:v1:` 照旧可用。`secret_describe` 对引用返回引用、label、类型、hosts、uses，不返回值和密文。没有范围、别的任务的引用、已释放或过期的引用一律拒绝（代理返回 403 `X-Secret-Gate: denied`）。
- daemon（`src/executors/gateRefs.ts`，包在凭据修复通道里面）：执行前登记已知密文，把 task、brief、交接说明、CONTEXT、平台记忆、反馈，以及执行中用户答复里新出现的 `enc:v1:` 换成引用；执行结果、事件和错误里的引用换回密文，库里存的始终是稳定密文，下次执行重新登记新引用。范围在 `finally` 里释放（正常结束、抛错、中止都会释放）。refs CLI 不可用时退回完整密文、不带范围，并发一条事件说明。
- 凭据修复：引用在离开 gate 前换成密文交给调度器；修复出的新密文登记为同一范围的新引用返回。
- **释放引用只删除映射，不撤销原密文。** 已导出的 `enc:v1:` 仍受其原有策略约束；释放过的范围不能重开；调度器崩溃没释放的引用 2 天后失效（查询时即判定，不等下一次登记）。有效期和真正的撤销机制仍需单独设计，不能由删除引用推导出密文已失效。

**限制。**

- gate 进程里新登记的引用（修复结果、§5.2 封装值）不在 daemon 的映射表里，出现在执行结果里时以引用形式留下，范围释放后失效。封装值本就应随执行结束失效；修复出的密文另有 `credential_repair` 事件和后续交接说明携带。
- 同一 macOS 用户下，其他进程能看到 gate MCP 进程的环境变量和 shell 的代理地址（含范围）。范围防的是误用、跨任务串值和旧引用，不防同用户的主动窥探；后者要靠 gate 以独立用户运行（§3）。

## 2. 字段的当前状态与填写历史

**目的。** 让执行者在不查看原值的情况下判断是否需要填写，减少重复操作。

**实现。** 浏览器 gate 新增 `secret_field_state(target)`，`secret_fill` 的结果末尾也附同样的信息：

- 当前状态 `current`：`empty`、`nonempty`、`unknown`。gate 通过 Playwright 的 `inputValue` 在其隔离环境中读取，只返回判定，值不离开 Playwright 进程；目标不唯一、不是输入框或读取失败时为 `unknown`。每次调用都重新读，页面清空、替换节点或导航后反映的是当前页面。
- 操作历史 `attempted`、`filled`：按页面 URL 和目标记录，调用浏览器前记 `attempted`，浏览器调用无错返回后记 `filled`。历史不代替当前状态，也不证明目标系统已经保存或接受。

## 3. 受控部署与配置

**实现。**

- `secret-gate service install|uninstall|status|reload [--port N] [--dry-run]`：LaunchAgent `com.agentswitch.secret-gate.proxy`，运行本安装的 `secret-gate proxy`（只监听 127.0.0.1）；环境只有 `SECRET_GATE_HOME` 和最小 PATH，不含任何代理变量；umask 077，日志在 `<gate home>/logs/`（目录 0700、文件 0600）。缺密钥对时拒绝安装；端口被别的进程占用时只警告，不去停它。`status` 同时看 launchctl 状态和端口连通性，不健康时非零退出；`reload` 发 SIGHUP。
- `secret-gate bootstrap <claude-code|codex|opencode> [--write PATH]`：检查密钥对、`ca.pem`（有效、未过期、与代理实际使用的 mitmproxy CA 一致）、端口可达，以及监听者确实是 gate（发一个解不开的密文，必须得到 `403 X-Secret-Gate: denied`）；按本机路径输出该 harness 的配置片段，并写明作用范围（例如 Codex 的 `network_access=true` 对所有沙箱命令生效；CA 只经环境变量交给这个 harness，不改钥匙串）。`--write` 只写到明确给出的路径，全部检查通过才写，拒绝覆盖 harness 的全局配置。
- `upstream-insecure.txt` 在 SIGHUP 时重载，不断开现有连接，只加载管理员列出的条目。文件不可读、不是 UTF-8、超过 64 KiB、组或他人可写、或有非法行时保留旧名单并报错；文件被删除视为没有例外（更严格的方向）。任务失败不会自动添加站点或关闭全局证书校验。未验证证书的警告改写到 stderr（mitmdump 以 `-q` 运行时会丢掉日志）。
- 代理本身：策略 host 取代理实际连接的地址（CONNECT 目标或绝对 URL），不取客户端可随意填写的 Host 头；带值的请求若 Host 头与目的地不一致直接拒绝（防域前置），`secret_http` 同样要求 Host 头就是 URL 的 host。检查过程出任何意外错误都拒绝请求且请求保持原样，响应脱敏出错则扣下整个响应。上游证书例外名单在启动时也按重载的严格规则加载，文件不可信就不加载任何例外。
- daemon：`serve()` 启动时发现代理不通会打印错误；每次执行前做 TCP 探测，不通就不启动 harness，以失败类型 `gate_unavailable` 停止任务。三个 harness 共用同一个代理，重试或换目标都没用；这种失败不记作模型失败，也不标成安全事件。

**未做。** 本机还没有安装服务（当前代理仍是手动启动，需要用户执行 `secret-gate service install`）；gate 以独立 macOS 用户运行仍是手动步骤。→ 2026-09-27 起按 `gate-service-v0.md` 做成系统服务（独立服务账户、LaunchDaemon、本机 socket），取代这里的 LaunchAgent。

## 5. 授权页面的截图脱敏与字段传递

**现状。** 代理使用当前请求解析出的值，对响应头和可处理的文本正文做精确替换，输出 `[REDACTED:label]`，不是重新加密；大于 4 MiB 的响应正文跳过。浏览器 gate 按本会话填入或封装的值脱敏文字输出（含报错），截图按 §5.1 遮罩。浏览器填写按目标元素所在的 frame 及其全部上层 frame 校验：主 frame 的 ref 用页面 URL，frame 里的 ref 和选择器由 Playwright 报出 frame 链，每一层都须被密文允许。这些都不等同于完整的页面个人信息识别或像素级脱敏。

### 5.1 截图脱敏

**目标。** 在授权访问的页面上减少敏感字段进入模型截图，同时保持页面原有表单和值的正常工作。

**实现。**

- 截图前 gate 先取一份自己的未脱敏快照，遮罩候选包括：显示本会话填入值或封装值（任一编码）的元素；显示个人信息模式（邮箱、手机/电话、身份证号、银行卡，默认全开，可在 `<gate home>/screenshot-mask.json` 调整）的元素；本页填过的字段；所有密码框；管理员按 host 配置的区域。页面持有过受保护值时，整块遮住所有 canvas。没有 ref 的文本行，遮它最近的带 ref 的祖先元素。模式识别只用于决定遮什么，不赋予读取或传递权限。
- gate 通过 `browser_run_code_unsafe` 调 Playwright 原生 `mask` 截图。这个工具不对模型开放，代码来自固定模板，只嵌入 gate 自己校验过的 JSON 字面量。不改 DOM 文本或 input value，不向页面注入脚本，不改站点 CSP；输入框切换为明文显示时照样遮挡。字段标签若与值在同一元素里会一起被遮。
- 覆盖检查不依赖页面自报：gate 自己解码 PNG，要求每个遮罩框的内部像素全是遮罩色。以下情况拒绝截图：敏感文本找不到可遮挡的元素、遮罩框没盖住、截图失败、图像无法核对、没有私有输出目录。页面上没有任何需要保护的内容时，截图照旧直接转发。
- 截图文件写在 gate 的私有输出目录，调用结束即清理。
- 密码框、canvas 和管理员区域按 CSS 选择器遮，每个 frame 里都遮。
- 缺口：快照与截图之间新出现的内容；遮罩计划来自无障碍快照，`aria-hidden` 元素和 CSS `content:` 生成的文字不在其中；快照里没有的跨域 iframe 内容、关闭的 Shadow DOM、图片；与受保护值无关页面上的 canvas。不做 OCR。

早期“代理注入脚本、修改 CSP、让页面自报遮罩状态”的提议没有采用。

### 5.2 授权字段的受控传递

**适用场景。** 用户明确授权将来源系统中指定记录的必要字段填写到指定目标表单，例如将用户有权处理的联系信息同步到其管理的业务系统。来源访问权限与目标写入权限均需成立；页面可见、持有密文或具备目标账号不能替代完整授权。

**实现流程。**

1. 路由器只在用户原任务明确要求把指定字段从一个具名系统搬到另一个具名系统时，在决策里给出 `transfer`：来源和目的地各 1–8 个精确 host 或 host:port，字段取 `email`、`phone`、`id_number`、`bank_card` 的子集，用途 1–200 字。不从页面内容、摘要、记忆或执行者报告推断，不用于凭据（凭据已经是密文）。拿不准时留空并用 `clarify` 追问。无效授权整条丢弃并留审计事件，从不修补或放宽。授权里的每个 host 还必须出现在用户自己的话里（任务链中的用户消息、CONTEXT.md、用户的答复），所以用户只写了 host 而路由器自行补了端口时，这份授权会被丢弃。
2. 授权固定在首次路由决策上。分步执行时，循环或规划模型会读到执行者的回复（可能带着页面内容），它们给出的步骤决策只能是固定授权的子集（字段、来源、目的地都包含在内，用途相同或不写），超出就整条丢弃并记录；步骤决策不写 `transfer`，这一步就没有授权。daemon 派发时再校验一次，审计事件按实际情况逐级记录：`pinned`、`dropped`、`offered`，执行器按真实接线发 `applied` 或写明原因的 `inactive`（没有 gate、短引用回退导致没有范围、没挂浏览器）。只在挂了浏览器且本次执行有范围时，把授权作为 `SECRET_GATE_TRANSFER` 交给浏览器 gate，不进其他进程，也不交给下游 Playwright。执行者提示词里加一行，说明字段、来源、目的地和用途。
3. 浏览器 gate 在来源页的工具输出里（报错文本也算）识别授权类型的值，当场用当前公钥加密成只允许目的地 host、用途为 `fill` 的密文，登记为本执行范围的引用（label 如 `page/email-1`）。`fill` 只有浏览器填写接受，代理和 `secret_http` 一律拒绝，所以封装值绕不开下面的表单去向检查。模型只看到引用和一段说明，原页面 DOM 和 value 不变。非来源页、非授权类型的值原样输出。已封装的值在任何页面上都显示为引用（换了格式也算：电话加了分隔符或国家码、邮箱改了大小写），并享有与填入值相同的保护：文字脱敏、子串预言机、复制组合键、截图遮罩。gate 没有范围或解析不了授权时不启用授权。
4. 目的地填写：密文自带的 host:port 策略限定页面和整条 frame 链；此外 gate 核对字段所在表单的提交地址，以及它每个提交按钮的 `formaction`（包括用 `form="id"` 挂在表单外的按钮），有一个不在授权目的地内或不是 HTTP(S) 就拒绝，什么都不输入。没有表单（由脚本提交）时只靠 host 策略。
5. 填写、提交和确认保存分开执行：`filled` 不代表业务已完成。
6. 审计：gate 的 `logs/browser-audit.jsonl`（0600）记录封装、填写、截图和拒绝及原因，只含 host、label、引用、计数和执行范围的短哈希；daemon 记录 `transfer_grant` 事件和工具调用事件。执行结束时范围释放、封装的引用随之失效；续跑或更换目标需要新的执行，重新授权、重新封装，不复用已释放的范围。

**没做。** 完整的业务授权推断（授权来自路由器对用户原话的理解，没有单独的审批卡片）；四类模式之外的字段；导航竞态和目的地页面脚本在填入后改动表单去向；下载文件的内容（文件名脱敏不代表文件内容已受保护）。

**分期。** 原定三期（短引用和字段状态、生产浏览器截图控制、授权字段传递）已全部接入；后续按 §4 清单列出的缺口推进，每补一项同步补清单和拒绝用例。

## 7. 隔离试验（2026-09-23）

已在 `packages/secret-gate/scripts/gate_next_demo/` 实现可重复运行的本地 demo，使用明确标记的虚构数据、临时内存密钥和独立浏览器，产物写入 `WorkSpace/Scratch/`。未接入生产 daemon、现有 gate 配置或用户账户，未调用真实模型。

1. 短引用：随机引用 ID 与显示 label 分开，登记绑定任务/执行范围；验证同 label 不串值、错误任务/host/use 被拒绝、释放执行范围后不可用，以及在原密文策略仍允许的情况下重新登记续跑。释放引用只撤销映射，不宣称原 `enc:v1:` 已失效。恢复仅覆盖同一临时密钥存活期间。
2. 截图与字段状态：在受控截图调用中施加不透明 mask，比较遮罩前后像素；页面 DOM/value 不变。验证普通节点、已加载的动态内容、输入框、开放 Shadow DOM、本地同源 frame 和整块画布遮挡。字段返回当前 `empty/nonempty/unknown`，另记 `attempted/filled`。
3. 页面字段传递：受控驱动从本地来源页读取预先指定的虚构字段，在 gate 内加密并登记短引用；给模型的模拟快照只有引用，原 DOM 不改。按精确目标 host:port 校验后由驱动填入本地目标页并提交表单，验证收到的数据一致；错误目的地、用途、任务范围和已释放范围拒绝。页面本身不连接本地 gate 端口。

**已记录的结果。** 三项 demo 共 50 项检查通过（短引用 20、截图及字段状态 19、页面字段传递 11）。样例完整密文 273 字符、随机引用 24 字符，字符数减少约 91%，不等同于模型 token 数。7 处遮罩的 86,261 个内部像素均为不透明遮罩色，公开控件像素与 DOM/value 保持不变；两个本地页面之间的虚构邮箱和电话完成真实表单 POST，接收值一致。报告附截图与模拟模型快照，复现命令及范围见 `packages/secret-gate/scripts/gate_next_demo/README.md`。

这些结果仅证明本次受控样例中的行为，不代表通用个人信息识别、生产级截图保密保证、完整授权或撤销机制，也不能用于推断模型供应商的安全判定。正式接入前仍需完成相应实现与验证。

## 8. 生产接入验证（2026-09-24）

全部使用虚构数据、临时密钥和本机页面，不调用真实模型，不碰用户的 `~/.secret-gate`、LaunchAgents 或钥匙串。

- secret-gate：`pytest` 450 项通过（审查修复后 470 项），覆盖率 96.6%；另有 2 项真 Chromium 测试（`SG_BROWSER_E2E=1`，Playwright MCP 0.0.82）通过：登录页的客户端校验、字段状态、逐像素核对的遮罩截图（填入后和“Welcome <邮箱>”页面各一次）；两个本地站点之间的授权传递，虚构邮箱和手机号在来源页只以引用出现，经 `secret_fill` 填入目的地并真实 POST，目的地收到原值，模型输出和审计日志里都没有原值。
- 真 mitmproxy 冒烟（`scripts/smoke_e2e.py`）：带范围的引用经明文 HTTP 和 HTTPS CONNECT 都能解析，站点收不到 `Proxy-Authorization`；不带范围、释放之后均为 403。
- daemon：`tsc` 无报错，vitest 772 项通过（原 717 项，审查修复后 782 项，§6 技术维护完成后 870 项）；另有一项在有 venv 时运行真实 `secret-gate refs` CLI 的集成测试。

**安全审查（2026-09-24）。** 接入后做了一轮针对明文外泄的审查，确认并修复：
- 代理用可伪造的 Host 头做策略判断，`Host: 允许的站点` 加连到别处就能把明文送走（接入前就存在，引用和封装值扩大了影响）；改为按实际连接地址判定，带值请求的 Host 头不一致即拒绝，`secret_http` 同样处理。
- 代理遇到非预期异常（如注册表被锁或损坏）时放行已部分改写的请求，且响应不脱敏；改为一律拒绝、请求保持原样，响应脱敏出错时扣下响应。
- 浏览器填写只看顶层页面 host，值可以被填进允许页面里的第三方 iframe；改为校验目标所在 frame 链的每一层。
- 分步执行时循环或规划模型可以签发或放宽传递授权；改为固定首次路由的授权、后续只能缩小，并要求 host 出现在用户自己的话里。
- Claude 执行器经 Agent SDK 把执行范围、修复通道密钥和授权放进了子进程 argv；改为 0600 配置文件，只传路径，并用真实 SDK 和假 CLI 抓 argv 做回归测试。
- 另修：封装值改用只能浏览器填写的 `fill` 用途；换格式显示的封装值、来源页报错文本、拒绝原因和审计里的原因都做封装或脱敏；子串预言机覆盖拖拽目标、表单各字段目标、大小写和文本类选择器；表单去向检查覆盖所有提交按钮；补上浏览器表单编码和 encodeURIComponent 两种脱敏形式；CSS 选择器遮罩覆盖所有 frame；引用在查询时即判断过期；上游证书例外名单启动时也按严格规则加载；审批、提问和事件里的引用与范围换回密文或遮住。

修复后：secret-gate `pytest` 470 项通过、覆盖率 96.7%，2 项真 Chromium 测试和真 mitmproxy 冒烟通过；daemon `tsc` 无报错、vitest 782 项通过。

**未验证。** 真实模型下的端到端：路由器是否只在该给时给出 `transfer`，执行者是否正确使用引用和字段状态；launchd 服务在本机的真实安装；复杂站点（导航竞态、跨域 frame、持续变化的内容）下的截图遮罩。这些结果只证明受控样例中的行为，不代表通用个人信息识别、生产级截图保密保证或完整的撤销机制，也不能用于推断模型供应商的安全判定。
