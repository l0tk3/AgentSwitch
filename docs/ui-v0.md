# ui-v0：Mac 与 iPhone 应用的界面规范

2026-09-25 用户要求：用统一的审美重做两个应用的前端，并去掉“助理在想”这类 AI 味重的描述。本文是两端共同的准绳；改界面先看这里。

## 1. 原则

1. **安静的工具，不是聊天机器人。** 内容第一，外框最少。界面不拟人：不说“我”“在想”“收到啦”，状态用名词或短动词。
2. **一个主色，状态色只表状态。** 其余都是灰阶。颜色不用来装饰。
3. **层级靠字重、字号和留白，不靠框。** 每一项最多一层容器（一张卡片）；不在卡片里再套彩色块。
4. **一眼看状态，细节点进去看。** 状态 = 小圆点 + 一个词；长文、事件流、技术细节放在详情页。
5. **技术名词说人话。** 模型用人名（Opus 5.5、Sonnet 4.6、DeepSeek Flash、GPT-6 Luna），执行器只在需要时出现（Claude Code、Codex、OpenCode），路径缩短（`~/Projects/AgentSwitch`）。

## 2. 颜色

| 用途 | 浅色 | 深色 | 说明 |
|---|---|---|---|
| 主色（按钮、选中、进行中、链接） | `#2F5BEA` | `#6D8BFF` | 两端的 AccentColor |
| 主色填充（自己的消息、发送按钮等白字底） | `#2F5BEA` | `#3F66F0` | 深色模式下比主色深，白字才清楚 |

## 3. 字与间距

- 字：iOS 正文 `.body`，次要 `.subheadline`，辅助 `.footnote`，元信息 `.caption`（`.secondary`）；数字用等宽数字。Mac 正文 `.body`，分组标题 `.headline`，说明 `.callout`/`.caption` 次要色。
- 间距刻度：4 · 8 · 12 · 16 · 24。卡片内边距 14（iOS）/ 12（Mac）；时间线条目之间 20。
- 圆角：卡片 14，气泡 18，标签用胶囊。
- 图标：SF Symbols，单色，跟随文字颜色；只有状态点带状态色。设置里的行要么都有图标，要么都没有。（2026-09-28：自己的标记改为像素图、圆角改为方角，见 §7；系统控件仍用 SF Symbols。）

## 3b. 终端窗口（2026-09-28，terminal-v0 §1）

- 终端窗口例外地是**深色**的一整块：屏幕用用户 iTerm 的配色和字体，侧栏、标题带、状态栏用同一底色提亮一点（深色屏幕提亮约 7%），之间只用细线分隔。主色、等你处理、完成、失败四个颜色与上表相同，取深色值。iPhone 的终端页同样：导航栏、按键条、回复框、加密框（和它弹出的键盘）不随手机的浅色外观变浅，底色与屏幕相同，只用点线分隔（2026-09-29，用户：浅色的工具栏和输入框跟终端太割裂）；浮在屏幕上的权限卡片仍按手机外观。
- 顶部标题带在 Mac 上是可拖动的窗口顶边，不放字也不放按钮，也不画分隔线（读作终端的上边距）。没有底部状态栏；终端下方只有一条加密发送的细栏，点开原地变成输入框。对终端的其他操作在侧栏：悬停出现 ×（关闭），双击改名，右键菜单（重命名、加密发送、关闭），配快捷键 ⌘W、⌘⇧V、⌘T、⌘1–9。
- 状态点：进行中是主色并缓慢呼吸，等你处理橙色，空闲绿色，已结束空心。
- 电脑上不放按键条和常驻输入框；这两样只在窄屏出现。
- 终端名字按 terminal-v0 §1 的规则，不带 agent 的状态符号。

## 4. 文案

- **不拟人**：不写“助理在想”“我来帮你”“好的呢”“收到啦”。等待中写“发送中”“处理中”。
- **状态词**固定：排队 · 进行中 · 等你处理 · 已完成 · 未完成 · 失败 · 已取消。（2026-09-28：短词改用英文，见 §7.2 第 7 条。）
- **占位与空状态**：输入框“输入任务或问题”；空状态一句话 + 两三个例子。
- **按钮**：动词开头，两到四个字：发送、重发、修改、处理、删除、安装。
- **说明文字**：一句话以内，放在分组下方；更长的解释不放在设置页上。
- **时间**：刚刚、3 分钟前、今天 14:20。
- **用词**：daemon 叫“服务”，secret-gate 叫“凭据网关”，路由器模型叫“调度模型”（“调度”），harness 叫“执行器”（只在 Mac 设置和模型菜单里出现），thread 叫“话题”（topic），首页上的对话和任务合称“记录”（history）。（2026-09-29 用户：第一次用的人分不清“会话”和“对话”，也不明白为什么要删两次——原来 thread 叫“会话”、另有“任务记录”和“清空对话”。）删除只针对看得见的东西：首页的一项（一问一答连同它建的任务、一条任务、一行提示）、一个话题（只在话题页）、全部记录（设置里的 `clear history`），见 threads-v0“手动删除”。界面上不出现“助理”“路由器”“执行者”“守护进程”“分诊”“口播”。
- 对话里 AgentSwitch 自己的消息（回复、通知）是**陈述句**：“已交给 Opus 5.5。”“「财务平台登录」等你回答：短信验证码是多少？”——不寒暄，不用感叹号和表情。

### 4.1 语气：书面、克制、准确（2026-09-27）

用户反馈：“没等它”“排在前面的地址先连上了”这类说法太随便。去掉 AI 味不等于写成聊天口吻；界面文字按系统设置的写法来。

- **状态用词组，不用句子**：可用 · 0.1 秒、未使用、超时、已连接（局域网）、无响应。
- **说明用中性的完整陈述句**。不用口语词：句尾的“了”改“已…”；“没 / 没有”改“未 / 无”；“能 / 不能”改“可 / 无法”；不用“就、先、别的、一下、挺、吧、呢、啦、搞、弄”；不用比喻和拟人（“睡着了”“挤掉”“不认”“拿不准”）。
- **不用“它”指代程序、线路、模型**：写出主语，或者省略。
- **原因和操作分开**：先写原因（陈述），再写操作（动词开头）。“Mac 处于睡眠状态，或 AgentSwitch 未运行。”
- **“你”只用在需要用户动手的地方**（等你处理、请在 Mac 上修改），不用“您”。
- **不改的**：用户自己说的话（示例数据里的用户消息、任务原文）；模型生成的结果原文。

| 原来 | 改为 |
|---|---|
| 没等它 | 未使用 |
| 排在前面的地址先连上了 | 已通过优先级更高的地址连接 |
| 能连上 | 可用 |
| 每个地址同时试，排在前面的能用就用它。 | 同时探测所有地址，按顺序选用第一个可用地址。 |
| 连不上时手机会一直自动重试，不用一直开着这页。 | 连接中断时会自动重试，无需停留在此页面。 |
| Mac 睡着了，或者 Mac 上的 AgentSwitch 没在运行。 | Mac 处于睡眠状态，或 AgentSwitch 未运行。 |
| iPhone 上开着别的 VPN 应用，把 Tailscale 挤掉了 | 其他 VPN 应用正在使用 VPN 通道，Tailscale 未连接（iOS 同一时间只允许一个 VPN）。 |
| Mac 不认这台 iPhone 了，需要重新配对 | 配对已失效，请重新配对。 |
| 调度模型拿不准、它选的都用不了、或它自己出错时，任务交给这个。 | 调度模型无法判断、所选模型均不可用或调度出错时，任务交由此模型执行。 |
| 手机丢了就在这里吊销，它会立即断开。 | 设备丢失时可在此吊销，吊销后立即断开连接。 |
| 可以开始了 | 引导完成 |

## 7. 视觉语言 v1：像素、字符、信号（2026-09-28，草案已定，待落地）

用户要求：整体美术风格走像素 / glitch / ASCII 美学（参考 Hermes Agent 官网、看门狗 2、小红书黑客松开场片），但“不要滥用，保持克制和实用”；之后逐项定了：短词用英文，列表用目录树，粉色作信号色，大的身份标记加层次。图标规则按 tonsky《It's hard to justify Tahoe icons》（引 1992 年 Macintosh HIG）对照过一遍。演示页在 `docs/design/`（终端窗口、整体方向、像素层次三页，浏览器直接打开）。**写任何新界面（新功能、新页面、新状态）都按本节来**：先在演示页里找到对应的样子，找不到就先补演示页再写代码。

本节取代 §2 的主色、§3 的圆角与“图标用 SF Symbols”、§4 的中文状态词；其余（不拟人、书面语、用量）照旧。落地前两套并存。

### 7.1 理解

三个参考的共同点是**把媒介本身露出来**：像素、字符、抖动、信号错误；看门狗里 glitch 是“出事了”的信号，不是背景花纹。这是一个天天盯着用的工具，所以：**要读的字一律不加工，质感只出现在标记、标签、计量条、空状态，和状态变化的那一刻。**

### 7.2 规则

1. **格子**：一切落在字符格上——等宽、方角、1px 实线（2026-10-03 起分隔线一律用实线，不再用 2px 点线，用户：分割线也别弄虚线了，改成实线吧，看着累人；颜色取最淡的一档 `--ink4`，原来点线的地方都换）、`├─ └─` 树线。像素图标每格是整点（1pt 或 2pt），外接普通屏也清楚；每个尺寸单独画一张，不缩放。圆角只留给系统控件（标签栏、弹窗、菜单栏）。
2. **读的字不加工**：正文、对话、终端输出、按钮文字不抖、不加扫描线、不加阴影。
3. **一个信号色**：粉 `#FF2E88`（浅色 `#E0106E`）只用在选中（行左侧 3px 竖条 + 序号）、品牌标记、主按钮悬停、glitch 的第二通道。状态色只表状态：青 = busy，琥珀 = waiting，绿 = ok / idle，红 = failed；从不单独表意，总配形状或文字（色弱也分得清）。
4. **一个图标一个意思**（tonsky / HIG “icons should differentiate”，同一图标不能表示两件事）：`×` 只表示关闭（可恢复）；删除记录写 `delete`（不可恢复，悬停变红）。`>_` 只表示 Codex；终端标签页用带框的终端窗口。进行中处处是同一个盲文转圈 `⠋⠙⠹…`，静态场合（小组件、实时活动）用第一帧。找不到好隐喻就只写字。
5. **图标要区分，不要铺满**：只有在跑的终端带状态标记（■ idle/waiting，□ exited，转圈 busy）；会话记录不带。有无图标的行共用同一列，文字起点对齐；菜单里每行都留图标列，或者都不留。iPhone 的系统菜单（`+`、`⋯`、长按）每一项都带 SF Symbols 图标（2026-09-30，用户：手机上这个选项应该加图标，其他 app 都有，这个 app 的选项上都没用几个图标，都加上）：系统画的菜单用系统的图标最协调；一个意思一个图标——copy `doc.on.doc`、delete 一律 `trash`、open `arrow.up.right.square`、rename `pencil`、close `xmark`、camera `camera`、photos `photo.on.rectangle`、files `folder`、paste image `doc.on.clipboard`、ciphertext `lock`、new `plus`、pin model `pin`、handoff `arrow.right.arrow.left`、read aloud `speaker.wave.2`（stop `stop.fill`）、topic `bubble.left.and.bubble.right`、revert `arrow.uturn.backward`、older `clock`；在一串同类选项里挑一个的（模型名、auto）不带图标。Mac 菜单栏面板的操作行仍只有字（像素图标的方案见 `menu-icons.html`，待定）。
6. **系统符号按系统的意思用**：`▸ ▾` 只表示展开/收起（“▸ 2 more”，不用 “… 还有 2 个”）；`…` 只表示“还需要输入”（`settings…`）；`⌘ ⇧` 只写快捷键；单选是 `< > <x>`（尖括号，2026-09-28 用户觉得 `( ) (•)` 不好看），复选才是 `[ ] [x]`——两者不能混用。
7. **短词英文，整句中文**：短词用英文，按苹果的标题式大写（2026-10-01 改，用户：很多地方的单词拼写是全小写，应该首字母大写才对；此前全小写，下文和其他文档里更早的记录仍按当时的小写写法，以本条为准）——状态、按钮（含 `[ Allow ]` 式）、菜单项、标签页与导航标题、分组标签（`// Archived Topics`）、占位短词（`Search`）、单独的时间词（`Now` `Today 13:32` `Yesterday 06:57`）、展开（`▸ 2 More`）都是每个实词首字母大写；冠词、短介词与连词（a an the and or but for of on in to at by as via vs）在中间时小写：`Paste Image` `Delete Record` `Send as Typed` `+ Add MCP Server` `New Terminal`。缩写全大写（`OK` `MCP` `URL` `ID`），专名按它自己的写法（`AgentSwitch` `Claude Code` `Codex` `OpenCode` `pi` `Opus 5.5` `DeepSeek Flash`；文字标 AGENTSWITCH 是图形，照旧）。**保持原样的是代码与数据**：键名（`esc` `tab` `⇧tab` `^C` `pgup`，同键帽上印的）、数字开头的单位与时长（`3h` `62%` `3m ago` `9/28` `±2`）、git 分支、路径与文件名、命令（`/compact`）、内部 id 与接口值。成句的用正式中文（§4.1）——说明、确认、报错、空状态、占位提示。用户内容原样。一个词只有一个意思：
   | 场合 | 用词 |
   |---|---|
   | 任务 | Queued · Busy · Waiting · Done · Incomplete · Failed · Cancelled |
   | 终端 | Busy · Waiting · Idle · Exited |
   | 服务、网关、连接 | OK · Starting · Down · Connected |
   | 操作 | Resume · Delete · Close · New · Allow · Deny · Send · Start · Install · Open |
   | 标签页、入口 | Dispatch（调度；原“托管”、`Tasks`，2026-10-02 dispatch-v0 §0）· Terminals（终端） |
8. **抖动代替淡出**：停止、已结束、未安装、未运行用 50% 抖动（棋盘格），不降透明度——看得出“信号断了”，又不像按钮失效。
9. **glitch 是事件**：在新的权限请求、失败、进程意外退出时闪一次；用户主动的选择和打开（新建面板里选 agent、打开加密发送）也各闪一次，作为“收到”的回应（2026-09-28 用户要求，演示页原本就有）。每次 ≤ 0.5 秒（RGB 错位 + 横向切片），不循环、不装饰、不用在被动刷新上；“减少动态效果”打开时不出现。像素动画用 `steps()`，不用缓动。**换页即刷新**（2026-10-02，dispatch-v0 §1；当天先做成换台，随后换台改给切换主机）：Mac 主窗口的页间切换不放 glitch，放 §7.4 的刷新——顶栏以下自上而下 13 步刷出、扫描线在前，0.26 秒；只给用户主动的换页，可被打断且必须回到原样，“减少动态效果”时不放。换台（撕裂带、雪花与频道名）只留给切换主机（演示页 `mesh.html`，搁置）。唯一的例外是**在跑的行**（2026-10-01，用户看到一行卡在 glitch 中途：抛开 bug 不谈，这个效果还是很好的，正在运行中的都改成这个效果）：终端列表里 busy 的终端行每隔 3–7 秒（随机）闪一下轻的——只有横向切片和青粉错位，没有反色，0.14 秒——让“在跑”看得出是活的；完整的一次（带反色、0.29 秒）仍只给等你和退出，两者分得开。同一个 glitch 被打断（行滚出屏幕、离开页面）时必须回到原样，不能停在某一帧（那一行原来就是这样卡成半截的）。
10. **层次只给大的身份标记**（≥ 24pt）：应用图标和中号标记 = 1 像素硬阴影 + 斜线台阶补半亮像素（次像素抗锯齿）；文字标 AGENTSWITCH = 笔画 2 格粗、信号色错位 1 个细格（半个笔画；错整整一格时粉色和字一样粗，读成一排粉字）+ 补半亮，第一次出现时从字符噪点里显形（最后一帧是 LCD 次像素条纹），之后静止；进行中的小方块带次像素拖尾（亮 → 半亮 → 暗）。状态方块、agent 小图、标签页图标、菜单栏图标保持平的；挤出（多层厚度）试过，这个尺寸下显得挤，不用。凡是 ≥ 20pt 的品牌标记（窗口顶边、导航栏、菜单头部、应用图标）一律带层次，不能有的地方有、有的地方没有。

### 7.3 基础

- **颜色**（深 / 浅）：底 `#000` / `#F3F1EA`；墨 `#E9E6DF` / `#151413`，次 `#8D8A84` / `#5F5B54`，弱 `#4D4B48` / `#A29D93`，线 `#262524` / `#D3CEC3`；信号 `#FF2E88` / `#E0106E`；busy `#2EE6FF` / `#0086A8`，waiting `#FFB000` / `#C27400`，ok `#9BE22D` / `#3F8F00`，failed `#FF4A3D` / `#D7261B`。终端屏幕本身仍用用户 iTerm 的配色（§3b）。
- **字**：界面等宽用用户终端的字体（取不到时 SF Mono），中文回落苹方；正文、对话仍用系统字体。分组标签 `// status` 等宽疏排。
- **标记**：应用标记是图标那个“一分三”的开关画在 14×11 像素格上——源点 + 三条车道，亮着的是上面那条。idle = 亮车道；busy = 小方块沿亮车道跑；waiting = 车道尽头琥珀色闪；failed = 尽头变红；off = 整体抖到一半。菜单栏用单色模板图（状态只靠形状和透明度），静止不动。agent 各一张 5×5 像素图（Claude Code 星芒、Codex `>_`、OpenCode 方括号、pi π），新建面板里图和名字并排出现，教会对应关系；列表里悬停显示名字。 **2026-10-04 起应用标记换成叠窗（§10）；“一分三”留作 Dispatch 页的图标。**
- **计量条**：字符条 `████░░░░ 62%`。
- **浮层**（权限卡、加密发送、菜单、确认框）：1px 墨色框、方角、抖动的硬阴影（右下 6px 棋盘格），不用模糊阴影。按键栏的键帽底边 3px 厚度，按下时下沉 2px、底边剩 1px。

用户：所有的像素图标有能力画的更精致一些吗，现在看上去总感觉有些简陋……能不能弄成那种像素风格但是很精致的图标（附一张有明暗、有描边的像素画应用图标）。先看了两套概念稿（单色加信号粉点缀、彩色）：你这单色太丑了，彩色还好看点。彩色换进真实界面后：**好出戏，能不能只用黑灰色强调层次感，就不上色了**。黑灰版放进真实界面看过之后：**一口气全换完，安装**。

- **画法**（演示页 `docs/design/concepts/pixel-icons.html`，样子以它为准）：每个图标是 16 × 16 以内画板上的一个小物件，1.5 点一格（格子看得出来；按屏幕倍数取整像素：2 倍屏 3 个像素，1 倍屏 1 个，iPhone 3 倍屏 4 个）。只用墨色的六档——高光、墨、中、暗、深、底（浅色背景下反过来），不用任何别的颜色，也不用信号粉。层次靠明暗：近的、凸起的亮，远的、凹下去的暗；凸起的块上边和左边一格高光、下边和右边一格暗色；窗口类的图标用墨色描边，里面是深色的屏幕或面板；右下偏一格是硬阴影（列表里的小图不带）。
- **各图标**：应用标记——一个源头分到三条线，最近的一条和它的去处最亮，往后一条比一条暗；Terminals——窗口，标题条上三个点，深色屏幕，亮的提示符与光标；Browser——浅的陆地、深的海，左上一道高光；Settings——三根滑杆，走过的一段亮；List——侧栏是浅一档的面板；Split Right / Down——新分出的那块顶上最亮；New——有厚度的加号；Encrypt & Send——凸起的锁身、暗一档的锁梁，只有 10 点地方时（地址栏的 HTTPS、加密栏）用小一号的同一把锁；四个 agent 的标记（9 × 9）——Claude Code 的星芒中心最亮、尖端渐暗，Codex 的 `>_` 上缘受光，OpenCode 的括号与 pi 的 π 是凸起的笔画。
- **带状态的应用标记**（菜单面板、iPhone 首页 / 设置 / 配对页、网页顶栏、实时活动）：就是上面那张应用标记，状态落在最近的那条线上——忙：一个青色块沿这条线跑（两格一步，七步；大标记带渐隐的拖尾和一点辉光，减弱动态效果时静止）；等你：这条线的去处变成一颗橙色的键（带亮边暗边，每 0.56 秒明暗一次）；出错：红色的键；离线：整张图隔格抽掉。除了状态的颜色，标记本身没有颜色。 **2026-10-04 起这张图换成叠窗、状态落在最前面那个窗口的标题栏上，见 §10；“一分三”这张图留给 Dispatch 页。**
- **状态方块**：颜色照旧（绿、橙、红），是一颗小键——上左 1 点亮边、下右 1 点暗边；空心方块是键的空位——上左暗、下右亮。
- **与 §7 一致**：颜色仍然只给状态和选中，选中仍是信号粉的竖线或边框；图标本身没有颜色，没选中或不可用的图标整体压暗（图标栏 70%，标签栏 55%，列表里的 agent 标记 55%–80%）。原来靠把图标染成信号粉来表示的（悬停的锁、选中的 agent 卡），改由边框和明暗表示。
- **没有换的**：菜单栏里的图标（系统规定是单色模板图）；盲文转圈、折叠箭头、树线、关闭分屏的小叉（它们是字符，不是图标）；经典外观不受影响（§8，线性图标）。
- **在哪里**（2026-10-04，全部）：
  - Mac：主窗口的图标栏、顶栏、状态栏的锁；菜单面板的应用标记；Dispatch、用量、Browser 分组里的 agent 标记；Browser 地址栏的小锁；实时活动的胶囊与卡片（标记、agent 标记、方块）。
  - iPhone：标签栏；首页、设置、配对页的应用标记；Terminals 列表、新建终端、用量、Browser 里的 agent 标记；锁屏页的大锁、回复栏与加密栏的锁、地址栏的小锁；Browser 标题旁的地球；实时活动（灵动岛的紧凑 / 最小 / 展开，锁屏卡片）。
  - 网页：终端页的顶栏按钮（List、New）、顶栏的应用标记、目录树的状态方块与 agent 标记、新建终端的选择卡、加密栏的锁（Mac 窗口里的终端页同一份）；网页控制台的应用标记、agent 标记、状态方块。
  - 应用图标（程序坞、主屏幕）：`packages/mac-app/scripts/make-icons.swift` 改画这张明暗的应用标记，黑底、硬阴影、最近一条线上一点辉光照旧。 2026-10-04 起应用图标是叠窗（§10）。
- **代码**：三份同样的图——Mac Core 的 `ShadedSprites.swift`、iPhone 的 `AgentSwitchLive/ShadedSprites.swift`（实时活动的小组件也用，所以放在没有依赖的这一层；`AgentSwitchKit` 只管哪张单色图由哪张明暗图代替）、网页的 `ui/lib/shaded.js`。三边的测试（`ShadedSpritesTests` ×2、`uiShaded.test.ts`）守着同一个校验数（按图名与各行算的 FNV-1a），改了一处，另两处的测试会失败，提醒一起改。带状态的标记：`ShadedMark`（那条线的七步、去处是哪十六格）与两端的 `ShadedMarkPaint`、网页的 `shadedMark()`。两端的 `PixelSprite` 给了 `strength` 且是像素外观时画明暗图，`cell` 定格子大小，`picture` 指定另一张图（小锁），`onDark` 指定底色深浅（常黑的面板、信号粉的条）。网页原来的单色数据（`pixel.js` 的 `mark`、`AGENT_PX`、`LOCK`、`SQUARE`）删掉了。
- **验证**：三边单元测试；Mac `-designPreview` 出主窗口、菜单、实时活动的图，`-terminalProbe` 出窗口里的终端页；iPhone 模拟器拍首页、Terminals、新建终端、Browser、设置、配对页；`LiveRenderTests` 出灵动岛与锁屏卡片；临时服务加无头 Chrome 拍终端页与控制台（深色、浅色）。
- **还没看过的**：真机锁屏与灵动岛上的样子（只有渲染测试出的图）；终端页在浅色终端主题下的图标（浅色六档由 `terminal.js` 随屏幕底色换，只有单元测试守着）。`docs/design/implemented/` 里各页画的还是旧的单色图标，图标的样子以 `concepts/pixel-icons.html` 为准。
- **教训**：概念稿里单独看的图标，和放进真实界面里看是两回事（彩色单看好看，放进黑底等宽字的界面里出戏）。以后图标类的改动直接出真实界面的截图给用户看，概念稿只作对照。

## 10. 叠窗：应用图标与应用标记（2026-10-04 已定）

用户嫌应用图标“有点大丑”，四轮候选之后（细线条的像素标记、粉色、我用 CoreGraphics 模拟的玻璃配通用图形都被否；要求“有经典版和像素版，正常版要符合 apple 的液态玻璃规范”，主题色不用粉色）选了**叠窗**：三个叠着的终端窗口，最前面那个停在提示符上等你输入。接着问“叠窗的话顶栏中还有实时活动中的图标怎么设计”，看过放进真实界面的图、指出“经典外观的小图标还没像素的多细节”并补上之后：**直接全套叠窗图标先更换上**。agent 的标记（Claude Code、Codex、OpenCode、pi）这一轮不动。

- **两件事分开**。应用自己的标记（身份加状态）换成叠窗；“一分三”那张图（一个源头分到三条线）不再是应用标记，只留作 **Dispatch 页的图标**（Mac 图标栏、iPhone 标签栏），它说的是“调度”。Terminals 页的图标是一个窗口，应用标记是三个叠着的窗口。
- **提示符 `>` 画短（2026-10-07）**。用户：像素的 terminal 的 > 这个符号普遍太长了，有点难看。原来终端那张图里的 `>` 每一步横跨两格（6 格宽、5 格高），是扁长的；Codex 的 `>_` 竖着占满整张图（明暗版 9 行里占 7 行，线条版 5 行占满）。改成：终端图里一步一格（4 格宽、5 格高），光标跟着左移一格；Codex 明暗版 5 行、线条版 3 行。三处明暗图（iPhone、Mac、网页）一起改，校验值随之更新；演示页的 `pixel.js` 与图标稿同步。应用自己的叠窗标记没有动。iPhone 简略视图的切换键在像素外观下原来写的是字符 `>_`（等宽字体的下划线很长），换成底栏同款的终端小图。
- **应用图标**有两个，各是一份 Icon Composer 的分层文件（`.icon`：`icon.json` 加 `Assets/*.svg`），由系统自己渲染：
  - **经典版** `AppIcon.icon`：液态玻璃。黑色渐变的底（浅色、深色样式下是同一个黑，和主窗口的黑面一体，§8）；三块玻璃窗口由远到近越来越实（白，不透明度 0.28 / 0.5 / 1），最前面一块上是深色的提示符 `>` 和光标（光标原先是蓝的，用户看过后：**这个黑色就行**——整个图标没有彩色）。高光、半透明、阴影都是系统画的，深色、透明、着色几种样式也由系统按同一份文件给出。
  - **像素版** `AppIconPixel.icon`：同一幅图逐格画，18 × 15 格、每格 34 px，纯黑的底，墨色六阶、不上色（§9）。三个窗口都是不带标题栏的凸起面板（上亮下暗；第一版各有标题栏，用户：**这个把顶栏去掉，然后重新优化一下里面的 >_ 的形状**），每块 12 × 9 格、比后一块靠左下三格，之间隔一格黑；最前面一块上是五行、两格宽的 `>` 和它最后一行上四格长的光标（五种画法并排比过，用户：**改成 A**）。不带玻璃效果。标题栏只留在小标记上，那里它是状态灯。
  - **谁用哪个**：包里的图标是经典版（访达、启动台、主屏幕默认）。外观设置是 `Pixel` 时，Mac 在运行期间把程序坞里的图标换成像素版（`DockIcon`，`Resources/AppIconPixel.png`）；iPhone 把像素版作为备用图标，应用回到前台或外观设置改变时对一次（`HomeIcon`；系统每次更换都会提示一次，已经是对的就不动）。
  - 生成：`packages/mac-app/scripts/make-icons.swift` 写出两份文件（Mac 的 `Resources/`、iPhone 的 `App/` 各一套）和程序坞用的那张 PNG。两个工程都把 `.icon` 当资源交给资源编译器（`ASSETCATALOG_COMPILER_APPICON_NAME`，iPhone 另有 `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES`）；Mac 的包里因此有 `Assets.car` 和给旧系统的 `AppIcon.icns`，不再手写 `.icns`。
- **应用标记**（菜单面板、iPhone 首页 / 设置 / 配对页、网页顶栏与控制台、实时活动）：三个叠着的窗口，**最前面那个窗口的标题栏就是状态灯**——只有这一处表示状态（原来是两处：跑动的块在线路上，等你时线路末端变色）。

  | 状态 | 像素外观 | 经典外观 |
  |---|---|---|
  | 空闲 | 标题栏是墨色 | 标题栏是白色（字色） |
  | 进行中 | 整条青色，一个亮块沿标题栏跑（2 × 2 格一步，五步；带层次时有渐隐拖尾和一点辉光，减弱动态效果时静止） | 整条强调色（蓝），旁边照旧是系统转圈 |
  | 等你 | 琥珀色，每 0.56 秒明暗一次 | 橙色 |
  | 出错 | 红色 | 红色 |
  | 完成（实时活动结束时） | 绿色 | 绿色 |
  | 未运行 | 整张图隔格抽掉 | 整体变淡 |

  - **像素外观**：`stack`，16 × 14 格，墨色六阶。后面两个窗口一个比一个暗，只露出标题栏和右边框，和前一个窗口之间隔着自己深色的屏幕；最前面的窗口是凸起的标题栏（上亮、右端暗）、深色屏幕、亮的提示符、暗一档的光标。状态色落在标题栏上时照旧带亮边暗边。
  - **经典外观**：14 × 11 个单位的线条画。每个窗口都有实心标题栏（后面两个越远越淡，只画没被挡住的部分，和前一个之间留一道缝）；最前面的窗口标题栏上有三个圆点（镂空），窗体里是提示符 `>` 和光标。
  - **菜单栏里应用自己的图标**：单色模板图（由系统着色），14 × 11 格、1 pt 一格，静止。第一版是三个窗口的线框，装上后用户：**这个顶栏中的图标不太理想，可以简化一下突出主体**。现在是最前面那个窗口画成一整块实心面板（12 × 9 格，就是像素版应用图标的前窗），`>_` 从里面镂空，后面只留一个窗口的上边和右边一道细线。它说的是应用整体的状态（两个服务的状况，加上有没有东西等你），不是任务在不在跑——任务在跑由旁边的实时活动胶囊表示。正常：面板实、后面那道线淡；服务正在启动或停止：后面那道线也变实；有东西等你，或服务没有响应 / 出错：面板变淡、提示符亮起来；服务未运行：隔格抽掉。这张图上没有标题栏。**经典外观下是同一幅图的平滑画法**（第一版只有像素一种，经典外观下也是像素格子；用户：**这个东西没有 classic 的版本吗？我怎么看都是像素版**）：圆角的实心面板，`>_` 是圆头的线条，后面的窗口是一条带圆角的细线；状态规则相同，只是未运行时整体变淡、不抽格。菜单栏图标跟着外观设置即时切换（`MenuBarGlyph.image(_:waiting:look:)`，各部分的显隐在 Core 的 `PixelArt.stackShows(_:in:)`）。
- **代码**：
  - 图：三份 `ShadedSprites` 各多一张 `stack`（Mac Core、iPhone 的 `AgentSwitchLive`、网页的 `ui/lib/shaded.js`），三边测试里的同一个校验值随之改变；`ShadedMark` 的 `picture` / `lane` / `isEnd` 改指这张图的标题栏。Mac Core 的 `PixelArt.stackRows`、`stackCells`、`stackShows(_:in:)` 是菜单栏那张单色图和它各状态的显隐（`MenuBarGlyph` 只管画）。`PixelArt.markRows`（“一分三”）名字未改，现在是 Dispatch 页的图标。
  - 画法：像素外观仍是 `ShadedMarkPaint`（状态色给标题栏，跑动块是白的）；经典外观 Mac 是 `ClassicMark`（叠窗）与 `ClassicLanes`（Dispatch 页），iPhone 的叠窗画在 `LiveLook.drawClassicMark`（实时活动的小组件和应用共用），网页是 `ui/lib/look.js` 的 `mark(state, size)`。
- **演示页**：`docs/design/concepts/stack-icon.html`（两个应用图标、各状态的标记放大图、放进菜单栏 / 灵动岛 / 锁屏卡片的真实渲染）。
