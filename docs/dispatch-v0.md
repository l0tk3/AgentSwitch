# dispatch-v0：调度入口——命名与 Mac 主窗口

2026-10-02 用户：console / 路由器这部分应该起一个正式的名字，和终端分开 → 定名 **Dispatch**。又指出桌面端没有 dispatch 的正式入口：程序坞图标只打开终端窗口，dispatch 只能从菜单栏 `Open Console` 跳到浏览器。三个方案（一个主窗口两页切换、内容用网页 / 两个独立窗口 / 原生重写）里用户选了**原生重写**：一个主窗口两页切换，Dispatch 页用 SwiftUI 画。随后定了内容（用户：入口应该保持简洁，和手机一样，一个输入框和对话记录，其他都放在高级设置里）：Dispatch 页就是手机首页，网页控制台那种三栏不搬进主窗口。本文是草案；界面以演示页 `docs/design/implemented/mac-window.html` 为准，每一步先截图给用户看。

## 0. 命名

- 两个入口并列，互不代替：
  - **Dispatch（调度）**：说一句要求，调度模型选执行器和模型、派活、盯着、验收，按审批方式替你过审批（router-v0、loop-v0、assistant-v0）。
  - **Terminals（终端）**：你自己选 agent 和目录开终端，自己盯、自己回、自己批（terminal-v0）。
- 短词写 `Dispatch`，成句写“调度”（ui-v0 §7.2.7）。取代此前的“托管”和标签页 `Tasks`。
- 三个词分开用：**Dispatch** 是入口（一种用法）；**Tasks** 是它产生的东西（任务）；**Console** 只指网页控制台这个地方（浏览器里打开的页面）。路由器、调度模型是内部实现，界面上不写 router。
- 本次改名的范围：
  - iPhone 底部标签页 `Tasks` → `Dispatch`，图标不变（应用标记）；设置里“环境说明、密文”一组的标题 `Tasks` → `Dispatch`（环境说明是给调度模型读的）。
  - 网页控制台：左栏分组 `// Console` → `// Dispatch`；浏览器标签页标题 `Dispatch — AgentSwitch`；终端页回控制台的链接 `Console` → `Dispatch`。
  - 演示页同步（`app.html`、`phone.html`、`console.html`）。
  - 不改：网页控制台导航里的 `Tasks`（列任务的那一页）、接口路径（`/tasks`）、代码里的类型名。

## 1. Mac 主窗口

现状（app-v0 §4 Dock）：终端窗口是主窗口；dispatch 只有网页。改为一个主窗口、两页。

- **一个窗口 `AgentSwitch`，两页：Dispatch、Terminals。** 窗口记住上次的页和尺寸；点程序坞图标、在访达里再次打开应用 → 主窗口回到上次那一页（服务还没起来时照旧打开设置窗口）。第一次打开是 Dispatch。
- **顶栏**沿用终端窗口那一行（32 pt，红绿灯居中，下沿点线；terminal-v0 §1 Mac）：

  ```
  Dispatch 页   ● ● ●   Dispatch  Terminals ▪                                   ⠙1 ▪1  ⚙
  任务页        ● ● ●   Dispatch  Terminals ▪      ‹  ⠙ 构建 AgentSwitch.app         ⠙1 ▪1  ⚙
  Terminals 页  ● ● ●   Dispatch  Terminals  ▯     ■ claude · AgentSwitch          +  ■■⠙
  ```

  - **页切换**：紧跟红绿灯，两个等宽短词，位置在两页都不变。当前页墨色、下面一条信号粉下划线；另一页是次色，那一页有事时词后跟状态标记——有等你的是琥珀方块（同等你的闪法），只有在跑的是转圈，都没有不写。不用系统分段控件：这一行的其余部分都是像素与等宽字。
  - **标题**（居中）：Dispatch 页空着（手机导航栏写的是 Mac 的名字，在 Mac 本机上是多余的）；任务页、话题页是 `‹` + 状态标记 + 标题，点 `‹` 返回；Terminals 页同现在（屏幕上的终端 + 状态标记）。
  - **右侧**：Dispatch 页是任务计数（`⠙1 ▪1` = 进行中 / 等你）和设置（像素齿轮，打开设置窗口的 Dispatch 组，§3）；服务、网关出问题时计数前多一行等宽短词（如红色 `■ Gateway Down`），平时不放。Terminals 页同现在：列表按钮（只有这一页有侧栏）在页切换后面，右侧 `+` 新建终端和所有终端的状态。
- **换页即刷新**（2026-10-02 同日改，按用户的意见：换台留给切换主机——网状连接的设想，已搁置，演示页 `mesh.html`；页间切换改用手机那种扫描线刷新，盖住顶栏以下整块；演示页 `mac-window.html`，`?freeze=0…12` 逐步定格）：页之间切换（点页名、⌘0、⌃⇥、⌘1–9 从 Dispatch 跳到终端、⌘N / ⌘T 跨页；以后的第三页 `Browser` 同样，browser-v0）时，顶栏和页面立即换成新页，内容区（顶栏以下整块）随即自上而下分 13 步刷出、一条亮扫描线在前，还没刷到的部分是新页的底色。20 ms 一步、共 0.26 秒，按 `steps()` 跳、不缓动，两个方向一样。和手机终端屏幕、网页终端切换终端时的刷新是同一个效果（ui-v0 §7.4），是刷新不是 glitch。
  - 规则：用户主动换页才有，被动的（实时活动打开一个任务时已在那一页）不放；“减少动态效果”时直接换；刷新中途再换页，前一次立即撤掉（扫描线和底色都不留），新页重新刷一次；切到已在屏幕上的那一页什么都不做。
  - 原生做法：内容区最上面盖一层不接收事件的视图，里面两块：新页底色的遮挡块（从刷到的位置到底部）和 2 pt 的扫描线，每步挪一次；扫描线在深色上是白色 90%，在浅色 Dispatch 上是墨色 85%。不截取页面的画面（终端画面自己画，截不到也不用截）。页数不限：容器按 `MainPage` 收下每一页，加第三页不用改效果。
  - 原来的换台（撕裂带、两帧雪花与频道名、新页带竖向滚动落定，0.32 秒）移给切换主机，只留在演示页 `mesh.html`，应用里不再有。
- **快捷键**：⌘0 Dispatch；⌘1–9 第 n 个终端（已有；在 Dispatch 页按也会切过去）；⌃⇥ 在两页之间来回；⌘N 回到 Dispatch 并聚焦输入框；⌘T 新建终端（切到 Terminals）；Esc 或 ⌘[ 从任务页返回；⌘B 终端的侧栏；⌘, 设置。（第三页之后见下方“第三页 `Browser`”。）
- **菜单栏面板**：`Open Console` 改为 `Open in Browser`（网页控制台，照旧用一次性登录链接）——**2026-10-07 这一项删掉了**（用户：open in brower删掉，把这个功能直接删掉）；网页控制台本身还在（应用内的终端页用它），只是菜单里不再有入口。同时其余几项各加一个图标（用户：剩下的几个都加上图标）：`Pair Device…` 二维码、`Restart Service` 两个箭头绕一圈、`Settings…` 与侧边栏底部的设置同一个、`Quit AgentSwitch` 电源；没有程序坞图标时的 `Open Dispatch`、`Open Terminals` 用侧边栏里那两页自己的图标。像素外观是 1 点的小像素图，Classic 是对应的系统符号。没有程序坞图标时，`Open Terminal` 换成 `Open Dispatch`、`Open Terminals` 两项；有程序坞图标时都不放（程序坞图标打开主窗口）。
- **实时活动**（assistant-v0 §4）：卡片上点任务标题 → 主窗口打开那个任务的任务页（原来是浏览器里的网页控制台）；`[ open ]` 去答的提问同样落到任务页；点终端照旧。“正在看的不打扰”也用于任务页：主窗口在前台、正开着那个任务的任务页时，它的结果不落卡片、不响，失败也不留。

- **单独的窗口**（2026-10-05，用户：现在所有窗口都是单窗口逻辑，如果我想单独让某个 session 的终端单独开窗口打开应该怎么弄？浏览器是不是也应该用多窗口打开？那这样的话 dispatch 是不是也需要多窗口打开？——听了“先用网页拼一个”的做法后：不能原生实现吗……先把这些东西全都原生做吧。演示页 `docs/design/implemented/item-window.html`）：

  - **入口**：终端列表里右键 `Open in New Window`；顶栏标题右键也有（当前这一块的终端）。
  - **一样东西只在一处**：开出去以后，主窗口里显示它的那一块空出来（只有一块时换成下一个终端，没有别的终端就是新建面板）；列表里这一行后面标 `↗`，点它（或 ⌘1–9、实时活动的卡片）是把它的窗口带到前面，不在主窗口里再开一份。右键 `Move Back Here` 把它收回主窗口。
  - **关窗口不结束它**：⌘W 或红灯只关窗口，终端照跑，留在列表里（和关主窗口一样）。在列表里 `Close` 掉这个终端，它的窗口跟着关；终端自己结束时窗口留着，最后一屏还在。
  - 尺寸有主照旧（terminal-v0 §1）：这个窗口是一块独立的屏幕；手机上打开同一个终端时这里显示 `On iPhone` 的占位，点一下拿回来。实时活动里“正在看的不提示”算上这些窗口。

## 2. Dispatch 页：手机首页的桌面版

和手机首页同一套内容、同一套规则（app-v0 §5、assistant-v0 §1.1、ui-v0 §7.4 iPhone），只按桌面放宽：

- **一栏，居中，最宽 760 pt**（读的宽度；窗口再宽两边留底色）。从上到下：
  - 进行中条：有任务在跑或等你的话题，横排，点开话题页。
  - 不属于任何卡片的待批准（`■ 2 Waiting ›`），没有时不占位。
  - 对话记录，旧的在上，新内容出现时跟到底：你说的话（方框）、助理的回答、回答下面挂着它建的任务卡片、别处建的任务单独一条。任务卡片 = 状态行（状态方块或转圈、状态词、agent 图与模型、用时）+ 标题 + 进度块 + 当前一步或结果 + 给你的文件；提问卡与审批卡内嵌在任务卡片里（墨色框 + 抖动硬阴影，等你的琥珀色标题栏）。结果只出现一次、“等你”行在提问未答时不进记录，规则同手机。
  - 输入框（底部固定）：`+` 菜单（`Files…`、`Paste Image`、`Insert Ciphertext`、`New Ciphertext`、`Pin Model ▸`）、多行文本框（占位“输入任务或问题”）、发送方块。↩ 发送、⇧↩ 换行（同终端）；把文件拖进窗口 = 附件，附件在框上方一排；指定了模型时框上方一个可移除的 `Pin → Opus 5.5 ×`。没有目录、模型、浏览器、审批那一排选项：目录与执行器由调度模型定（control-v0 §2），需要时说在话里或用 `Pin Model`。
- **空状态**：只写一句“发送任务或问题”（同手机 2026-09-29）。
- **任务页、话题页**：点任务卡片或进行中条，在同一栏打开（同手机的推入），顶栏标题变成 `‹` + 标题；Esc、⌘[、`‹` 返回，回来时记录停在原处。任务页同手机：请求 · 状态行 · 摘要 · 结果 · 文件 · 过程（工具调用一次一行，点开看输入与结果）· 动作（`[ Cancel ]` `[ Retry ]` `[ Hand to ▾ ]`、评分、删除）。
- **手机长按的菜单 → 右键菜单**，项目与图标同手机（`Copy`、`Delete` 等，ui-v0 §7.2.5）；删除先确认。
- **画法**：SwiftUI。复用 Mac 已有的组件（`StatusMark`、`CharMeter`、`DottedRule`、`SectionLabel`、`PixelViews`），新增硬阴影浮框、进度块、`[ Word ]` 式文字按钮（悬停反色，主按钮悬停变粉）。颜色用 ui-v0 §7.3 两套，跟随系统深浅。读的字用系统字体（结果、回答按 Markdown 排版），状态、时间、按钮用等宽英文。glitch、转圈、等你的闪烁同手机，在“减少动态效果”下不播放。
- **代码**（2026-10-03，用户：dispatch里加上代码块支持吧，这样看着太难受了……手机上也是；演示页 `mac-window.html` 里 `跑一下这两条` 那一问及其任务页、`app.html` 的手机）：围栏代码块（三个以上反引号或波浪号开头，可带语言）用等宽字放在一层淡淡的墨色底上（Mac `Look.code`、手机 `Theme.code`：墨色 7%，在页面、卡片和你说的话的凸起框里都看得出），方角细框；一行就是一行，过长的行左右滑动、不折行——命令折成两行会被读成两条，手机上尤其如此；框上方是语言（有的话）和 `Copy`（点后短暂显示 `Copied`）。行内代码同样淡底。你说的话只认代码（围栏与反引号），其余一字不改，`*`、`#`、`-`、`1.` 都照原样；模型写的（回答、报告、结果、原因、提问、话题摘要、过程里模型的原话）整体按 Markdown。任务卡片仍是几行的预览，代码在预览里是淡底等宽字，完整的块在任务页。围栏照 CommonMark：只有同种符号、不短于开头、后面没有别的字的一行才收尾（长围栏里可以包着短围栏，开头带语言的一行不收尾），反引号围栏的开头一行里再出现反引号就是行内代码；没收尾的块到结尾为止；行内代码不跨行。逻辑在 Core 的 `DispatchCode`（手机 Kit 的 `MarkdownCode`，同一组用例），模型输出的解析器用同一套围栏规则。网页控制台里你说的话同规则（`ui/lib/markdown.js` 的 `mdTyped`，ui-v0 §7.4）。验收的提示多了一句“命令、路径和文件名写在反引号里”（`ACCEPT_SYSTEM`），卡片上的 `not accepted: …` 因而能画成代码。
- **数据与手机同一套接口**，走本机令牌（同 Mac 应用现有的 `DaemonClient`）：助理对话 `GET/POST /assistant`、删除 `DELETE /assistant/:seq`、任务 `/tasks…`（详情、事件流、回答、批准、取消、重试、交接、评分、文件、删除、已读）、`/approvals`、`/threads`、附件 `POST /uploads`、密文 `GET /gate/pubkey`（本地造密文，同手机）。列表每 6 秒轮询一次（窗口不可见时停），在跑的任务用事件流。
- **逻辑放 Core，可测**：接口与数据模型、记录的排法（对话与任务合成一条时间线、结果只出现一次、等你行的取舍）、状态词与时间短写。界面只负责画。不与 iPhone 的 Kit 共用代码（跨 package 只通过进程 / 网络接口）：照 Kit 移植，各自的测试固定行为。

## 3. 高级设置：设置窗口的 Dispatch 组

网页控制台三栏里的其余内容，和手机设置里对应的几项，放进设置窗口左栏新的一组 `Dispatch`（顶栏的齿轮直接打开这一组）：

> - Log 的 `From` 一栏写模型选择的来源（`Pinned` / `Auto` / `Default`）——服务不记任务来自哪台设备；筛选 `Dispatched` = 选定了执行器，`Answered` = 调度模型转而问你，`Refused` = 其余没有执行器的；对话里直接回答的不进这张表。
> - 清空记录：服务全有或全无，有任务正在进行或等你处理时拒绝；说明与确认框照实写（演示页原写“运行中的任务不受影响”，已改）。
> - MCP 表单比网页严（2026-10-02 审查后收紧）：名称里任何位置含 TOKEN、SECRET、PASSWORD、KEY 等词（不分大小写，`accessToken`、`PGPASSWORD` 都算；`MAX_TOKENS`、`TOKENIZER…` 除外）的环境变量或请求头，值必须恰好是一个 `enc:v1:` 密文（请求头可带 `Bearer ` / `token ` 前缀），`${VAR}` 引用放行；参数里的 `--token=…`、`--password <值>`、`NAME=…`，以及带密码或凭据名查询参数的 URL 同样检查。新建时名称与已有的服务或 skill 重名则拒绝（服务以名称为键，保存即覆盖）。服务与 skill 的删除在编辑框和右键菜单里。
> - 任务产出的文件：文档类在对应应用里打开，可执行的（`.command`、`.terminal`、`.app`、描述文件等）只在访达里显示；下载的文件带隔离标记；HTML、SVG、XML 显示源码。
